# G-130 기록

표의 줄: [간극 대장 「공개 출시」의 G-130](../../gaps.md#공개-출시)

정책의 원본은 PRD §6.6 이다. 여기는 경과와 그 절에 맞출 자리만 든다.

## 2026-11-02 — 정책을 PRD 에 세움

운영자 지시 「문서에다가 적용좀해 정책또묻고 … 코드는이런데 정책이다르다 이러지말고」로 확정 정책을 §6.6 에 적었다. 1~9 는 운영자 결정, 10~21 은 조율자 결정(운영자 위임)이다. 같은 날 운영자가 합의 방향 안의 세부 UX · 문구 · 한도 · 재시도를 맡겨, 조율자가 여덟 글자 · 동의 범위 · 다시 청하기 · 하루 10건(D4)을 고쳐 세웠다. 옛 위임의 「거두면 다시 못 연다」와 「실패 뒤 글자 거둠」은 걷혔다.

새 흐름의 여덟 글자는 ADR 0012 의 변경이다(15). 관계 해석에서 상대 글자를 유추할 위험은 남고 복원 불가를 보장하지 않는다. 직접 노출 차단은 아직 코드가 없어 구현 때 잰다. 개인정보가 아니라는 것은 운영자 의견이고 법적 결론이 아니다. ADR 은 #975 가 쓰는데 그 초안은 아직 이 변경을 안 든다.

## 켜기 전에 §6.6 에 맞출 자리 — #975 (2026-11-02, 머지 전 head `6da31f3b`, 마이그레이션 · ADR 초안을 읽어 잰 값 · 돌려 보지는 않았다)

| §6.6 | #975 초안 | 맞출 일 |
| --- | --- | --- |
| 상세 궁합 요청은 72시간(5 · 6) | 7일(`match_request_ttl`) | 상세 요청의 기한 |
| 상세 궁합에 거절 단추 없음, 그냥 두면 만료(13) | 추천 표에 「상세의 거절」, 상태 `rejected`, 거절하면 양쪽 다 다시 못 청한다 | 거절 길 · 재요청 막음 |
| 화면 · 응답에 상대 글자 없음(15) | 누름 때 `match.chart_*` 에 글자를 베낀다 | 응답에 안 나가게, 베낌이 필요한지 |
| 기술적 실패에 동의를 다시 안 받고, 양쪽 누구나 재시도 · 누른 사람 1장(16) | 양쪽 다 새로 청하고 새로 눌러야 한다 | 재시도 길 |
| 거두거나 취소 · 만료 뒤 다시 청함, 시간당 3회(18) | 거두면 방이 닫히고 그 사람을 다시 못 연다 | 재시작 길 · 횟수 |
| 정지로 닫힌 답 전 대화는 끝나고 해제 뒤 새로 시작(14) | ADR 「잠그지 않은 것」 — 풀리면 방이 다시 열리고 첫 말 제한이 이어진다 | 끝남 처리 |

답 전 상세 불가(12) · 첫 말 1건(3)은 같은 방향이다. 재지 않은 것: 끝난 대화의 목록 · 신고 길(10) · 거두기 전 알림(11) · 24시간 묶음(19) · 접기(20) · 하루 10건(21).
