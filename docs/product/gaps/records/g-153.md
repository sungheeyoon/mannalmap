# G-153 기록

표의 줄: [간극 대장 「공개 출시」의 G-153](../../gaps.md#공개-출시)

## 2026-11-08 — 운영자 결정 (a) 고지 보완, `notice-v19` 초안 (ADR 0245)

운영자가 (a) 「처리방침에 고지를 보완한다」를 골랐다(2026-11-08). 문장 넷은 운영자가 정했고(정오의데이트처럼 실제 기능을 적고 「향후 서비스 확장」
같은 포괄 표현은 쓰지 않는다), 초안 PR 이 웹 처리방침(`noticeFor`, `NOTICE_VERSION` `notice-v19`)에만 실었다. 줄마다의 근거 · 항목 표 · 근거
선택지는 `docs/legal/privacy-grounds.md` 「프로필 사진 · 소개 — `notice-v19`」.

**이 판이 하는 것과 안 하는 것.** 고지 보완은 게시 뒤의 처리를 알리는 것이다. 게시 전에 저장된 사진 · 소개의 처리는 따로 정하고, 이 줄을
닫아도 그 근거가 정해진 것은 아니다. 인연 공개(누구에게 언제 보이나)는 ADR 0222 를 여는 결정이 따로 정한다.

### 잰 것 (코드, 2026-11-08 `origin/main` `8944d4cd`)

- **선택 항목이다** — 가입(`complete_signup`) · 참여(`set_discovery_participation` · `ensure_discovery_participation`)가 사진 · 소개를 묻지 않는다.
  가입 화면의 닉네임 안내가 이미 「프로필 사진과 소개는 가입한 뒤에 추가할 수 있어요.」(`src/lib/consent/signup.ts` `SIGNUP_LABEL.nicknameNote`).
- **지금은 본인에게만 보인다** — `may_see_photo` 의 남의 갈래(후보 · 지나친 인연 · 요청 · 인연)는 모두 `match_open_to` 를 지난다
  (`discovery_pair_eligible` · 요청 줄 · `visible_matches`, `20270106120000`). 소개를 내는 읽는 문(`my_discovery_board` 등)도 같은 판정 뒤다.
- **정지된 계정은 고치지도 지우지도 못한다** — 사진의 쓰는 문은 `lock_my_photos`(`20261026090000`), 소개는 `save_my_profile`
  (`20270101090000`)이 `is_active_account()` 로 거절한다. 정지 계정의 삭제를 여는 것은 db 의 PR(ADR 0244)이다.
- **참여는 닫힌 동안에도 켜진다** — 내 사주를 저장하면 자동 참여(ADR 0222 의 5). 열 때 성인 확인(`adult_check_switch`)이 켜져 있으면
  양쪽 다 확인을 마쳐야 보이고 그 확인 화면의 「확인을 마치면 다른 회원에게 내 프로필이 보여요.」가 공개 시점의 안내다(ADR 0214 추기).
  꺼져 있으면 참여 중인 사람은 스위치를 여는 순간 보인다 — 두 스위치는 코드로 묶여 있지 않다(ADR 0222 의 8 은 차례 규칙이다).
- **`DISCOVERY_DISCLOSURE` 가 서는 자리는 처리방침 하나다** — 참여를 켜는 화면에 따로 서지 않는다(`grep DISCOVERY_DISCLOSURE app src mobile`).
  닫힌 동안 웹 · 앱 설정의 「인연」 무리(참여 끄기)가 안 선다(`matchEntriesStand`, ADR 0222 의 6) — 처리방침의 「언제든 설정에서 끌 수
  있습니다」는 그동안 화면으로는 밟을 수 없다(DB 문은 열려 있다).

### 의존 순서

1. db 의 PR(ADR 0244 — 정지 계정의 삭제를 연다)이 먼저 머지된다. 그 전에는 넷째 줄 「삭제할 수 있습니다」가 정지 계정에 사실이 아니다.
2. 운영자가 위 표에 답하고 `notice-v19` 의 PR 이 글자를 맞춘다.
3. 웹 배포로 `/privacy` 에 게시된다. 재확인 기준을 올리기로 했으면 그 마이그레이션은 웹 · 앱이 v19 를 보낸 뒤다(ADR 0237 의 좁히기).

### 기준을 안 올리는 동안의 어긋남

앱의 가입 화면은 처리방침을 웹의 현행 판으로 연다(`mobile/src/app/signup.tsx:206` `openLegalPage('/privacy')`, ADR 0172 추기 2026-11-07). 판본은
번들의 `NOTICE_VERSION` 을 보낸다(`mobile/src/auth/signup.ts:89`). 그래서 웹에 v19 가 게시된 뒤에도 깔린 옛 빌드로 가입한 사람은 **v19 의 글을
보고 기록은 `notice-v18`** 로 남는다 — 기준이 v18 이라 DB 가 받아 준다. 이 커밋 뒤의 새 빌드부터 v19 로 적힌다. 기준을 v19 로 올리면 옛 빌드의
가입은 DB 가 거절하므로 최소 빌드도 함께 올린다(ADR 0237).
