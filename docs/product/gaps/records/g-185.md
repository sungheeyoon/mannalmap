# G-185 기록

표의 줄: [간극 대장 「공개 출시」의 G-185](../../gaps.md#공개-출시)

2026-11-27 무인 라운드의 글꼴 · 면 시안(아티팩트(2026-11-27))이 잰 값과 권고다. 운영자의 말(03:40): 「ui 는 지금 너무 뭐 사실적으로
어린아이가 쓰는 거 같은데 … 폰트 이거랑 뭐 이런 식의 플로우가 낫지 않냐라는 둥 전부 추천해 줬으면 좋겠어」 · 「애플이 유명한 이유가
디테일의 변태잖아, 완성도 있는 앱을 내고 싶어」. 지금 글꼴(ADR 0109 추기 「글씨는 부산단디명조 하나」, 2026-10-28)과 면(ADR 0109,
2026-09-24)은 운영자가 정한 것이라, 시안은 그것을 다시 고를 수 있게 나란히 놓았다.

**운영자 결정(2026-11-27 낮): 「일단 글꼴 바꾸는 건 안 할게」** — 줄은 `보류` 다. 운영자가 다시 꺼낼 때까지 조율자 · 에이전트는 묻거나 권하지 않는다.
아래는 꺼낼 때 다시 재지 않도록 남긴 시안의 값이다.

## 찍은 법과 한계

앱 웹 번들(390 폭)에 가짜 서버로 데이터를 채운 실제 화면 아홉(첫 화면 · 로그인 · 홈 · 내 사주 만세력 · 풀이 결과 · 궁합 고르기 · 궁합풀이 표지 · 풀이권 · 설정)을
글꼴과 토큰 값만 갈아 끼워 여덟 방향으로 찍었다 — 글자 · 배치 · 흐름은 한 자도 안 바꿨고, 시안 코드는 되돌렸다.

- 리눅스 크로뮴이라 iOS · 안드로이드 실기기의 글꼴 렌더링(굵기 · 획)과 조금 다르다. 웹(Next)은 안 찍었다.
- 웹 번들은 앱의 어절 줄바꿈이 빠져 모든 방향(지금 포함)에 `word-break: keep-all` 을 넣었다. 고정폭 숫자는 시안 전체에 켰다.
- 기기 서체를 UI 로 쓰는 길(0바이트)은 리눅스에서 그릴 수 없어 그림이 없다. 로딩 · 빈 화면 · 실패 상태는 안 찍었다.

## 방향 여덟

- **지금** — 부산단디명조 한 벌(UI · 제목 · 비유 · 풀이 본문 · 큰 숫자), 만세력 한자는 기기 서체. 면은 크림 · 오행 파스텔 · 카드 모서리 20 · 알약 단추와 그림자. 앱 글꼴 10.4MB
- **A** — 프리텐다드 한 벌, 면 그대로. 4.7MB. 작은 글자가 가장 잘 읽히지만 풀이 글이 공지문처럼 읽히고 비유 따옴표가 굵은 막대가 된다
- **B** — 프리텐다드 UI · 본문 + 부산단디명조 B 의 제목(20px 이상) · 비유, 면 그대로. 8.4MB. 풀이 화면에서 명조 비유와 고딕 본문이 갈린다(2026-10-28 의 「완전히 다르다」와 같은 자리)
- **C** — 프리텐다드 UI · 제목 + 마루 부리 비유 · 풀이 본문, 면 그대로. 6.1MB
- **D** — C 의 글꼴 + 차분한 면(아래). 6.1MB. 가볍게 갈 때의 길 — 마루 부리는 예약 이름이 있어 네이버가 내는 woff2 를 손대지 않고 둔다
- **E** — A 의 글꼴 + 차분한 면. 4.7MB. 글꼴 하나 원칙(2026-10-28)을 지키는 길 — 「사주 앱」의 결이 가장 적다
- **F** — 프리텐다드 UI · 본문 + 함렛 제목 · 큰 숫자 · 비유, 차분한 면. 6.1MB. 권하지 않는다 — 한글이 2,788자뿐이라 지어 쓰는 비유 · 이름에서 글꼴이 섞이고, 500 · 600 굵기가 고딕처럼 보인다
- **G(권고)** — 프리텐다드 UI(단추 · 탭 · 입력 · 설명 · 표의 숫자) + Noto Serif KR 제목 · 큰 숫자 · 비유 · 풀이 본문 · 만세력 한자, 차분한 면. 구글 배포 TTF 가 굵기당 14.1MB 라(셋이면 45.4MB) 한자를 덜어낸 서브셋이 필요하다 — 서브셋 크기는 안 쟀다

## 권고 G 의 까닭

- 어린아이 같은 인상의 대부분은 작은 글자에서 온다 — 단추 · 탭 · 숫자 · 설명까지 붓맛 명조라 「사주풀이 보기」 「직접 입력」이 동화책처럼 읽힌다. UI 를 프리텐다드로 바꾸는 효과는 A ~ G 가 같다.
- 명조는 한 벌, 자리는 「읽는 것」 — 비유 카드와 본문이 같은 글꼴이라 2026-10-28 의 「비유 카드와 아래 글이 완전히 다르다」가 다시 생기지 않고, 큰 명조 제목이 위계를 만든다.
- 만세력 한자까지 본문과 같은 명조는 G 에만 있다 — 한글 11,172자 · 한자가 한 파일에 있어 비유 · 이름 · 간지 어디서도 글꼴이 안 섞인다(파일 측정).
- OFL 1.1 이고 예약 이름이 없어(배포처 OFL.txt 대조) 앱에 맞게 잘라도 이름을 지킨다.
- 치르는 값 — 무겁다(웹 조각도 굵기당 합 3.3MB 로 프리텐다드의 세 배쯤, 한 화면은 쓰는 조각만 받는다). 고정폭 숫자 기능이 없어 표의 숫자는 프리텐다드에 둔다. 두 벌(고딕 · 명조)이다.
- 2026-11-27 앱 점검(G-190)의 「원인 다섯」 가운데 붓맛 명조 한 벌과 장식으로 쓴 색을 함께 겨눈다.

## 다시 꺼내 G 를 고르면 바뀔 자리

- **결정** — ADR 0109 추기 「글씨는 부산단디명조 하나」를 바꾸는 새 ADR(글꼴 역할 표와 숫자 규칙), ADR 0109 머리에 후속 결정(일부) 줄. 추기 「본문 웹 글꼴(Pretendard)을 뺐다」(2026-09-30)도 다시 여는 일이라 그때의 까닭이 왜 더는 안 서는지 적는다. 면 값을 바꾸면 같은 ADR 에 2026-09-24 의 어느 값이 바뀌는지.
- **앱 글꼴** — `mobile/assets/fonts/` 의 부산단디 OTF 둘(10.4MB)을 프리텐다드 R · SB 와 Noto Serif KR 서브셋(한글 11,172자 + 라틴 + 간지 한자와 화면의 한자) R · SB · B 로. 자르는 범위 · 명령은 스크립트로 남긴다.
- **앱 적재** — `mobile/src/app/_layout.tsx` 의 `useFonts`, `mobile/src/ui/tokens.ts` 의 `FONT` 에 명조 자리. 명조를 부를 자리는 제목 · 큰 숫자 · 비유 · 풀이 글 · 만세력 한자(`mobile/src/chart/parts.tsx` · `mobile/src/people/parts.tsx` 의 `GLYPH_FONT`). 한 글꼴 이름에 굵기 하나라 `fontWeight` 를 함께 주지 않는다.
- **웹** — `app/busan-dandi.css` · `public/fonts/busan-dandi/` 를 프리텐다드 동적 서브셋과 Noto Serif KR 구글 조각으로(스스로 둔다 — `next.config.ts` 의 `font-src 'self' data:` 그대로), `app/globals.css` 의 `--font-app` 을 고딕 · 명조 둘로, `app/layout.tsx` 의 import, `app/ui/surfaces.ts` 머리의 글꼴 표.
- **자리 맞춤** — `src/lib/design/parts.ts` 의 `checkBoxTop`(부산단디 15/24 의 잉크 자리로 맞춘 값)을 다시 맞추고, `scripts/design-compare.mjs` 의 글꼴과 공유 그림 굽는 도구를 맞춘다.
- **면** — `src/lib/design/tokens.json` 을 고치고 `node scripts/design-tokens.mjs`, 단추 모서리는 `src/lib/design/parts.ts` 의 `BUTTON_*` 와 `app/ui/buttons.ts`. 잠금 `scripts/design-tokens.test.ts` · `scripts/fixtures/design-tokens-before.json` · `app/ui/scale.test.ts` · `scripts/mobile-type-styles.test.ts`.
- **근거** — `docs/legal/font-grounds.md` 에 프리텐다드(배포본 그대로) · Noto Serif KR(서브셋)의 원문과 확인 날짜. OFL 은 라이선스 글을 글꼴과 함께 두라는 조건이 있다.
