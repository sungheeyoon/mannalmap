## 2026-11-19 감사가 찾은 두 벌 (`1da9819e`)

화면은 그대로 두는 정리다 — 옮긴 뒤 전후 그림이 같아야 한다. 항목마다 한 벌로 옮기거나, 두 벌로 두는 까닭을 여기 적고 그 항목을 지운다. 목록이
비면 대장의 줄을 닫는다. 앱의 API 함수 · 행 옮기기는 이미 한 벌이다(ADR 0243) — 아래는 그 밖에 남은 자리다. 종 딱지 셈은 이 목록 밖이다(결함 PR 이 따로 고친다).

1. **앱 첫 화면의 출생 입력이 공용 `BirthFields` 를 안 쓴다** — `mobile/src/app/index.tsx` 135 ~ 148 · 186 · 253 ~ 339 줄이 입력 칸을 손으로 그리고,
   같은 칸을 사람 추가 · 출생 정보 수정은 `mobile/src/people/birth-fields.tsx` 의 `BirthFields` 로 그린다. 그 첫 화면 파일은 2026-10-20 ~ 11-19 의
   30일에 25번 바뀌었다 — 입력 칸 손질이 두 자리로 나뉜다.
2. **웹 `app/` 의 순수 판단을 앱이 옮겨 적었다 — 감사가 넷을 셌다.** 예: `app/me/reading/target.ts` 73 ~ 84 줄의 `readingHrefOf` 와
   `mobile/src/home/read.ts` 90 ~ 101 줄의 `runningHref` 가 같은 갈래 넷을 같은 주소로 바꾼다. 웹의 판단이 `app/` 에 있어 앱이 부르지 못한다
   (`docs/architecture.md`) — `src/lib` 로 옮기면 한 벌이다. 나머지 셋의 자리는 이 기록에 아직 없다(확인 전) — 이 항목을 집는 PR 이 다시 찾아 적는다.
4. **가입 동의 초기값이 두 벌이다** — 웹 `app/signup/form.tsx` 83 · 148 줄과 앱 `mobile/src/app/signup.tsx` 145 · 185 줄이 선택 동의의 초기값
   (`{ improvement: false }`)과 보내는 값을 따로 적는다. 동의 항목이 늘면 두 자리를 함께 고쳐야 한다.
5. **웹 · 앱에 같은 한글 글자가 248개 있다** — 화면 문구가 두 쪽 코드에 따로 적혀, 대장(`docs/product/copy-ledger/`)의 한 문구를 고칠 때 두 자리를
   고친다. 248 은 감사가 센 수이고, 어느 글자를 한 원본(`src/lib/brand` 등)으로 옮길지는 항목을 집는 PR 이 정한다.
