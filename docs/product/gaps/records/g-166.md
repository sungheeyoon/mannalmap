# G-166 기록

표의 줄: [간극 대장 「공개 출시」의 G-166](../../gaps.md#공개-출시)

Play 가격이 묶음 가격과 다를 때다.

## 정한 것 (운영자 위임 2026-11-19, ADR 0259)

Play 콘솔의 상품 가격이 `READING_BUNDLES` 와 다른 묶음은 앱 진열에서 뺀다(그 묶음만, fail-closed). 원화가 아니거나 숫자가 없어 같은지 모르는 것도 뺀다.
숫자는 기기 언어의 숫자(`\p{Nd}`)를 값으로 읽고, 0 뿐인 소수 자리(「₩4,900.00」)는 같은 값이다. 실사례 없음 — 고지와 결제를 맞추는 내부 규칙이다.

## 남은 것 — 운영자가 어긋남을 이용자보다 먼저 아는 길

지금 붙일 길은 없다. 앱에는 운영자에게 닿는 기록 길이 없고(`mobile/src` 는 `console.error` 뿐), 서버의 구매 확인(`purchases.products.get`)은 가격을 주지 않는다.
런북 `docs/ops/runbook/credits.md` 「Google Play 결제」 상품 표 밑 한 줄과 기기 확인(#770)뿐이다.

재료(조율자 검토 2026-11-19):

- 운영 알림 — `public.notify_ops`(`supabase/migrations/20270119090000_the_server_finishes_a_store_purchase_it_could_not_consume.sql` 의 `store-consume-urgent` 가 부르는 꼴)
- Play 서비스 계정으로 이미 날마다 도는 크론 — `app/api/cron/store-consume`(같은 계정 · 키로 가격 대조를 더할 자리)
- Android Publisher API — 상품 목록(`monetization.onetimeproducts`)과 주문마다 가격을 주는 `orders.get`. 결제 검증용 서비스 계정의 권한으로 읽히는지는 확인 전이다
- 서버 쪽 가드는 없다 — 장부의 주문 금액은 늘 `reading_bundle_price` 이고, 이 규칙 전 앱 빌드는 가드 없이 Play 가 준 금액으로 판다
