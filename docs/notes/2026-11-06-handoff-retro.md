# 인계가 끊긴 날 — 세션 사이에서 무엇이 빠졌나 (2026-11-06)

요구사항이 아니다. 규칙은 `docs/agents/delegation/coordinator.md` 의 「세션을 열 때」 · 「출시 흐름」 · 「인계 — 세션을 끝낼 때 남기는 것」 · 「자주 하는 실수」,
`docs/agents/delegation/done.md` 「끝났다는 것」의 「코드 · 문서 · 정책」, 결정은 ADR 0229 가 든다. 도구 고침은 #1027, 워크트리 · 가지 정리는 #1025 다.
여기는 그 규칙을 부른 그날의 사정만 적는다.

## 운영자가 한 말

- 세션 사이의 인계가 나쁘게 돌고 있다. 인계에 무엇이 들어야 하고 세션이 무엇을 되풀이하는지 문서가 말해야 한다.
- 「코드랑 문서랑 정책 따로 놀아」
- 「정책 정해졌는데 묻지 마라 문서 봐라」, 「다른 서비스 보고 알아서 해」
- 지금의 출시 흐름이 틀렸다. 코드 PR 은 운영자 검토 뒤에 머지하고, 화면은 그림 보고로 보며, 배포 뒤 정리는 저절로 돈다(ADR 0229).

## 무엇이 빠졌나

1. **Production SHA 를 문서에서 못 찾았다.** GitHub Deployments 는 2026-09 뒤로 갱신되지 않았고, `vercel inspect` 에는 SHA 가 없다.
   실제 기록은 #770 의 댓글에 묻혀 있었다. 새 세션은 운영이 v15 라고 맞게 말했지만, 그것을 증명하려고 한참 팠다.
2. **운영 상태가 이슈 댓글에만 있었다.** 2026-11-05 에 카카오 로그인이 운영에 섰고 비즈 앱 전환도 끝났다. 그런데 G-131, 카카오 절차서, PRD 는 「꺼짐」이었고
   사실은 #770 의 인계 댓글에만 있었다. 다음 세션은 낡은 문서를 읽었다(문서는 #1021 이 맞췄다).
3. **운영자 결정이 대화에만 있었다.** 운영자는 스토어 환불 규칙(「환불된 결제에서 남은 풀이권을 회수 … 반복 악용이 확인되면 검토 후 구매를 제한」)이 환불정책에
   이미 들었다고 알았다. 그 문장은 저장소 어느 파일에도 없었고 G-126 은 「결정 대기」였다. 세션이 다시 물어 운영자를 언짢게 했다.
   이 노트를 쓰는 PR 은 그 규칙을 원본에 넣지 않았다. 넣는 일은 G-126 의 몫이다.
4. **정해진 정책을 물었다.** 대상 나이와 최소 나이는 ADR 0225 가 19세 이상 조건을 인연의 조건으로 옮겨 이미 정했다. 서브에이전트가 18세 이상을 권했고,
   조율자는 ADR 을 대 보지 않고 그대로 전했다.
5. **그림 도구가 낡았다.** `scripts/ui-seed.mjs` 의 종료일이 `2026-10-31` 로 박혀 지났고, 새 회원 무료 몫(ADR 0227 뒤 1개)을 채우지 않는다.
   `scripts/ui-shots.mjs` 는 1280 · 390 만 찍는데 운영자는 1920 도 원했다. 옛 체크아웃의 `.next/types` 가 `next build` 를 깼다.
   카카오 단추는 `KAKAO_REST_API_KEY` 가 있을 때만 서서 그림에서 조용히 빠졌고, 운영자가 「카카오로그인 어딧어」로 잡았다(#1027).
6. **확인하지 않은 결함 보고.** 가짜 서버에 대고 찍은 네이티브 에뮬레이터 그림에서 앱 결함 다섯을 보고했다. 셋은 가짜 데이터에서 났거나
   (DB 에 없는 `closed_reason: 'left'`, `listed:false` 인 자기 줄) 의도된 동작이었다. 「풀이 글의 별표」는 실제 모델 출력이 아니라 꾸민 예문에서 났다. 진짜는 하나였다(#1018).
7. **참고 조사가 모자랐다.** 로그인 단추 사례를 390 폭에서만 쟀다. 데스크톱과 아이콘 정렬을 빠뜨렸고 운영자가 둘 다 잡았다(ADR 0228 이 다시 쟀다).
8. **워크트리 26개, 로컬 가지 189개가 쌓였다** — #1025.
9. **운영자 목록이 둘(#304 · #770)이었다.** 같은 날 다른 에이전트가 #770 하나로 합쳤다(#1026).

## 이 PR 이 한 것

- 위 1 ~ 7 을 「자주 하는 실수」의 줄로, 인계의 체크 일곱과 세션을 열 때 잴 넷으로 옮겼다. 맨 위 줄은 운영자의 「따로 논다」다.
- 어긋남의 예로 `docs/product/prd/screens/public.md` 의 가입 · 로그인 줄을 고쳤다. ADR 0225 가 코드를 걷었는데 「코드 · 닉네임 · 안내 확인」과
  「코드가 없는 사람의 길」이 남아 있었다.
- 역할 문서에는 가리킴만 더했다. ui 에는 「확인 전」 줄의 출처 · 날짜, 그림 도구의 두 폭, Metro `--clear` 를, ops 에는 `docs/ops/**` 의 운영 주소 금지를 더했다.

## 헤맨 것

- 「세션을 열 때」를 어디에 둘지 망설였다. `docs/start.md` 「모두가 먼저 보는 것」은 모든 역할의 입구라, Production SHA · #770 은 사람과 말하는 세션의 일로 보고
  `docs/agents/delegation/coordinator.md` 에 두었다.
- 코드 PR 을 운영자 검토 뒤에 머지하라는 지시가 위임 규약 여러 곳(`--auto` 를 주라는 브리프 칸, 무인 라운드의 표)과 부딪혔다. 결정이라 ADR 0229 로 적고
  ADR 0152 의 4 에 후속 결정(일부) 줄을 달았다.
