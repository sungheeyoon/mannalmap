# 에이전트 체계 점검 · 고침 라운드 (2026-11-19)

**요구사항도 규칙도 아니다** — 이 날 무엇을 왜 했나의 사정이다. 규칙은 이 라운드가 고친 원본(`docs/agents/delegation/` · `docs/roles/` ·
`docs/agents/code-rules/references.md` · ADR 0254 · 0255 · 0256 · 0258 · CI 의 #1178)에 있다. 지금은 그 원본을 읽는다.

## 무엇을 했나

운영자 말(2026-11-19, 줄임): 「테스트 · 린트 · 아키텍처를 점검하고, UI · 문구는 모르면 지어내지 말고 한국 비슷한 서비스를 레퍼런스로 검토해 나한테는
최종 마무리만 받고 싶은데 이게 자꾸 내가 말을 써야 한다. 깃 기록에서 어디서 자꾸 어긋나는지, 문서 정합성도 계속 내가 말해 줘야 한다. 에이전트 역할들이
유기적으로 굴러가는지 점검해라 — 워크트리로 병렬로 알아서 취합해라.」

1. **감사 일곱(읽기만)** — 시험 · CI / 코드 규칙 · 린트 / 아키텍처 / 에이전트 역할 체계 / 되풀이 지시(깃 기록 · 이 기계의 세션 기록에서 운영자가 친 말 1,082 줄) /
   UI 문구 과정 / 최근 머지의 문서 닫힘. 발견마다 「왜 지금 구조가 이걸 못 막았나」를 일곱 갈래(규칙 없음 · 제때 안 읽힘 · 글뿐 · 원본 둘 · 사설 기억에만 · 낡음 · 잡음)로 달게 했다.
   보고는 운영자에게 아티팩트 한 장으로 보였다.
2. **운영자 답** — 조율자 질문 셋에 모두 권고대로: 「다 시작」, CI 넷(바깥 검사 따로 · ADR 번호 빈틈 검사 걷기 · 린트 경고 0 + 문서 칸 검사 · 새 화면 글자 대장 대조),
   규칙 셋(승인 시안 글자 = 확정 · 역할 문서 한도 조정 · 자동 권한 설정의 저장소 이름). 그 뒤 「바이패스모드라 안물어봐도돼」(ADR 0258), 사용 한도 뒤
   「새로 띄우는 워크트리는 effort 를 낮춰서」.
3. **고침** — 붉은 main(#1174) · 잠금(#1175 ADR 0254 · #1177) · 결함(#1176) · 화면 과정(#1182 ADR 0255 · #1183) · 운영 상태(#1179 ADR 0256) ·
   에이전트 체계(#1180 · #1181 ADR 0258) · CI(#1178 · #1184) · 이 노트(라운드 끝). 남은 손질은 G-166 ~ G-169.

## 감사가 잰 것 — 숫자는 검토자가 검색식으로 센 근사

- 운영자가 친 말 1,005 줄(중복 · 사적 줄 뺌) 가운데 244 줄(24%)이 같은 교정의 되풀이였고, 기록된 27일 중 24일에 나왔다. 가장 많은 셋 —
  「한국 서비스 레퍼런스로」 43 줄 · 18일, 「정리를 시켜야 함」 43 줄 · 13일, 「문서가 코드 · 운영과 어긋남」 26 줄 · 13일.
- 되풀이한 말은 대부분 규칙이 **있었다**. 다시 나온 까닭은 다섯이었다 — 운영자가 실제로 보는 단계(시안)의 규칙이 「문구 대장 · PRD 를 읽지 않는다」였고 출처 칸이 없었다 ·
  운영 방식(herdr 흐름 · 쉬운 말 · 예상 시간)이 Claude 의 사설 기억에만 있었다 · 검사가 모양만 쟀다(대장 「확인 전」 293 줄 중 162 줄이 링크 없이 통과) ·
  노트 → 회고 → 역할 문서의 고리와 인계가 손으로만 돌았다 · 공개 출시 뒤 붉은 main 넷이 모두 바깥 탓이었다.
- **반례** — 공유 번호 겹침은 기계 검사(ADR 0238)가 생긴 뒤 운영자가 한 번도 말하지 않았다. 이 라운드의 고침이 글보다 잠금 · 틀 칸 · 스크립트 쪽인 까닭이다.

## 조율자의 판단과 까닭

- **인계 글을 가설로 읽었다.** 운영자가 붙여 넣은 앞 세션의 인계 글은 운영 SHA 를 `7398c9a3`(9월의 #228 커밋)으로 적었고(실제는 `f8450ea2`), 열린 붉은 main #1170 을
  빠뜨렸다. 「세션을 열 때」의 넷을 재다 잡았다 — 그래서 인계 칸을 찍는 `scripts/session-status.mjs` 를 들였다(#1180).
- **붉은 main 을 먼저.** 원인은 #1169 가 넣은 예외의 advisory 가 머지 1.5시간 뒤 철회된 것이었다. 감사와 나란히 `ops` 에이전트 하나로 걷었다(#1174).
- **번호를 미리 나눴다.** ADR 0254 ~ 0258 · G-166 ~ 169 · 대장 `public-20`. ADR 번호 빈틈 검사를 걷는 PR 에 가장 앞 번호(0254)를 줘 먼저 들게 했다 —
  그 PR 이 들자 다른 PR 이 번호 순에 묶이지 않았다.
- **결정 PR 은 독립 검토 뒤 머지했다.** #1175 는 첫 검토가 「ADR 이 시험보다 세게 말한다」를 짚어 고친 뒤, #1181 은 FAIL 일곱을 고친 뒤 재검토 PASS, #1177 은 PASS.
- **사용 한도로 에이전트 여섯이 한꺼번에 멈췄다.** 한도가 풀린 뒤 새로 띄우지 않고 `SendMessage` 로 멈춘 자리에서 이어 가게 했다 — 워크트리와 맥락이 남아 있었다.
- **#770 은 조율자가 한 번에 고쳤다.** 여러 에이전트가 같은 이슈 본문을 따로 고치면 서로 덮는다. 에이전트는 「고칠 글(전 · 후)」만 보고에 실었다.

## 정리

머지된 PR 의 워크트리 · 가지는 그때마다 걷었다 — 일하는 에이전트의 빈 가지는 미리보기에 「걷을 것」으로 나와도 걷지 않았다(정리 도구는 그 가지가 아직 쓰이는지 모른다).
감사가 읽은 운영자 세션 기록 뽑기(스크래치의 `operator-*.tsv`)는 라운드 끝에 지웠다. 로컬 스택 · dev 서버 · Metro 는 띄우지 않았다.
