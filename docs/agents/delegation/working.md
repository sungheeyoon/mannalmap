# 위임 규약 — 시작하기 전에 · 일하는 법

색인은 `docs/agents/delegation.md` 다.

## 시작하기 전에 — 붉은 main 이 먼저

**열린 `ci-main-red` 이슈(`gh issue list --label ci-main-red`)가 있으면 새 작업보다 먼저 고친다** — 붉은 main 위에 쌓으면 무엇이 깼는지
가를 수 없고, 나란히 선 세션이 다 같은 빨간불을 제 것으로 읽는다. 이슈가 「코드가 같다 — 바깥이거나 흔들리는 시험」이라고 적었으면 커밋을 뒤지지 말고
붉은 단계의 기록부터 보고, 바깥 탓이면 `gh run rerun <run id> --failed`, 흔들리는 시험이면 고칠 일로 남긴다.

`ci-outside-red` 는 붉은 main 이 아니다 — 코드가 그대로여도 답이 바뀌는 검사(의존성 감사 · Maven 좌표 조회)를 하루 한 번 모은 이슈라
새 작업도 묶음 배포도 막지 않는다. 할 일은 `docs/ops/runbook/security.md` 「운영 의존성 취약점」.

## 일하는 법 — 세션마다 다시 배우던 것

**재는 법**

- 「main 초록」은 `ci-main-red` 이슈가 없다는 뜻이 아니다 — main HEAD 의 `verify` run 이 completed · success 인지 본다
  (`gh run list --branch main --workflow verify --limit 1 --json headSha,status,conclusion`). 「전부 초록」은 워크플로 둘을 다 본 뒤에.
- CI · 빌드는 끝나면 돌아오는 명령(`gh pr checks <n> --watch` · `gh run watch <run id> --exit-status` · `eas build:view <id>`)을 백그라운드로 걸어 기다린다 — 알림만 기다리면 끝나도 깨지 않는다.
- 새 잠금 시험은 옛 상태를 되살려 붉어지는지 본다 — 부재로 통과하는 검사, 소스 글자를 세다 글자가 바뀌면 조용히 0 이 되는 잠금이 이 저장소에서 되풀이됐다.
- class 문자열을 상수로 옮긴 리팩터는 바뀐 줄마다 낱 모둠으로 견준다(이 저장소에는 `tailwind-merge` 가 없어 차례가 결과를 안 바꾼다). 앱 화면이 웹의 `app/*.module.css` 를 따라 그렸으면 앱 값은 그 CSS 와 견준다.
- **이 저장소는 공개다(ADR 0152).** 커밋한 글자는 지워도 기록에 남는다 — 집 주소 · 전화 · 주민번호처럼 사람을 가리키는 값은 코드에도 문서에도
  적지 않고 주소는 시군구까지만 든다. 예외는 법이 공개하라는 사업장 주소 하나로, `src/lib/brand/business.ts` 에만 둔다. 꼴은 `scripts/code-rules.test.ts` 가 잰다.
- 값을 적는 자리는 하나다 — 도구 · 씨앗 · 검사 · 문서가 화면의 값을 다시 적지 않고 진짜 자리에 묻거나 실행이 찍게 한다.
- 죽은 코드는 셋으로 가른다 — 시험에서만 쓰는 것(이 저장소는 내부를 일부러 시험하니 둔다) · `export` 만 떼면 되는 것 · 아무 데서도 안 쓰는 것.
  기능을 걷기 전에 시험이 그것을 도구로 쓰는지 본다.
- 남의 PR 의 코드는 그 워크트리에서 `git checkout` 하지 않는다 — 그 세션의 가지가 바뀐다. `git fetch origin pull/<N>/head:pr-<N>` 뒤
  `git archive -o <스크래치>/x.tar pr-<N>` · `tar -xf` 로 풀어 읽는다. 그 사본에서는 `git ls-files` 잠금이 늘 붉다 — 판정이 아니다.

**사용자와**

- 대화는 존댓말(`~요` · `~입니다`), 커밋 메시지와 코드 주석은 평서형이다.
- 새 지시가 방금 한 일과 부딪혀 보이면 둘 다 참인 구성을 먼저 찾는다 — 되돌리기는 선택지의 기본값이 아니다.
- 지시가 분명하면 그대로 하고, 충돌은 한 줄로 보고한다. 선택지를 셋씩 만들어 묻지 않는다 — 걱정되는 자리는 바꾼 화면을 찍어 보인다.
- 한글 문구는 지어내지 않는다 — 한국 서비스 실사례를 출처와 함께 넣는다(`docs/agents/code-rules/screen-copy.md` 「화면 문구」). 문구만 바뀐 라운드는
  시험을 안 돌리되, e2e 가 그 문자열을 붙들고 있으면 스펙을 같이 고친다.
- main 의 낯선 커밋은 사용자나 다른 세션이 PR 로 넣은 것이다(`docs/agents/delegation/permissions.md` 「main 은 PR 로만」) — 묻지 않고 그 위에서 잇는다.
- 프롬프트를 고쳤으면 올리기 전에 운영자가 실호출로 한 번 돌릴 수 있게 건넨다. 프롬프트에 금지 목록을 쌓지 않는다 — 결론의 모양을 시키고 본보기 한 토막을 준다.
  「후보 · 시험값 · 자료상」처럼 제품이 덜 됐다고 말하는 말투는 세기(「~일 것 같아요」)로 녹인다.

**저장소와**

- 작업 가지는 worktree 로 연다 — 같은 폴더에서는 PR 에 남의 커밋이 섞인다.
- 워크트리는 소스만 가른다 — 스택 자리를 따로 받는다(ADR 0096). 같으면 한 워크트리의 `db:reset` 이 남의 데이터를 지우고 e2e 가 남의 dev 서버를 잰다.
  에이전트 워크트리는 메인 폴더 안 `.claude/worktrees/` 에 서고, 손으로 여는 워크트리는 메인 밖에 둔다:

  ```bash
  git worktree add ../saju-<일> -b <가지> origin/main
  cp -Rc node_modules ../saju-<일>/        # 맥. WSL 은 cp -a --reflink=auto · 링크로 족한 때는 local-env.md 「로컬 환경의 함정」
  cd ../saju-<일> && npm run stack:slot -- --auto
  npm run db:start
  ```

  받은 번호는 이슈의 「공유 자원 · 병렬」 칸에 적고(`로컬 스택: 자리 3`), 끝나면 `npm run db:stop`. main 체크아웃은 자리 0 이다.
- **원격 DB 에는 기계 전체의 잠금(`scripts/remote-lock.mjs`)을 거쳐서만 닿는다** — SQL 은 `npm run db:remote -- --purpose "<목적>" "<sql>"`(목적과
  SQL 해시가 보내기 전에 접속기록에 남는다, ADR 0105), 메인 체크아웃의 push 는 `npm run db:push`, 읽기 전용 확인(`migration list` · `db push --dry-run`)과
  워크트리의 push 는 `node scripts/remote-lock.mjs <메인>/node_modules/.bin/supabase <명령> --linked`, 원격 백필은 운영자가
  `node scripts/remote-lock.mjs npx vitest run <백필 파일>` 로 감싸 돌린다(백필의 SQL 도 문장마다 `db:remote` 와 같은 길로 접속기록에 남는다). 잠금 없이 부른 `npx supabase` 는
  잠금을 지나친다. 남은 잠금은 스스로 지우지 않는다 — 지우는 법을 말하고 멈춘다.
- 커밋 전 `git diff` · 뒤 `git status` 의 `??` 를 본다 — 로컬 타입체크는 디스크를 보니 추적 안 된 모듈을 부르는 커밋이 CI 에서만 깨진다.
- 코드 주석의 근거는 지금 유효한 ADR 하나, 미결은 `G-nn` 줄이나 이슈(`#67`)다 — 날짜는 적지 않고, 예외는 밖의 문서를 확인한 날(`확인 YYYY-MM-DD`)
  하나다(`docs/agents/code-rules/comments.md` 「주석과 ADR 참조」).

## 화면은 시안 먼저

화면 일은 **시안 → 운영자 승인 → 구현** 순서다. 시안은 기능을 잇지 않고 화면만 빨리 만들어 보이는 것이고, 문구 대장과 한국 서비스 레퍼런스로 시작해
디자인 일관성을 함께 보고한다.

- 시안 단계에서 하지 않는 것: 고친 코드의 커밋, 시험, CI, PR, 공유 번호, 로컬 DB · 시드 · dev 서버.
- 글자 · 배치를 짓기 전에 찾는다.
  - 바꿀 글자 · 상태마다 대장(`docs/product/copy-ledger.md` 와 그 화면의 무리 파일)을 grep 한다 — 있으면 그 글자를 쓴다.
  - 대장에 없는 글자, 새 배치 · 흐름 · 상태는 한국 서비스 레퍼런스를 우리 폭(390 · 1280)마다 정렬까지 본다 — 차례는 `docs/agents/code-rules/references.md` 「레퍼런스」,
    찾은 사례는 `docs/context/references.md`.
  - 시안의 글자는 자리표시가 아니다 — 승인되면 그대로 확정된다.
- 운영자는 지어 그린 HTML 이 아니라 실제 화면을 본다.
  - 문구만 바꿀 때: 운영 주소를 Playwright 로 열어 DOM 글자를 바꾼 뒤 찍는다.
  - 배치를 바꿀 때: 워크트리에서 코드를 대충 고쳐 찍는다 — 앱은 웹 번들 + 가짜 서버(`docs/agents/delegation/local-env.md` 「앱을 웹 번들로 재기」), 웹은 로컬.
- 그림 규칙: 로그인한 상태의 화면 전체를 찍는다(임시 페이지에 부품만 띄우지 않는다). 앱은 `EXPO_PUBLIC_KAKAO_NATIVE_APP_KEY` 에 가짜 값을 넣어 카카오 단추를 보인다.
  큰 글씨 그림은 시킨 때만. 개발 번들의 빨간 로그 띠는 가린다.
- 390 · 1280 전후를 `index.html` 한 장과 함께 세션 임시 폴더에 두면 조율자가 아티팩트로 올린다. 그 한 장에 셋을 담는다.
  - 문구 표 「자리 | 전 | 후 | 출처」 — 출처는 대장의 절, 또는 서비스 · 링크 · 확인 날짜 · 수준(A~D). 지은 글자는 「새로」.
  - 배치 · 흐름을 바꾸면 레퍼런스 그림을 같은 폭으로 곁에 둔다.
  - 아래 「보여 드리기 전 스스로 견주기」의 다섯 줄.
- 「강조해 달라」 같은 작은 요청은 가장 작은 변화(색 · 굵기 · 한 줄)부터 보이고, 동작 · 흐름까지 바꾸는 안은 「더 할 수 있는 것」으로 나눠 묻는다.
- 막히면 우회하지 않고 막힌 것을 적고 돌아온다.
- 승인된 배치 · 흐름이 명세다. 승인된 시안의 글자를 한 자도 안 바꾸고 쓰면 확정이다(`docs/agents/delegation/decisions.md` 「결정 점검표」). 그때부터 역할 문서를
  전부 따르고, 그림으로는 시안과 맞는지만 본다.

### 보여 드리기 전 스스로 견주기

시안이든 구현이든 운영자에게 그림을 보이기 전에 다섯을 줄마다 적는다 — 시안은 `index.html`, 구현은 PR 본문에. 운영자의 화면 지적 대부분을 이 다섯이 먼저 잡는다.

1. **대장 · 같은 꼴** — 바꾼 글자 · 상태마다 대장의 절과, 같은 꼴의 기존 화면(grep 한 목록). 지은 것은 「새로」
2. **레퍼런스** — 새 글자 · 흐름 · 배치마다 한국 사례 하나 이상(서비스 · 링크 · 확인 날짜 · 수준 A~D)과 그 그림을 390 · 1280 으로. 없으면 「실사례 없음」과 가장 가까운 것
3. **일관성** — 같은 상태(0장 · 빈 화면 · 실패 · 입력 오류 · 로딩 · 확인 창 · 완료)를 다루는 다른 화면과 열린 PR 의 꼴 · 정렬 · 단추 차례. 다르면 까닭
4. **짝 · 상태** — 웹과 앱 둘 다, 처음 · 로딩 · 빈 화면 · 실패 · 대기 · 0장. 없는 상태는 「없음」
5. **규칙** — 같은 길 두 번(`docs/product/prd/screens.md` §3.2) · 저장소 말(`docs/context/copy.md` 「이 뜻으로 쓰지 않는 말」) ·
   명리 이름(`docs/agents/code-rules/screen-copy.md` 「화면 문구」) · 늘 참인 문장 · 덧붙인 설명(`docs/context/copy.md` 「8. 화면 문구 규칙」)
