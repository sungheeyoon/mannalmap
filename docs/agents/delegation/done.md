# 위임 규약 — 끝났다는 것

색인은 `docs/agents/delegation.md` 다.

## 끝났다는 것 — PR 이 드는 칸

PR 틀(`.github/pull_request_template.md`)의 칸이고 이름 · 차례가 이 표와 같다. **안 한 것은 안 했다고 적는다** — 안 돌린 것을 통과로 적지 않는다.
「문서」 칸과 「결정 여부」 줄은 `gate` 가 확인한다(`scripts/pr-body.mjs`) — 비면 실패한다. `feat` · `fix` 가 코드를 고치고 `docs/` 를 안 고쳤으면
「문서 없음 — <까닭>」을 쓴다. 본문을 고친 뒤에는 `gate` job 만 다시 돌린다. PR 을 열기 전에 `npm run pr:check -- --title "<제목>" --body-file <본문 파일>` 이
제목과 이 칸을 같은 판정으로 확인한다(커밋한 변경만 센다).

| 칸 | 무엇을 적나 | 왜 |
| --- | --- | --- |
| **무엇이 참이 되는가** | 이슈의 첫 칸 그대로. 재어 보니 달랐으면 잰 값으로 다시 쓴 문장 | 이슈 문장은 가설이다 |
| **잰 값** | 고치기 전에 잰 수와 그 방법, 후보 문장과 어디가 달랐나 | 값이 없으면 다음 사람이 다시 잰다 |
| **돌린 것** | 명령과 결과(수까지) — 무엇을 돌리나는 `docs/agents/test-map/what-to-run.md` 「무엇을 고쳤으면 무엇을 돌리나」. 프롬프트 본문이면 실호출 명령을 「사람이 할 걸음」에, 마이그레이션이면 `db:types` diff. **안 돌린 것과 그 까닭** | 단위 시험은 화면이 사라진 것을 모른다 |
| **잠금이면 일부러 어긴 것** | 린트 · 시험 · pgTAP 을 새로 세웠으면 옛 상태를 되살리거나 일부러 어긴 파일로 실패하는 것을 본 기록 — 같은 뜻의 다른 표기(별칭/상대경로, 정적/동적, `.ts`/`.jsx`)까지 | 「규칙을 넣었다」와 「규칙이 건다」는 다르다 |
| **문서** | 역할 문서의 「끝날 때 고치는 것」을 옮겨 적는다. 첫 줄은 **결정 여부** — `docs/agents/delegation/decisions.md` 「결정 점검표」의 어느 줄인지, 운영자가 답했는지(결정이면 같은 PR 에 ADR). 낱말은 `docs/context/`(색인 `GLOSSARY.md`), 모양은 `docs/product/prd/` 와 `docs/product/prd-changelog.md` 맨 끝에 `- **YYYY-MM-DD** — **무엇이 참이 됐나**(절 · ADR · 결정 출처). 한두 줄`, 틈은 `docs/product/gaps.md`, 돌리는 것은 `docs/agents/test-map.md` | 문서와 코드가 어긋나면 시험이 있는 쪽만 산다 |
| **사람이 할 걸음** | 등급 3 — `db push` · 실호출 · 문구 확인 · 운영 SQL. 앱 배포 ≠ DB 마이그레이션(`docs/ops/runbook/deploy.md` 「배포」) | 앱은 묶음 배포로, DB 는 그보다 먼저 따로 간다 |

**코드 · 문서 · 정책은 같은 차례에 맞춘다** — 모든 역할에 걸린다.

1. 정책이 정해지거나 일이 끝나면 그 차례에 원본(ADR · PRD · 간극 대장 · `docs/ops/runbook/` · 문구 대장)에 넣는다 — 이슈 댓글이나 대화에만 있으면 끝나지 않은 것이다.
2. 이미 정한 정책(ADR 의 결정 · 약관 · 고지 글 · 가격 · 환불 규칙 · 게시된 흐름)을 바꾸려면 운영자에게 먼저 묻는다. 따르는 데는 묻지 않는다.
3. 코드와 문서가 어긋나면 한쪽을 말없이 고르지 않는다 — 가르는 법은 `docs/agents/delegation/coordinator.md` 「조율자 세션」의 「사실과 의도」. 가를 수 없을 때만 걸린 화면이나 단추를 보이며 묻는다.

코드 PR 은 열고 운영자 검토를 기다린다 — 머지 · 배포 · 정리의 차례는 `docs/agents/delegation/coordinator.md` 「출시 흐름」. 일반 문서 PR 은 열자마자 `--auto` 다 — 예외 둘(검증 · 배포의 문턱 · 마이그레이션)도 같은 절.

**전후 그림은 저장소에 커밋하지 않는다** — 같은 로컬 상태에서 찍은 전후를 스크래치패드의 제 이름 하위 폴더에 두고 경로를 보고한다.
조율자가 고친 화면만 아티팩트 한 장으로 보이고, 운영자가 확인하면 아티팩트와 그림을 함께 지운다. 작은 시각 변경은 대표 화면 한두 곳의
바뀐 자리만 잘라 먼저 보이고, 같은 부품을 쓰는 나머지는 그렇다고 적는다. 운영자가 이미 「확인했어」라고 했으면 머지를 다시 묻지 않는다.
**아티팩트 주소는 저장소 문서 · 코드에 적지 않는다** — 확인 뒤 지우면 링크가 죽는다. 「아티팩트(YYYY-MM-DD)」 꼴의 글자로 적고 주소는
PR 댓글 · 대화에만 둔다. 지운 뒤에는 「아티팩트(YYYY-MM-DD 지움)」. `scripts/code-rules.test.ts` 가 확인한다.

**임시 파일(커밋 메시지 · PR 본문 · 스크립트)은 제 워크트리 안에 `.<이름>.tmp.<확장자>`(`.pr-body.tmp.md`)로 쓴다** — 스크래치패드는 한 세션의
에이전트들이 함께 써 같은 이름이면 서로 덮는다. 그 꼴은 `.gitignore` 가 거른다. `git add` 는 파일 이름으로 한다.

**커밋과 PR 제목**은 `type(scope): 한국어 문장 (ADR NNNN)` 이다(`docs/agents/code-rules/locks.md` 「커밋과 PR」). squash 본문은 PR 본문이 아니라
커밋 메시지들을 이어 붙인 것이라(저장소 설정 `COMMIT_MESSAGES`) 커밋을 하나로 두거나 머지 화면에서 다듬는다.

## 읽기량 예상치는 보고다

`npm run read-budget` 의 표(역할마다 손대기 전에 읽는 바이트의 예상치)에는 천장이 없다 — CI 를 실패시키지 않는다. 읽기량에 걸린 실패는 둘뿐이다
(`scripts/code-rules.test.ts` 「역할 문서」) — 역할 문서의 「닿을 때 여는 것」 앞까지가 한 화면(8,000 바이트)을 넘었거나, 가리킨 파일 · 「절」 · 앵커가 없다.
앞의 것은 원본에 있는 것을 옮겨 적고 있다는 뜻이고, 뒤의 것은 가리키는 쪽을 지금 자리로 고친다.

- **역할 문서의 가리킴을 바꿨으면** 그 역할의 전후 예상치를 PR 의 「잰 값」에 적는다. `npm run read-budget -- <역할>` 은 고정 파일과 센 절을 찍는다.
  백틱 경로 바로 뒤에 `「절」` 이 아닌 글이 오면 셈은 파일 전부다.
- **줄이는 것은 바이트가 아니라 쓸데없는 지시다** — 바이트를 맞추려고 문장을 줄이거나 파일을 쪼개지 않는다. 문서를 고치거나 줄일 때 이 잣대로 본다.
  1. **줄마다 묻는다** — 빼면 모델이 실수하나, 그 실수를 시험 · 훅 · 설정 · CI 가 못 잡나. 둘 다 「예」인 줄만 남긴다
  2. **원본 하나** — 규칙의 자세한 것은 한 곳에만. 역할 문서의 「지킬 것」과 `AGENTS.md` 의 멈출 선은 규칙을 한 줄로 직접 적고 출처를 단다 —
     원본을 바꾸는 PR 이 그 줄도 고친다. 색인 · 입구는 「언제」를 앞에 둔 가리킴만 든다
  3. **늘 실리는 것은 더 깎는다** — `AGENTS.md` · `docs/start.md` · 역할 문서의 칸 셋에는 모든 갈래가 쓰는 것만. 환경(`package.json` · 설정 · 스크립트 머리말)이 답하는 것은 가리킨다
  4. **규칙은 무엇과 까닭 한 마디** — 날짜 · 이슈 번호 · 경위는 git 과 `docs/notes/` 에. 금지에는 할 일을 짝짓고, 센 말은 멈출 선에만
  5. **끝 조건은 확인할 수 있게** — 무엇이 어디에 있으면 끝인지로
- **시험도 같은 잣대로 본다** — 링크 · 경계 · 비밀처럼 실수를 막는 검사는 두고, 문서의 꼴만 잠그는 검사는 고치거나 지운다. 시험이 지금 틀을
  지킨다는 것은 그 틀이 맞다는 근거가 아니다
- **「먼저 읽는 것」과 「닿을 때 여는 것」 사이로 줄을 옮기는 까닭은 일의 쓰임뿐이다** — 그 역할의 거의 모든 일이 손대기 전에 쓰고, 기계가 못 잡나. 바이트는 까닭이 아니다.
