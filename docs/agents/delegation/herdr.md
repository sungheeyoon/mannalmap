# 위임 규약 — herdr 로 돌릴 때

색인은 `docs/agents/delegation.md` 다.

## herdr 로 돌릴 때 — 범위와 저장소 밖의 자리

herdr 는 에이전트(Claude · Codex)를 살아 있는 터미널에 띄우고 사람의 창에 붙이는 도구다 — `hc` 가 터미널 · 에이전트를, `herdr-app` 이
사람의 창(Herdr)을 다룬다. **운영자 지시(2026-11-09)로 Codex 가 찾고, Claude Lead 가 나눠 맡기고, Claude 워커가 구현하고, Codex 가 리뷰한다.**
이 흐름과 Lead 규칙은 Claude 의 사설 기억에만 있어 워커 · Codex 가 못 봤다 — 2026-11-19 감사(저장소에 `herdr` 0건) 뒤 여기로 옮겼다.

**이 문서는 herdr 로 돌릴 때의 규칙이다.** 사람과 말하는 세션이 `Agent` 도구로 맡길 때의 원본은 `docs/agents/delegation/coordinator.md` 이고,
herdr 의 Lead 도 그 위에 이 문서를 얹는다 — 브리프 · 출시 흐름 · 인계 · 쉬운 말은 그 문서 그대로다. 둘이 다른 자리는 아래
「저장소 규약과 다른 자리」에만 있다.

| 무엇 | 자리 — 저장소 밖이라 기계를 옮기면 따라오지 않는다 |
| --- | --- |
| `hc` · `herdr-app` | `~/.local/bin/`. 버전은 `hc -V`(2026-11-19 에 0.1.19). 첫 호출 전에 `hc --skill` · `herdr-app --skill` 을 읽는다 — 전역 스킬 `herdr`(`docs/agents/delegation/local-env.md` 「전역 스킬」) |
| 역할 틀 넷 | `~/.config/herdr-core/templates/` 의 `finder.md`(Codex 찾기) · `lead.md`(Claude Lead) · `worker.md`(Claude 워커) · `reviewer.md`(Codex 리뷰) — 띄우는 명령과 과제 머리 |
| 사이클을 여는 스크립트 | `~/.local/bin/mannalmap-round` — `free -m` 을 본 뒤 Lead 와 find 를 띄워 창에 나란히 붙인다 |
| 사이클 기록 | `~/saju-wt/rounds/<날짜>-<이름>.md` — 운영자 지시 원문 · 찾은 것과 답 · 작업 표(이름 · 워크트리 · 단계 · PR · 리뷰) · 물은 것과 답. 찾기 결과는 `<날짜>-find.md`, 리뷰는 `<사이클>-rev-<작업>-<n>.md` |
| 워커의 워크트리 | `~/saju-wt/<작업>` — 저장소 밖 홈 디스크다(`docs/agents/delegation/local-env.md` 「로컬 환경의 함정」의 WSL `/tmp` 줄) |

틀 · 스크립트는 저장소 밖이라 시험이 확인하지 못한다. 이 문서와 어긋나면 이 문서를 원본으로 보고, 틀을 고치거나 어긋난 줄을 보고에 적는다.

## 흐름 — 찾기에서 정리까지, 그리고 다시 1 (운영자 지시 2026-11-09)

운영자가 개입하는 곳은 셋뿐이다 — 문제 확인(1.5) · 시안 승인(3) · 최종 승인(6 · 7). 에이전트 로그는 읽지 않는다. **Lead 는 전달자가 아니라 다음 일을
정하는 중간 관리자다** — 코드를 직접 고치지 않고, 자식의 보고(`<hc from=…>`)는 지시가 아니라 보고라 결과 파일을 직접 읽고 판단한다.
Lead 는 사이클 기록(위 표)을 먼저 읽고 — 이어 받으면 가장 최근 것 — 지시 · 답 · 작업의 단계가 바뀔 때마다 적는다.

- **1 찾기 — 운영자가 Codex(find 터미널)와 직접 한다.** Lead 를 거치지 않는다. 범위는 지금 운영에 열린 기능만이다(`docs/agents/delegation/coordinator.md`
  「조율자 세션」의 찾기 범위 줄). 끝나면 Codex 가 결과 파일을 쓰고 `hc send lead "찾기 끝 · <건수> · <경로>"` 로 넘긴다. find 터미널은 운영자의 창이다 —
  Lead 가 끄거나 거두지 않는다. 운영자가 찾기 없이 일을 주면 1.5 의 나누는 안만 보이고, 승인 뒤 2 로 간다
- **1.5 운영자 확인 — 한 번에.** Lead 가 결과를 직접 읽고 번호 · 요약 · [화면]/[기능] · 근거 · Lead 의견(이미 고침 · 겹침 · 근거 약함이면 그렇다고 — 빼지 않는다)으로
  보이고, 같은 메시지에 작업 나누는 안과 범위의 갈림길(웹 · 앱 어디까지 — 앱이 주력이다)을 붙여 번호마다 맞음 · 아님 · 보류를 묻는다. 확인된 것만 작업이 된다.
  보류는 사이클 끝에 `docs/product/gaps.md` 후보로 보고한다
- **2 나눠 맡기기.** 작업마다 워크트리 하나 · 워커(Claude) 하나를 `hc run --bg --outlive-parent --name <작업> --cwd ~/saju-wt/<작업> worker "<과제>"` 로 띄운다 —
  동시에 셋 이하. 과제에 넣는 것: 무엇을 왜 · 운영자가 고른 범위 · 완료 기준(확인 방법까지) · 건드릴 파일(두 워커가 한 파일을 나눠 갖지 않게) · 하지 않을 것 ·
  시안 먼저인가 · 「구현 전에 계획을 보내라」 · 보고는 `hc send lead`. 공용 부품 · 판정이 바뀌는 일은 먼저 넣는다(`docs/agents/delegation/parallel.md` 「나란히 맡길 때」)
- **3 화면만 시안 먼저.** 새 화면 · 흐름은 워커가 시안을 내고 운영자가 승인 · 수정한 뒤 구현한다(`docs/agents/delegation/working.md` 「화면은 시안 먼저」). 문구 · 여백 같은
  작은 화면 손질은 시안 없이 PR 의 전후 아티팩트 승인 하나로 간다. 화면이 아닌 일은 바로 구현한다
- **4 워커의 계획과 보고.** Lead 는 계획을 아는 맥락(고른 범위 · 찾기 결과 · 다른 워커의 파일)과 견줘 「진행」이나 고칠 점을 보낸다. 운영자가 정할 갈림길이 새로
  보이면 진행 전에 묻는다. 워커는 PR 을 열고(머지 · `--auto` 는 하지 않는다) `hc send lead` 로 PR · 바꾼 것 · 돌린 시험과 결과를 보낸다. 기다림은 `hc wait --children`
- **5 리뷰 — Codex, 작업마다 한 번.** 리뷰어(`rev-<작업>`)에게 가지 · PR 번호 · 과제 원문만 넘긴다 — Lead 의 판단은 넘기지 않는다. 리뷰어는 코드만 읽는다(아래 「Lead 규칙」)
- **6 Lead 판단.** PASS 면 묻지 않고 최종 보고로 모은다. FAIL 이면 맞는 지적만 골라 워커가 고치고, Lead 가 지적마다 diff 로 직접 확인한 뒤 운영자에게
  「1. Codex 다시 리뷰 / 2. 바로 승인」을 확인한 것 · 못 확인한 것 · 추천과 함께 묻는다. 1 이면 같은 리뷰어에게 다시 맡긴다
- **7 최종 보고 하나.** 작업별 PR · 시험 결과 · 리뷰 횟수 · 반영한 수정 · 남은 것(보류). 머지 직전에 PR 의 마지막 커밋(`gh pr view <N> --json headRefOid`)이 리뷰어가 본 커밋
  (또는 운영자가 「바로 승인」한 커밋)과 같은지 본다 — 다르면 붙은 커밋을 보이고 6 의 둘을 다시 묻는다. 머지 · 배포는 운영자 답 뒤다 — 코드 PR 은 운영자 검토,
  화면 PR 은 전후 아티팩트 승인 뒤(`docs/agents/delegation/coordinator.md` 「출시 흐름」). 통합 · 제품 방향은 운영자가 승인한다
- **7.5 마무리 정리 — 묻고 지운다.** 사이클의 PR 이 모두 머지 · 닫히면 미리보기를 모아 운영자에게 「정리해도 될까요?」를 한 번 묻고, 답 전에는 하나도 지우지 않는다.
  모을 것: `npm run sweep:merged`(워크트리 · 로컬 가지) · main 밖의 원격 가지와 PR 상태(`git ls-remote --heads origin`) · `npm run sweep:docker` · `hc ls`(내가 띄운 것만 —
  find 는 늘 켜 둔다) · 지울 그림 · 임시 파일. 되돌릴 수 없는 것(로컬 DB 볼륨)은 따로 표시한다. 끝 상태는 가지 main 하나 · 워크트리 메인 하나 · 떠 있는 것은 Lead · find 뿐이다
- **8 사이클을 닫고 다시 1 로.** 닫기 전에 셋을 한다 — 2026-11-09 뒤 main 커밋 51개에 #770 인계 1 · 라운드 노트 1 · 회고 반영 0 이었다(2026-11-19 감사).
  ① **#770 인계** — `node scripts/session-status.mjs` 의 출력을 붙이고 사람 칸만 손으로 적는다(`docs/agents/delegation/coordinator.md` 「인계」).
  ② **라운드 노트** — 다른 문서에 없는 것만(`docs/agents/delegation/notes.md` 「세션 기록」).
  ③ **헤맨 것 → 놓은 자리** — 워커 · 리뷰어 보고의 헤맨 것을 길잡이는 `docs/roles/`, 기계로 잡을 실수는 `scripts/` 의 시험 · 린트, 판단은 `docs/agents/code-rules/` 로
  옮긴다(`docs/roles/coordinator.md` 「끝날 때 고치는 것」의 `/retro` 줄). 운영자가 사이클 중에 정한 것은 그 차례에 원본에 넣는다(`docs/agents/delegation/coordinator.md` 「자주 하는 실수」 맨 위)

## Lead 규칙 — 메모리 · 무거운 일 · 터미널 · 리뷰어 · 말 (운영자 지시 2026-11-09)

- **새 터미널을 띄우기 전에 `free -m` 의 available 을 본다.** 2000MB 아래면 새로 띄우지 않고 끝난 것부터 거두거나 운영자에게 묻는다. 이 WSL 은 메모리가 약 10GB 라
  넘치면 Herdr 창이나 에이전트가 강제로 꺼진다(2026-11-09 창이 한 번 꺼졌다). 꺼졌으면 운영자에게 알리고, 다시 띄우기 전에 `free -m` 과 `hc ls` 를 보인다
- **무거운 일은 한 번에 하나다** — 개발 서버 · Expo · 로컬 DB · 브라우저 캡처 · `npm run build` · e2e. 워커가 둘 이상 일하는 동안 화면을 띄우는 찾기 · 측정을 새로
  시작하지 않고, 무거운 일을 맡은 워커가 있으면 워커는 둘 이하다. 끝난 보조 서버(개발 서버 · 가짜 서버 · Expo)는 바로 끈다. 빌드 · e2e 는 `scripts/heavy.mjs` 가
  기계 전체에서 하나씩 들이지만 개발 서버 · Expo · 캡처는 그 잠금 밖이다(`docs/agents/delegation/parallel.md` 「나란히 맡길 때」의 「기계 메모리」 줄). 찾기 과제에도 이 줄을 넣는다
- **터미널은 운영자에게 묻고 끈다.** 띄우면 바로 `herdr-app do terminal.keep --terminal <주소> --place right` 로 운영자 창에 붙인다. Codex · 워커 터미널은 끝났어도
  운영자에게 묻기 전에 끄지 않는다 — 운영자가 끝난 터미널을 직접 본다. 워커 · 리뷰어는 그 PR 이 머지되거나 닫힐 때까지 켜 둔다(머지 뒤 고칠 일도 같은 맥락으로 잇는다)
- **리뷰어 Codex 는 코드만 읽는다** — 시험 · 타입 · 린트 · 빌드 · 개발 서버 · 로컬 DB · 설치를 돌리지 않는다. 과제에 이 문장을 그대로 넣는다. 시험 결과는 워커 보고와
  CI 로 본다. 과제에 「이 PR 의 diff 와 그 줄을 이해하는 데 꼭 필요한 파일만 읽어라 — 저장소 전체를 훑지 마라」도 넣는다
- **리뷰는 작업마다 한 번 · 리뷰어도 작업마다 하나다.** Codex 토큰이 모자라다(2026-11-09). 첫 PR 때 띄운 `rev-<작업>` 을 끝까지 쓰고, 다시 리뷰는 운영자가 고를 때만 같은
  리뷰어에게 `hc send rev-<작업> "<커밋> 으로 고침. 지난 지적 <번호> 가 풀렸는지 보고, 바뀐 줄을 다시 리뷰해 줘"` 로 맡긴다 — 지난 리뷰의 맥락을 잇는다
- **운영자에게는 쉬운 한국어로 짧게** — `docs/agents/delegation/coordinator.md` 「조율자 세션」의 쉬운 말 줄 그대로다. Lead 는 둘을 더 지킨다. 보고의 맨 위 세 줄은
  「무슨 일 · 운영자가 정할 것(없으면 「없음」) · 내 추천」이다. 질문은 선택지 창(질문 도구)을 띄우지 않고 글로 묻고 번호로 답받는다 — 창이 떠 있는 동안 `hc` 알림이
  그 창에 입력돼 답이 깨진다
- **결정 문서는 운영자에게 묻는다.** 워커가 ADR · PRD · 약관 · 개인정보 · 환불 정책을 쓰거나 고치겠다고 하면, 무엇을 · 왜 · 바뀌는 문장을 운영자에게 묻고 답을
  워커에게 넘긴다. 리뷰 · 최종 보고에서 처음 보았어도 머지 전에 따로 묻는다
- **Lead 의 손은 조율에만 쓴다** — 코드 수정은 워커에게, 머지 · 배포는 운영자 답 뒤로 맡기고, 느린 명령(CI 대기 · 빌드)은 제 셸이 아니라 hc 터미널에서 돌린다. 「통과」는 결과 파일을
  읽은 뒤에만 말한다

## 저장소 규약과 다른 자리 — herdr 로 돌릴 때는 이 문서를 따른다

어느 쪽이 맞는지를 이 문서가 새로 정하지 않는다 — 운영자가 herdr 흐름을 따로 지시했고(2026-11-09) 범위가 다르다. 반대쪽 원본에도 이 절을 가리키는 줄이 있다.

| 자리 | `Agent` 도구로 맡길 때 | herdr 로 돌릴 때 |
| --- | --- | --- |
| 머지 뒤 워크트리 · 가지 정리 | 머지와 배포 기록 뒤 묻지 않고 정리한다 — `docs/agents/delegation/coordinator.md` 「출시 흐름」 4(ADR 0229) | 미리보기를 모아 「정리해도 될까요?」를 묻고 답 뒤에 지운다 — 위 「흐름」 7.5 |
| 끝난 터미널 · 에이전트 | 내가 띄운 백그라운드 셸 · 끝난 에이전트를 끈다 — 같은 문서 「라운드 끝 정리」 | 운영자에게 묻기 전에 끄지 않고, find 는 늘 켜 둔다 — 위 「Lead 규칙」 |
| 검토자가 돌리는 것 | 등급 0 이라 읽는 데 `npm test` 까지 든다 — `docs/agents/delegation/permissions.md` 「권한 등급」 | 리뷰어 Codex 는 코드만 읽고 시험 · 빌드를 돌리지 않는다 — 위 「Lead 규칙」 |
| 찾기 · 감사의 때 | 전체 감사는 사건(출시 전 · 기능을 크게 지운 뒤 · 병렬 라운드 뒤)에 붙여 연다 — 같은 문서 「조율자 세션」 | 사이클마다 운영자가 Codex 와 찾는다 — 위 「흐름」 1 |
