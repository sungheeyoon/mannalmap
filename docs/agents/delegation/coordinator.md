# 위임 규약 — 조율자 세션

색인은 `docs/agents/delegation.md` 다.

## 세션을 열 때 — 지금을 먼저 잰다

사람과 말하는 세션은 보고하거나 묻기 전에 `node scripts/session-status.mjs` 로 지금을 확인한다 — main · CI 실패 · Production SHA · 열린 PR ·
워크트리 · 정리 미리보기를 한 장으로 찍고 `git fetch` 밖에는 쓰지 않는다. 인계 글 · 메모 · 기억은 그 전까지 가설이다.

1. **메인 체크아웃은 뒤처질 수 있다** — 감사 · 보고는 `origin/main` 으로 읽는다. `main` 이고 로컬 변경이 없고 fast-forward 가 될 때만
   `git pull --ff-only` 하고, 아니면 그 상태를 보고한다.
2. **main 의 CI 실패가 먼저다** — 열린 `ci-main-red` 이슈가 있으면 새 일보다 그것을 고친다(`docs/agents/delegation/working.md` 「시작하기 전에」).
3. **#770 이 운영자 목록 하나다** — 인계 댓글의 운영 상태가 원본(`docs/product/gaps.md` · 운영 절차 · PRD)과 다르면 보고 전에 원본을 맞추는 문서 PR 을 연다.

## 조율자 세션 — 사람 하나 · 백그라운드 에이전트 여럿

사람과 말하는 세션(조율자)이 운영자와 에이전트 사이에 선다. 대화가 저장소 일로 넘어가면 그 일의 역할 문서를 읽고 워크트리에서 한다.

**맡길지는 비용으로 정한다** — 서브에이전트 하나는 첫 수정 전에 약 7만 토큰이 더 든다(고정 약 3.7만 + 문서 탐색, 2026-11-21 측정).
1 ~ 3 파일짜리 일은 조율자가 그 역할로 직접 한다. 맡기는 것은 충돌 영역이 갈리는 병렬 일(`docs/agents/delegation/parallel.md` 「나란히 맡길 때」)과
격리 · 따로 검토가 필요한 일이다 — 워크트리 격리 · 백그라운드로 하나씩. 맡길 때도 역할(전문가 롤)은 이름으로 분명히 준다 — 운영자가 좋아한다.

**브리프** — 에이전트는 이 대화를 모른다. 역할 이름(`docs/start.md` 「역할 고르기」 — 「역할 문서를 다 읽어라」는 적지 않는다)에 세 칸을 더한다.

- **성공 기준** — 끝났다는 게 무엇인지, 잴 수 있게. 해결책은 적지 않는다 — 고칠 모양을 적으면 구조를 안 보고 증상만 고친다. 정책 · 새 흐름에
  한국 실사례가 없으면 구조와 선택지를 보고하게 한다(`docs/agents/delegation/decisions.md` 「정책 · 흐름의 빈틈」)
- **해도 되는 것 / 안 되는 것** — 나란히 도는 세션과 그 파일, 내보내기(PR 까지 · `--auto` · `db push`), 나눠 준 ADR · `G-nn` · 문구 대장 절 번호.
  규칙은 기억으로 다시 쓰지 않는다 — 원본에서 옮긴 한 줄과 절 이름으로 준다. 찾기 · 검토 브리프에는 「범위는 지금 운영에 열린 기능만」을 넣는다 — 닫힌 기능(지금은 인연,
  G-135)의 발견은 「보류」로 권하고, `scripts/ui-seed.mjs` 가 그림용으로 연 인연은 운영 상태가 아니다
- **볼 곳 두세 개** — 파일 경로 · 절 이름(화면 시안은 `docs/agents/delegation/working.md` 「화면은 시안 먼저」, 문구는 `docs/agents/code-rules/screen-copy.md` 「화면 문구」)

보고는 메시지로 받는다 — 하네스가 `.md` 보고 파일을 막을 수 있다.

**묻는 곳과 말하는 법**

- **운영자가 고치라고 한 일은 커밋 · PR 까지 묻지 않는다** — 묻는 것은 결정 점검표에 걸린 것과 배포뿐이다. 머지는 「출시 흐름」.
- **사람에게 묻는 곳은 조율자 하나다.** 에이전트는 멈추지 않고 사람 판단이 드는 것(정책 · 비용 · 되돌릴 수 없는 설정)을 보고에 모은다. 조율자가
  모아 한 번에(질문 넷까지) 묻고, 결정 PR 의 표는 PR 이 열린 그 차례에 낸다. 사람만 할 수 있는 것(계정 · 사업자 정보 · 변호사)은 빈칸 ·
  `[변호사 검토 필요]` 로 두고 나머지를 끝낸다.
- **운영자에게는 쉬운 한국어로 짧게 말한다** — `G-nn` · ADR 번호 · 약어 · 영어 도구 이름은 풀어 쓴다(「인연을 여는 일(G-135)」, 「끝난 작업 폴더 정리」).
  명령 · 경로만 그대로 둔다.
- **맡길 때 예상 시간을 말하고, 넘기면 묻기 전에 알린다** — 살아 있는 에이전트 · 기다리는 것 · 다음 확인 시각을 한 줄로.
- **브라우저(`ego-browser`)에 로그인된 콘솔(Play Console · Google Cloud · Vercel 등)의 일은 에이전트가 한다.** 운영자에게는 계정 · 결제 · 동의와
  권한 표가 사람의 답을 요구하는 것만 넘긴다.
- **남은 일을 말하기 전에 간극 대장의 `보류` 줄을 본다** — 조건이 올 때까지 다시 권하거나 묻지 않는다. 운영자 확인이 남은 줄은 「결정 대기」가 아니다.

**판단**

- **무엇이 무엇을 답하나 — 사실과 의도.** 지금 동작은 코드와 실행 결과가, 의도는 PRD · ADR · 운영자 결정이 답한다. 어긋나면 버그 · 문서 노후 ·
  결정 미반영 가운데 무엇인지 가른다(가르는 일이 결정 점검표에 걸리면 결정이다). 운영자가 승인해 보낸 운영 코드와 어긋난 시험 · 문서는 노후다 —
  코드를 되돌리지 않는다.
- **확인한 흔적을 붙여 전한다** — 운영자 판단을 부르는 주장에는 이 세션에서 확인한 `파일:줄` · 실행 결과를, 저장소 밖 사실(법 · 가격 · 업체 조건)에는
  출처 링크를 붙인다. 없으면 「확인 전」. 에이전트 · 외부 리뷰의 판정도 코드에서 확인한 뒤 그 조건째 전한다.
- **구조 문제는 지적받기 전에 권고로 낸다** — 원본 둘 · 흩어진 설정(같은 공개 값이 Vercel · EAS 에 따로) · 어긋난 문서 · 둘로 갈린 할 일 목록 ·
  남은 워크트리. 질문이 아니라 고칠 모양과 까닭으로.
- **위험에 따라 두 번째 검토를 붙인다** — 운영 정책 · DB · 보안 · 사용자 약속이 걸린 보고 · 문구와 결정 점검표에 걸린 PR 은 이 대화를 모르는 검토
  에이전트가 코드와 대조한다. 결정 PR 은 push 전 로컬 diff 로 받는다(CI 한 바퀴가 8 ~ 13분).
- **전체 감사는 사건에 붙인다** — 출시 전 · 큰 기능 정리 뒤 · 병렬 PR 라운드 뒤. 읽기만 하는 역할 여덟(코드 규칙 · 아키텍트 · 시험 · 보안 · DB ·
  프런트 · 문서 · SRE)이 `origin/main` 의 파일:줄로 적는다.

**PR 과 머지의 함정**

- **에이전트의 PR 에 커밋을 더하면 PR 의 가지로 민다** — `git push origin HEAD:$(gh pr view <N> --json headRefName -q .headRefName)`.
  워크트리의 로컬 가지 이름이 달라 `git push origin HEAD` 는 원격에 새 가지를 만든다.
- **병렬 라운드의 머지 직전에 `npm run merge:sim -- <머지할 순서의 PR 번호…>`** — PR 마다 초록이어도 한 PR 의 새 잠금이 다른 PR 의 새 파일을 몰라
  합치면 실패할 수 있다.
- **「CI 기다림」 보고를 믿지 말고 PR 을 본다.** 하나가 머지되면 남은 PR 이 `DIRTY` 가 되고 거기엔 CI 가 안 돈다 — 머지마다
  `gh pr list --json number,mergeStateStatus` 를 보고 `DIRTY` 면 main 을 merge 하게 한다. 제목만 고치면 검사가 다시 안 돈다(빈 커밋을 민다).
  `gh pr update-branch` 뒤 `--auto` 가 풀릴 수 있다. 「기다림」을 남기고 끝난 에이전트는 꺼진 것이다 — 남의 일을 기다리는 머지 사슬은 조율자가
  `gh run watch <run id> --exit-status` 를 백그라운드로 돌리며 민다.
- **머지는 배포가 아니다** — Git 배포가 꺼져 있어 에이전트는 Vercel 의 Ready 를 기다리지 않는다. 배포는 「출시 흐름」 3.
- **화면 일의 보고는 전후 그림과 고친 자리의 로컬 시험이다** — e2e · 전체 CI 를 따로 지시하지 않는다(CI 계획이 정한다).
- **PR 을 다른 에이전트에게 넘길 때 앞 워크트리를 먼저 정리한다** — 앞 워크트리가 가지를 쥐면 새 에이전트가 체크아웃하지 못한다. push 안 된
  커밋은 먼저 PR 의 가지로 민다.

## 출시 흐름 — 운영자 검토 · 머지 · 배포 · 정리 (ADR 0229)

이 절과 다른 글이 어긋나면 이 절이 맞다.

1. **일이 끝나면 에이전트가 PR 을 연다.** 코드 PR 은 `--auto` 를 걸지 않고 운영자 검토를 기다린다. 문서 PR 은 열자마자 `--auto` 다.
2. **화면을 더했거나 흐름을 바꿨으면 조율자가 아티팩트 보고를 낸다** — 바뀐 폭(390 · 1280 · 1920)의 전후 그림, 잰 값, 무엇을 왜(출처와 함께).
   운영자는 diff 가 아니라 이것을 검토한다. 문구만 · 문서만이면 글 요약이면 된다.
3. **운영자가 승인하면** 최신 main 위에서 `--auto` 로 머지하고 `docs/ops/runbook/deploy.md` 「묶음 배포」로 간다 —
   **운영 배포는 운영자의 「배포」 답 뒤다**(`docs/agents/delegation/permissions.md` 「권한 등급」 등급 3).
4. **머지와 배포 기록(#770 댓글) 뒤에는 머지된 PR 의 워크트리와 로컬 가지를 묻지 않고 정리한다** — `npm run sweep:merged` 미리보기 → `-- --apply`.
   바이패스가 아닌 herdr 세션은 미리보기를 묻고 지운다(`docs/agents/delegation/herdr.md` 「저장소 규약과 다른 자리」).

**바이패스 줄** — 운영자가 바이패스 모드로 돌리는 세션(무인 라운드 · herdr Lead 포함)에서는 코드 PR 의 머지 승인을 묻지 않는다. 결정 PR 의
독립 검토와 CI 초록 뒤 조율자가 머지하고, 아티팩트 보고는 내되 기다리지 않으며, 머지된 제 워크트리 · 가지도 묻지 않고 정리한다(남이 띄운 것은 둔다).
없앤 것은 머지 승인뿐이다 — 결정 점검표의 물음에 아직 답이 없으면 그 답이 먼저고, 운영 배포는 그대로 「배포」 답 뒤다.

## 인계 — 세션을 끝낼 때 남기는 것

인계는 #770 의 댓글 하나다 — `node scripts/session-status.mjs` 의 출력에 사람만 아는 칸을 더한다.

- [ ] **원본에 들었나** — 끝난 일 · 정한 정책 · 대화로 받은 결정 · 켜고 끈 기능 · 콘솔 설정이 원본(ADR · PRD · 약관 · 간극 대장 · `docs/ops/runbook/`)에
      들었나. 이슈 댓글에만 둔 운영 상태는 끝나지 않은 것이다. 어긋난 채 남기면 간극 대장에 줄로
- [ ] **main 의 CI 실패** — 원인과 누가 고치는 중인지
- [ ] **열린 PR 이 기다리는 사람의 답** — 운영자 검토 · 결정 표 · `db push`
- [ ] **돌고 있는 것 · 남긴 것** — 살아 있는 에이전트 · dev 서버 · 가짜 서버 · Metro, 꺼진 채 남긴 로컬 스택의 자리 · 볼륨 · 보존할 Docker 이미지와
      그 까닭 · 언제 지워도 되는지. 누구 것인지는 만든 세션만 안다
- [ ] **운영자만 할 수 있는 새 일** — #770 에 줄로 더한다. 새 확인 이슈를 열지 않는다

라운드 노트는 다른 데 없는 것이 있었을 때만 쓴다(`docs/agents/delegation/notes.md` 「세션 기록」). ADR 은 되돌리기 비싼 결정에만 — 절차 조정은 규약 문서를 고친다.

## 자주 하는 실수 — 한 줄과 고치는 법

맨 위 줄이 다른 줄의 뿌리다.

- **코드 · 문서 · 정책이 따로 논다** → 끝난 일과 정한 정책은 그 차례에 원본에 넣는다(`docs/agents/delegation/done.md` 「끝났다는 것」의 「코드 · 문서 · 정책」)
- **기억(사설 메모리)에만 적는다** → 같은 차례에 저장소에도 — 서브에이전트 · Codex 는 기억을 못 본다(`AGENTS.md` 「새 기억은 저장소에 적는다」)
- **올린 글을 고치라는데 새 글을 올린다** → 운영자 이름으로 나간 글(카페 · 스토어 등록정보 · 이슈 댓글)은 열어 「수정」한다. 남의 글은 구조 · 표현을
  옮기지 않고 새로 쓴다
- **이미 정한 것을 다시 묻는다** → ADR · 약관 · PRD · 간극 대장을 grep 한다. 대화에서만 정했으면 지금 ADR · PRD 에 적는다
- **그림 도구가 맞추는 값을 손으로 고친다** → `node scripts/ui-seed.mjs` 와 `node scripts/ui-shots.mjs` 를 그대로 돈다(`docs/agents/delegation/local-env.md` 「워크트리에서 전후 그림 찍기」)
- **가짜 서버 그림의 결함을 버그로 보고한다** → 코드와 DB 값에 대 본다. 가짜 데이터 · 꾸민 예문에서 난 것은 결함이 아니다

## 라운드 끝 정리

라운드 끝 보고에 `npm run sweep:merged` 미리보기를 싣는다 — 운영자가 「정리해」라고 하기 전에. **내가 띄운 것만 끈다** — 사람이나 다른 세션이 띄운
프로세스 · 워크트리는 두고, 애매하면 묻는다.

- [ ] **워크트리 · 로컬 가지** — `npm run sweep:merged -- --apply` 는 「걷을 것」만 정리한다(판정은 `scripts/sweep-merged.mjs` 머리말). 머지되고
      배포 기록까지 적힌 PR 의 것은 묻지 않고, 그 밖의 것은 한 번 확인한다. 「끝난 듯」(잠근 세션이 살아 있다)은 제 에이전트가 끝난 것을 본 뒤
      손으로 정리한다. 스택 때문에 건너뛰면 거기서 `npm run db:stop` 뒤 다시 부른다
- [ ] **백그라운드 셸 · 에이전트** — 내가 띄운 dev 서버 · 대기 고리 · 끝난 에이전트를 끈다. 포트를 쥔 남의 프로세스는 `kill` 하지 않는다.
      herdr 터미널은 운영자에게 묻고 끈다
- [ ] **그림 · 임시 파일** — 그림은 운영자가 아티팩트를 확인한 뒤 함께 지운다
- [ ] **정리 기록** — 라운드 노트를 쓰면 정리한 것과 남긴 것(인계의 「돌고 있는 것 · 남긴 것」)을 한 줄로

**Docker 정리는 디스크가 모자라거나 지워진 워크트리의 볼륨이 보일 때만 한다** — `npm run sweep:docker` 로 진단하고, 보존할 것은 인계에 적고,
지우기로 정한 볼륨만 이름으로 `npm run sweep:docker -- --apply <볼륨> …`. 이름을 대는 것은 잘못 지우는 것을 막는 수단이지 삭제 권한이 아니다.
