# 코드 규칙 — 화면 문구

색인은 `CODING_STANDARDS.md` 다.

## 화면 문구

문체 규칙은 여기 없다 — `docs/context/copy.md` 「화면 문구 규칙」과 `docs/product/prd/screens.md` §3.2(상품 이름 넷, 버튼은 동사로 갈린다)가 답한다.

**한글 문구를 지어내지 않는다**(ADR 0196) — 문법이 맞아도 제품이 쓰는 말이 아닌 문장은 퇴짜를 맞는다. 차례는 이렇다.

1. **대장에서 찾는다** — 머리 `docs/product/copy-ledger.md` 와 고칠 화면의 무리 파일(`docs/product/copy-ledger/`). 있으면(「확인 전」 절도) 그 글자를 쓴다
2. **없으면 실사례로 넣는다** — 같은 자리에 한국 서비스가 쓰는 표현을 찾아(차례 · 꼴은 `docs/agents/code-rules/references.md` 「레퍼런스」)
   출처와 함께 넣고, 글자를 묻지 않고 PR 까지 간다 — 운영자는 나중에 확인한다. 머지는 다른 코드 PR 처럼 운영자 검토 뒤다
   (`docs/agents/delegation/coordinator.md` 「출시 흐름」)
3. 시안 · 외부 리뷰 · 에이전트의 문구는 출처가 없으면 넣지 않는다. 운영자가 승인한 시안의 글자, 사용자가 불러 준 문안은 그 자체가 출처다 —
   한 자도(줄바꿈까지) 바꾸지 않고 「확정 문구」 절로 넣고 #770 에 올리지 않는다. 브리프 · 시안은 그 밖의 글자를 「확정」이라 적지 않는다(ADR 0255)

넣은 글자의 기록:

- 그 PR 이 무리 파일에 「확인 전」 절(`## <무리>-NN 확인 전 — …`)을 더한다 — 줄마다 자리 · 이전 · 넣은 글자 · 출처(제 링크 · 확인 날짜, 「위와 같음」 안 됨).
  실사례가 없으면 「실사례 없음」과 가장 가까운 사례 — 그 링크 · 다른 대장 절(`home-13` 꼴) · 제품 코드의 `const` 이름 중 하나.
  꼴은 `scripts/code-rules.test.ts` 가 잡는다. 정책 · 새 흐름의 빈자리는 글자가 아니다 — `docs/agents/delegation/decisions.md` 「정책 · 흐름의 빈틈」
- 머지되면 운영자 확인 이슈 #770 에 줄을 더한다(PR · 절 · 자리) — 새 이슈를 열지 않는다. 확인되면 절 제목을 「확정 문구」로, 고쳐 주면 그 글자로
- 「확인 전」 절을 옮기거나 자리 칸을 고치면 `NEAREST_MISSING_STILL_THERE`(시험 안)의 그 줄도 지우거나 고친다
- 문구가 결정 점검표의 다른 줄(권한 · 보존 · 삭제 · 비용 · 요금 · 환불, 새 약속)에 걸리면 머지 전에 묻는다(`docs/agents/delegation/decisions.md` 「결정 점검표」)

문구만 바뀐 라운드는 시험을 안 돌린다. 예외 — `/ops/**` 에서 운영자에게만 보이는 설명 · 제목 · 빈 상태는 실사례 없이 쓰고 PR 에 모아 보고한다.
개인정보의 이용 · 보관, 운영자 권한, 제재 결과, 사용자에게 가는 문구는 예외가 아니다(ADR 0103).

**저장소 내부 말을 그 내부 뜻으로 화면에 옮기지 않는다** — 문서는 지웠다 · 뺐다 · 회수했다를 「걷다」로 써 왔고, 그 말이 화면에 새면 이용자가
못 읽는다(사례 `docs/product/copy-ledger.md` 「all-09」).

- 걷다(삭제 · 회수) · 서다 · 들다 · 재다 · 밟다 · 판 · 문 · 몫 · 회차 · 예약 중 · 풀리다 등. 원래 뜻의 비유(오래 걷던 두 사람)는 괜찮다 — 글자가 아니라
  뜻으로 가른다. 목록과 대신 쓸 말은 `docs/context/copy.md` 「이 뜻으로 쓰지 않는 말」
- 운영(`/ops`) 화면의 집계 · 상태 칸 이름은 명사 꼴 — 구매 · 사용 · 사용 중 · 환불 · 회수 · 잔여. 동사 관형형(산 · 쓴 · 걷은)이 아니다

**이용자 화면의 설명은 명리 이름 없이 일상어로 쓴다.** 부를지는 `docs/context/evidence.md` 「이름을 안 부르는 판」이 정한다. 명리 카페 ·
전문가 글은 출처가 있어도 맞는 사례가 아니다 — 독자가 다르다.

**글자를 바꾸면 옛 글자를 찾는 시험도 그 PR 이 고친다** — `e2e/` · `scripts/check-*.mjs` 는 글자를 이름 그대로(`name: '…', exact: true`)도 찾는다.
문구가 말하는 상태 전이(누르면 무엇이 되나 · 실패 갈래)는 코드에서 확인한다.

문구는 그 화면(`.tsx`)에 산다. 여러 화면이 같은 사실을 적으면 상수 하나(`HOUR_UNKNOWN_LABEL`)로 둔다. 화면만 쓰는 상수는
`src/lib/<영역>/copy.ts`(ADR 0159) — 글자 · 글자만 든 표만 두고, 시험이 그 이름으로 찾으면 「문구만」 PR 이 아니다. `copy.ts` 상수를 JSX 자식 ·
글자 속성 밖(프롭 · 배열 · 인자)에 쓰면 `scripts/ci-plan.mjs` 의 `copyConstantMisuses` 가 잡는다 — 그런 문구는 `copy.ts` 밖의 상수에 둔다.
