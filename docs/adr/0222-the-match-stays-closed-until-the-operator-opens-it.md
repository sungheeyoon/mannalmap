# 사주부터 운영하고 인연은 닫아 둔다 — 카드 · 대화 · 채팅 · 상세 궁합을 닫힌 스위치 하나 뒤에 두고 운영 SQL 한 줄로 연다

> **운영자 결정 2026-11-04**(조율자가 옮김) — 「사주부터 운영하고, 인연 카드 · 요청 · 채팅은 닫아 둔다. 사람이 모이고 카카오 답 · 본인확인이 갖춰지면 연다.」
>
> 까닭: 카카오 로그인을 붙이려는데 카카오 운영정책 제4조가 「청소년에게 금지되는 콘텐츠(… 만남주선 등)」를 금지하고, 카카오 인증서 확인과 별도 검토로만 예외를 둔다
> (<https://developers.kakao.com/terms/latest/ko/site-policies>, 확인 2026-11-04). 카카오에 「현재 사주 기능만 제공한다」고 사실대로 문의하려면 운영에서 인연이 실제로 닫혀 있어야 한다.
>
> 결정 점검표의 「누가 무엇을 볼 수 있는가 · 할 수 있는가」 · 「실패했을 때 열리는가 닫히는가」에 걸린다. 세부(닫힌 주소의 행선지 · 참여 중인 프로필 · 소식)는 운영자에게
> 되묻지 않고 기존 정책(ADR 0214 의 막는 자리 · `/me/discovery` 의 옮김)에서 골라 여기 적는다. 이 ADR 은 ADR 0215 의 흐름(대화가 유일한 흐름, `20270109090000`)을 바꾸지 않고 그 앞에 문을 하나 더 둔다.

## 잰 것

- 운영 DB 의 인연 요청 · 인연 · 대화방은 0건이다(조율자의 앞선 집계, 2026-11-04). 초대받은 베타 사용자만 있다 — 닫아도 숨는 줄이 없다.
- 인연의 문은 이미 한 판정을 지난다 — 성인 확인(ADR 0214)이 막던 열여섯 함수(`20270109090000` 까지의 로컬 스택, `pg_get_functiondef`). 표를 바로 읽는 길(`chat_room` · `chat_message`)도
  RLS 가 `chat_room_readable` 하나로 모인다. 남의 행을 내는 그 밖의 표(`match` · `match_request` · `notification` · `discovery_candidate`)는 `authenticated` 에 열려 있지 않다.
- 깔린 앱(OTA 전)은 `match_talk_open()` 을 읽어 참이면 「대화 시작」을, 거짓이면 옛 「궁합 요청」을 그린다(`origin/main` 의 `mobile/src/matching/talk-doors.ts`). 어느 쪽이든 카드 · 요청 · 방은 DB 를 부른다.

## 정한 것

1. **스위치** `match_open_switch` 는 한 줄이고 기본값은 닫힘이다. 어느 마이그레이션도 열지 않는다. **줄이 없으면 닫힌 것이다**(실패 때 닫힘). 여닫는 것은 `docs/ops/runbook/match-opening.md` 의 운영 SQL 한 줄이다.
2. **판정** — 화면이 읽는 `match_is_open()`(anon · authenticated, 참 · 거짓 하나), 문이 묻는 `match_open_to(사람)` = 열림 그리고 성인 확인 통과, 쓰는 문의 거절 `match_must_be_open_to(사람)`.
   닫혀 있으면 「인연은 준비 중이에요.」(42501), 열려 있으면 성인 확인의 거절을 그대로 낸다. **성인 확인을 묻던 자리는 모두 이 판정을 묻는다** — 새 문이 성인 확인만 물으면 닫힌 동안 열리는 길이 생기므로
   `scripts/match-stays-closed.test.ts` 가 마이그레이션의 최신 본문을 훑어 막는다(성인 확인만 부르는 문). 둘 다 빠뜨린 문은 아래 「시험」의 pgTAP 8 이 인연의 표를 기준으로 잡는다.
3. **닫힌 동안 막는 자리** — 양쪽(나와 상대)을 다 본다. 카드에 남의 프로필이 서는 길이 없다.

   | 갈래 | 문 | 닫힌 동안의 답 |
   | --- | --- | --- |
   | 카드 | `my_discovery_board` · `my_passed_connections` · `restore_passed_connection` | 「인연은 준비 중이에요.」 |
   | 대화 · 답 | `request_match`(기대 종류를 실어도) · `respond_to_match_request`(답) | 같은 문장 |
   | 채팅 | `send_chat_message` | 같은 문장 |
   | 상세 궁합 | `request_match_detail` · 시도를 여는 문(`match_consent_holds` 가 거짓 → 동의 없음 거절) | 같은 문장 · `23514` |
   | 읽기 | `my_match_requests` · `my_matches` · `my_match_scope` · `my_match_detail_state` · `my_chat_rooms` · `my_chat_messages` · `unread_chat_count` · `my_ended_talks` · 요청 · 인연 소식 · 인연 궁합 글 | 비어 있다(`visible_matches` · `chat_room_readable` · `visible_notifications`) |
   | 표 직접 | `chat_room` · `chat_message` 의 RLS | 비어 있다 |
   | 사진 | `photo_at`(웹 `/me/photo/*` · 앱 `/api/mobile/photo/*`) | 남의 사진이 안 열린다(`may_see_photo`) |
   | 앱 API | `/api/mobile/matching/respond` · `/api/mobile/matching/detail` | 위 DB 거절을 옮겨 `ok: false` |

4. **닫혀도 열린 것** — 사주 · 궁합 · 저장, 그리고 떠나고 지키는 길(받은 상세 거절 · 보낸 요청 취소 · 차단 · 신고 · 참여 끄기 · 탈퇴). ADR 0214 의 6 과 같은 줄이다.
5. **참여 중인 사람의 프로필** — 지우지도 끄지도 않는다. 내 사주를 저장하면 자동 참여(`ensure_discovery_participation`)와 참여 스위치(`set_discovery_participation`)는 닫혀 있어도 그대로 돈다 —
   남에게 보이는 길이 모두 닫혀 있어 노출이 없고, 열 때 성인 확인을 함께 켜면(아래 「여는 조건」) **그 확인이 공개 시점**이 된다(ADR 0214 추기의 「확인을 마치면 다른 회원에게 내 프로필이 보여요」).
   끄는 쪽을 고르지 않은 것은 열 때 모두를 다시 켜는 운영 SQL 이 동의 없이 노출을 바꾸는 일이 되기 때문이다.
6. **화면 — 길만 걷는다.** 막는 것은 DB 다. 이 갈래가 통째로 틀려도 열리는 문은 없다.
   - **메뉴** — 웹 머리글 · 하단 독과 앱 탭 막대가 홈 · 궁합 둘이 된다. 열렸다고 **읽기 전에는** 인연 · 채팅을 안 세운다(실패 때 닫힘 — 못 읽은 한 번에 탭이 빠지는 쪽이, 누르면 홈으로 돌아오는 탭을 세우는 쪽보다 낫다).
     종(소식)은 남는다 — 풀이 · 풀이권 소식이 있다. 채팅의 안 읽은 수는 열렸을 때만 센다.
   - **입구** — 웹 설정의 「인연」 무리(참여 · 소개받을 성별)와 새 메시지 알림 줄, 앱 설정의 「인연」 무리, 앱 첫 화면 · 사주 저장 카드의 「인연은 어떻게 찾나요?」, 보관함의 「오늘의 인연」 빈 책이 안 선다.
   - **주소** — `/me/matching/**`(성인 확인 안내 포함) · `/me/match/*` · `/me/readings/match/*` · `/me/chat/**` · `/me/discovery` · 앱의 `/matching-intro` 는 닫혔다고 읽으면 **홈(`/me`, 로그인 전의 인연 소개는 `/`)으로** 간다 —
     웹은 관문(`proxy.ts`)이 화면 요청(GET)에서만, 앱은 껍데기(`useMatchClosedGuard`)가. 못 읽으면 안 돌리고 문의 거절이 말한다. 성인 확인 안내보다 먼저다 — 확인해도 열 것이 없다.
     행선지를 홈으로 고른 것은 이 저장소의 옮김(`/me/discovery` → 설정, 끝난 베타 → `/closed`)이 「갈 수 있는 가장 가까운 자리」로 보내는 꼴이고, 닫힌 기능에 안내 화면을 새로 세우면 새 문구 · 새 화면이 늘기 때문이다.
     **새 화면 문구는 DB 거절 하나다** — 깔린 앱이 인연 탭에서 그 문장을 세운다(대장 matching-22).
7. **깔린 앱(OTA 전)** — `match_talk_open()` 이 **이 스위치를 따른다** — 닫힘 파일에서는 옛 대화 스위치와 이 스위치가 둘 다 켜져야 참이고, `20270109090000` 이 옛 스위치를 걷으며 늘 참 대신 이 스위치만 따르게 했다. 닫힌 동안 거짓이라 깔린 앱은 옛 단추 글자를 그리지만, 탭을 열면 카드 문이 「인연은 준비 중이에요.」로 거절하고
   요청 · 방 · 채팅 목록은 비어 있다 — 옛 「궁합 요청」을 눌러도 `bundled` 는 `22023`, 대화는 닫힘으로 거절된다. 깔린 앱은 탭을 숨기지 못한다(그 코드가 없다) — 숨김은 새 OTA 부터다. 열면 참이 되어 #1001 이 뜻한 대로 대화를 그린다.
8. **여는 조건** — 셋이 다 갖춰지고 운영자가 승인한 뒤 한 번에 연다: ① 카카오의 답(만남주선 예외 검토 · 카카오 로그인과의 관계), ② 본인확인 — 성인 확인(#947, ADR 0214)의 업체 · 서버 문이 서서 **같은 날 성인 확인을 켤 수 있음**, ③ 수요 측정 — 사주 사용자 수와 인연 참여 의사(운영자가 기준을 정한다). 차례는 runbook.
9. **닫힘은 운영에 안 오른 인연 파일의 맨 앞에 선다** — 마이그레이션 `20270106120000` 은 운영의 마지막 판(`20270106090000`) 바로 뒤다.
   CLI 는 파일마다 트랜잭션을 묶어 커밋하므로, 닫힘을 맨 끝 파일에 두면 앞 파일(대화를 여는 `20270109090000`)이 커밋된 뒤 닫힘이 오르기 전까지 · 닫힘이 실패하면 그 뒤로도
   열린 구간이 생긴다. 맨 앞에 두고, 뒤 파일 중 인연 문을 다시 쓰는 둘(`20270107090000` 의 `request_match`, `20270109090000` 의 `request_match` · `respond_to_match_request` ·
   `request_match_detail` · `match_talk_open`)을 운영에 오르기 전에 같은 판정을 부르게 고쳤다. `20270107100000`(닫힌 방의 말을 지우는 크론) · `20270108154600`(정지 · 탈퇴)은
   인연을 여는 문을 다시 쓰지 않는다. 모두 한 파일로 다시 짜는 안은 고르지 않았다 — main 에 이미 든 파일 셋을 지우고 다시 세워야 하고, 다른 가지 · 로컬 DB 의 판 이력이 갈린다.
   **경계마다 잰 표**는 `scripts/match-closed-boundaries.mjs` 가 낸다: 운영의 지금(열림) → 닫힘 파일 커밋부터 마지막까지 열한 경계(각 파일의 실패 · 되돌림 포함)가 모두 닫힘.
10. **고지 · 약관은 그대로다** — 닫힘은 기능을 쓰지 않는 상태라 수집 항목이 늘지 않는다. 고지 판 번호는 건드리지 않는다.

## 실패했을 때

| 자리 | 답 |
| --- | --- |
| 스위치 줄이 없다 | 닫힌다 — pgTAP 이 잰다 |
| 화면이 열림 여부를 못 읽는다 | 탭 · 입구는 닫힌 쪽, 주소는 안 돌린다. 문이 거절한다 |
| 열린 동안 성인 확인이 켜져 있다 | 미확인인 사람은 성인 확인의 거절을 받는다 — ADR 0214 그대로 |

## 고르지 않은 것

- **화면에서만 숨기기** — 깔린 앱 · PostgREST 직접 호출 · 직접 주소가 그대로 열린다. 카카오에 「닫혀 있다」고 말할 수 없다.
- **성인 확인 스위치를 켜서 닫기** — 확인할 업체가 없으니 누구도 못 지나가 닫히긴 하지만, 문장이 「성인 확인을 먼저 마쳐 주세요.」라 사실과 다르고 열 때 두 뜻이 엉킨다.
- **옛 스위치(`match_talk_switch`)를 되살리기** — #1001 이 옛 흐름과 함께 걷었다. 이 스위치는 흐름을 고르지 않고 인연 전체를 여닫는다.
- **판정 함수의 이름을 그대로 두고 본문만 바꾸기**(`adult_check_passed` 가 닫힘도 묻게) — 이름이 거짓말을 하고, 참여 문처럼 성인 확인만 물어야 할 자리까지 닫힌다.
- **참여를 모두 끄기** — 위 5.

## 잠그지 않은 것

- 닫힌 동안에도 인연의 크론(상세 만료 · 끝난 방의 말 지우기 · 사진 쓸기)은 그대로 돈다 — 줄이 0이다.
- 풀이 보관함의 「인연」 칩은 그대로 선다. 인연 궁합 글이 없어 비어 있다.
- 웹 관문은 화면 요청에서만 돌린다. 서버 액션(카드 넘기기 · 요청)은 돌리지 않고 문이 거절한다.
