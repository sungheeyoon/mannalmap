# 열린 PR 이 이미 잡은 공유 번호를 늦게 연 PR 이 더하면 gate 가 붉다 — API 를 못 읽으면 경고하고 통과다

> **조율자 지시 2026-11-07** — 같은 날 나란히 열린 PR 들이 같은 ADR 번호(#1060 의 0235 와 #1061 · #1066 의 다음 번호)와 같은 문구 대장 절
> (`settings-16`, #1061 · #1063)을 잡았다. git 은 파일 이름 · 다른 줄이라 부딪히지 않았고, 늦은 쪽은 앞 PR 이 머지된 뒤 `scripts/code-rules.test.ts` 가
> 붉어서야 번호를 다시 매겼다. 그때까지 막는 것은 `docs/agents/delegation/parallel.md` 표의 문서 줄(「`gh pr list` 로 보고 다음 것을 잡는다」)뿐이었다.
>
> **결정 점검표의 「실패했을 때 열리는가 닫히는가」와 「검증 · 배포의 문턱」에 걸린다.** 둘 다 조율자가 브리프에서 정해 맡겼다 — 늦게 연
> 쪽이 알리고, API 가 안 되면 통과시키고 경고한다. 이 ADR 은 그 판단의 근거를 든다.

## 정한 것

1. **공유 번호는 넷이다** — ADR 파일 번호(`docs/adr/NNNN-…`) · 간극 대장의 `G-nn`(`docs/product/gaps.md` 의 새 줄) · 문구 대장의 절 번호
   (`## settings-16 …`, 무리마다 따로) · 마이그레이션 시각(`supabase/migrations/NNNNNNNNNNNNNN_…`). 마이그레이션은 ADR 0071 · `parallel.md` 의
   「마이그레이션 사슬은 순차」로 나란히 안 돌지만, 어기면 다른 파일 이름이라 git 이 못 보고 같은 판본 둘이 `db push` 에서야 부딪히므로 함께 잰다.
   처리방침 판본(`notice-vNN`)은 넣지 않았다 — 상수 한 줄(`src/lib/consent/notice.ts`)이라 두 PR 이 고치면 git 이 충돌로 막는다.
2. **새로 더한 번호만 센다.** ADR · 마이그레이션은 더한 파일(`added` · `copied` · 다른 번호에서 옮긴 `renamed`)이고, 있는 ADR 에 덧을 단 것
   (`modified`) · 모드만 바꾼 것(`changed`) · 이름만 바꾼 것은 아니다. 대장은 패치에서 `+` 로 선 줄 가운데 같은 대장의 `-` 에 없는 번호다 —
   줄을 고치거나 옮기면(문구 대장은 무리 파일 사이로 옮겨도) 둘 다에 선다.
3. **알리는 쪽은 늦게 연 PR 이다** — 이 PR 보다 번호가 작은 열린 PR 이 같은 번호를 더했으면 붉다. 번호가 큰 PR 과의 겹침은 그쪽이 안다.
   먼저 연 PR 의 머지는 막지 않는다: 그쪽이 먼저 머지되면 번호를 바꿀 일이 없고, 막으면 둘 다 선다. PR 번호는 여는 차례라 따로 시각을 읽지 않는다.
   같은 PR 의 재실행은 목록에서 저를 뺀다. 초안 PR 도 번호를 쥔 것으로 센다.
4. **실패는 겹친 PR 번호 · 제목과 다음 빈 번호를 든다.** 다음 빈 번호는 PR 을 main 에 합친 트리와 열린 PR **전부**(뒤에 연 것까지)가 잡은 번호
   위다. 간극 대장은 닫힌 줄을 지우므로 대장 · 기록 파일 · `docs/product/prd-changelog.md` 의 `G-nn` 을 다 센다 — 표만 보면 닫은 G-151 을 다시
   내준다(2026-11-07 의 표는 G-150 까지였다). 문구 대장은 그 무리의 다음, 마이그레이션은 가장 늦은 날의 다음 날 09:00:00 이다.
5. **자리는 `verify` 의 `gate` 다** — 새 job 이 아니다. `plan` 에 두면 붉을 때 차선이 다 건너뛰어져 다른 실패가 안 보이고, 새 job 은 「plan · gate
   밖의 job 은 전부 차선」(ADR 0082)을 깬다. gate 는 맨 끝에 돌아 그때의 열린 PR 을 읽고, 앞 차선의 결과와 상관없이 돈다. 권한은 그 job 에만
   `contents: read` · `pull-requests: read` 다. main 푸시 · 일정에서는 돌지 않는다.
6. **GitHub API 를 못 읽으면 통과시키고 경고한다**(fail-open). 이 검사가 막는 것은 「다시 번호를 매기는 수고」이고 겹친 번호는 앞 PR 이 머지된
   뒤 `code-rules.test.ts` 의 「ADR 번호는 한 파일에만 있다」 · 「G 번호는 한 줄에만 있다」 · 문구 대장의 번호 시험이 여전히 붉힌다. 닫으면
   GitHub 장애가 모든 PR 의 머지를 세운다. gate 가 저장소 · Node 를 못 받은 것도 같은 갈래다(두 단계는 `continue-on-error`) — 예전 gate 는
   바깥에 기대는 것이 없었으므로, 하나뿐인 필수 검사를 이 검사의 받기에 묶지 않는다. 대장 파일의 패치를 GitHub 가 안 준 PR(너무 큰 diff)도
   경고하고 그 대장만 못 본다. 한 PR 에서 같은 갈래가 둘 겹치면 둘째의 다음 번호는 첫째에 내준 번호 위다.

## 견준 것

- **`code-rules.test.ts` 의 번호 시험과 겹치지 않는다.** 그것은 한 트리(머지 뒤 · main 을 합친 가지) 안의 빈틈 · 겹침을 재고, 이것은 아직
  main 에 없는 열린 PR 사이를 잰다. 엇갈리지도 않는다 — 이 검사가 내주는 다음 빈 번호는 앞 PR 의 번호 위라, 앞 PR 이 머지되기 전에는 뒤 PR 의
  「ADR 번호가 빈틈없이 이어진다」가 붉다. 그것은 `parallel.md` 「ADR 번호」 줄의 「머지는 번호 순」 그대로다.
- **못 보는 자리**: 먼저 연 PR 이 뒤에 연 PR 이 이미 잡은 번호를 나중 커밋에 더하면 아무도 안 붉다(뒤 PR 은 다시 안 돈다). 그때는 먼저 든 쪽이
  머지된 뒤 남은 쪽의 `code-rules.test.ts` 가 잡는다 — 지금과 같다.

## 시험

`scripts/shared-numbers.test.ts` — 가짜 PR 목록으로 겹침 · 안 겹침 · 재실행 · 먼저 연 PR · 열린 PR 없음 · API 실패, 그리고 gate 의 권한과 부름.
