# 선 아이콘은 한 자료에서 두 쪽이 그리고, 앱의 고르기 판은 웹 `ActionSheet` 와 한 벌이며, 뼈대 · 스낵바는 웹에만 둔다

> **G-155 를 닫으며 정했다(2026-11-27, 무인 라운드 레인 B)** — 간극 대장의 끝 조건이 약속 표의 `pending` 셋을 「앱에 세우거나 안 세우기로 정한다」로
> 맡겼다. 겉모습의 뜻은 바꾸지 않았다 — 앱을 웹의 같은 이름 · 같은 값에 맞췄고, 바뀐 그림은 PR 의 전후 그림이다(운영자 확인 전).
>
> 이 결정이 바꾸는 것 — ADR 0241 (일부: 「정한 것」 7 의 `pending` 셋 — `ActionSheet` 는 앱에 섰고 `Skeleton` · `Snackbar` 는 웹에만 둔다. 「남은 것」은 아래로 옮겼다)

## 정한 것

1. **선 아이콘의 그림 자료는 `src/lib/design/icons.ts` 하나다** — `ICON_SHAPES`(그림 32 — 경로 · 원 · 네모)와 틀 `ICON_FRAME`(24 격자 · 획 1.8 · 둥근 끝).
   웹 `app/ui/icons.tsx` 와 앱 `mobile/src/ui/icons.tsx` 의 `Icon` 이 그 자료로 그리고 경로를 들지 않는다. 칠은 낱말이다 — `ink`(웹 `currentColor` ·
   앱 `color`) · `light`(태극의 밝은 반 — 웹 `var(--taiji-light, transparent)`, 앱은 비친다) · `none`. 웹 첫 화면 입구의 태극(`entry-marks.tsx` 의
   `TaijiShapes`)도 같은 자료이고, 앱만 부르는 `share` 도 자료에 산다.
   **웹 그림은 그대로다** — 아이콘 31 과 입구 그림 둘의 정적 마크업(`renderToStaticMarkup`)이 전후 바이트까지 같다. **앱은 `more` 하나가 바뀐다** —
   칠한 원(반지름 1.2)이던 점이 웹과 같은 선 원(반지름 1.2 + 획 반 0.9)이 되어 커진다(홈 내 사주 카드 · 대화방 · 인연 카드의 「⋯」).
2. **화면은 그림을 손으로 다시 세우지 않는다.** 앱 사진 크게 보기의 × · 「⋯」(획 2 · 반지름 1.8 점), 사진 칸의 ×(12 격자 · 획 1.6) · +(획 2),
   설정 줄의 「›」(16 격자 · 획 1.8), 공유본의 `Mark`(경로 셋의 사본), 웹 인연 지도의 `Spark`(경로 사본)가 `Icon` 을 부른다. 크기 · 굵기는 웹의 같은
   자리를 따른다 — 사진 칸 × 는 웹이 `size-3.5` 라 앱도 14px · 획 1.8 로 가늘어졌고, 설정 줄 「›」 는 웹 `size-4` 다.
   `scripts/design-icons.test.ts` 가 잰다 — 두 `Icon` 이 자료로 그린다 · 자료의 경로 글자(열 자 넘는 것)를 다른 파일에 베끼지 않는다 · 앱에서
   `react-native-svg` 는 그림 부품(아이콘 · 오행 · 천간 · 로고 · 점수 반원 · 로딩)과 표의 자리만 부른다. 표는 아이콘 한 벌에 짝이 없는 그림 여덟이
   까닭과 함께 든다 — 뒤로 「<」(웹은 「←」) · 확인 상자의 고름 표시(웹은 브라우저가 그린다) · 입구의 해 · 카카오 상징 · 관계 지도 · 궁합풀이 표지의
   두 색 면 · 빈 대화방 그림 · 만세력의 손그림 꺾쇠(G-165).
3. **사진 위의 동그란 단추는 웹 `photo-face`(검정 50%)다** — 오늘의 인연 카드의 ⓘ 와 신고 · 차단 「⋯」(`matching/today.tsx` · `matching/people.tsx`)가
   `alpha(검정, 0.42)` 에서 `COLOR.photoFace` 로 옮겼다. 인연이 닫혀 있어 운영 화면에는 안 선다(가짜 서버로 찍었다).
4. **앱의 고르기 판은 웹과 같은 이름 · 같은 값의 `ActionSheet` 다**(`mobile/src/ui/action-sheet.tsx`, 줄은 `ActionChoice` — 그림 · 이름 · 위험 · 할 일).
   손잡이 · 테 없는 흰 줄 묶음(`PLAIN_CARD_FACE` 에 여백 6) · 56 높이 줄에 20 그림 · 위험한 줄은 선 하나 뒤에 붉게 · 「취소」는 보조 단추 · 아래 여백은
   `max(20, 홈 막대)`. 웹이 JSX 에 클래스로 적은 값은 약속 표의 `values` 가 앱 글자와 견준다. 사진 보기의 「⋯」 판이 옮겼다 — 줄에 웹과 같은
   그림(대표로 설정 `spark` · 사진 변경 `pencil` · 위치 조정 `move` · 삭제 `remove`)이 서고, 「취소」의 테가 웹 보조 단추의 테가 됐다.
   판은 보기의 창 안에 깐다 — `Scrim` 의 `within`(창을 새로 띄우지 않는다). 고르면 보기와 판이 함께 닫히는데 iOS 는 닫히는 창 위에 다음 창을 못 띄운다.
   **사람 관리 시트(`people/parts.tsx` 의 `Sheet`)는 옮기지 않았다** — 그 짝은 웹의 띄움 메뉴(`person-menu.tsx` 의 `MENU_PANEL`)이고 시트는 제목
   (그 사람의 이름)을 든다. 고르기 판으로 옮기면 제목이 빠지고 「취소」가 서는 모양 바뀜이라 같은 모양을 한 원본으로 모으는 일이 아니다.
5. **뼈대(`Skeleton`)는 웹에만 둔다.** 웹의 뼈대는 Next 의 서버 화면 이동 때문에 섰다(ADR 0116) — `loading.tsx` 가 없으면 동적 화면을 미리 받지 않고
   누른 뒤 서버 답이 다 올 때까지 앞 화면에 머문다. 앱은 누르면 곧 다음 화면이고 그 화면이 첫 읽기를 오행 다섯 점(`LoadingDots`)으로 기다린다 —
   웹의 화면 안 기다림과 같은 꼴이다. 앱에 뼈대를 세우면 화면마다 새 로딩 모양이라 시안 · 승인부터다.
6. **바닥 스낵바(`Snackbar`)는 채팅을 열 때 세운다.** 웹에서 부르는 곳은 대화방 둘(대화 거두기 · 상세 궁합 취소)뿐이고 인연 · 채팅은 닫혀 있다(G-135).
   열린 앱 화면은 끝난 일을 곁의 한 줄로 말하고(`useDoneNote` — 웹 `DoneNote` 의 「곁의 한 줄이 먼저다」), 공유는 기기의 공유 창이다.
   약속 표(`src/lib/design/contract.ts`)는 이 둘을 `PARTS` 의 `pending` 에서 `WEB_ONLY` 로 옮겼다 — 웹에 그 이름이 있고 앱이 같은 이름을 세우지
   않았는지 `scripts/design-contract.test.ts` 가 잰다. 앱에 세우면 `PARTS` 로 옮긴다.
7. **화면 안 실패 글자는 웹의 같은 자리가 `FailureLine` 이면 앱도 `FailureLine` 이다**(ADR 0241 의 5 를 다섯 벌 밖까지). 열린 화면 열한 곳을 옮겼다 —
   가입의 별명 거절 · 가입 실패 · 다른 계정으로 나가기 실패(`app/signup.tsx`), 풀이 전 저장 실패 둘(`reading/save-self.tsx`), 홈의 내 사주 등록 실패
   (`app/me/(tabs)/index.tsx`) · 「알림 받기」 실패(`home/match-open-alert.tsx`) · 경고 「확인했습니다」 실패(`home/warning-notice.tsx`), 풀이 의견 실패
   (`reading/feedback.tsx`), 그리고 웹 짝은 없지만 누름 실패인 메일 열기 · 주소 복사 실패(`info/contact.tsx`) · 공유본의 로그인 시작 실패(`share/view.tsx`).
   13px · 줄 높이 19 · 20 이던 글이 14 · 24 가 되고 알림 역할이 선다. 다시 로그인이 답인 문장이면 웹과 같이 「다시 로그인」이 붙는다.
   **옮기지 않은 것** — 입력 안내 · 상태 줄(별명 중복 확인의 답 · 닉네임 곁의 말 · 동의 빠짐 · 임시 저장 실패 · 음력 바꿈 · 「바뀐 것이 없어요」) · 내역의
   환불 표시 · 확인 창 안의 경고 · 풀이 칸의 붉은 판 · 만세력 계산 실패는 웹의 짝도 `FailureLine` 이 아니다. 홈 · 관문의 읽기 실패 블록은 아래 「남은 것」.
8. **관계 지도의 숨 · 만남 박자(2600 · 900ms)는 토큰에 안 올린다** — 웹 `BEAT` 와 같은 화면 고유 값이다(ADR 0241 감사가 남긴 메모).

## 까닭

2026-11-08 감사(레인 D)가 값 층을 한 원본으로 잠근 뒤에도(ADR 0241) 두 쪽이 따로 드는 것으로 아이콘 경로 · 고르기 판 · 사진 위 단추 · 실패 글자를
남겼다. 따로 든 동안 실제로 갈라졌다 — 앱의 「⋯」 점이 웹보다 작았고, 사진 보기의 판에는 웹의 그림 · 손잡이가 없었으며, 웹 인연 지도도 경로를
베껴 들었다. 자료를 하나로 두고, 베끼는 꼴마다 시험을 하나씩 세운다(ADR 0274 과 같은 길).

## 받아들인 것

- 앱의 몇 그림이 웹 굵기로 가늘어지거나 커진다(「⋯」 점 · 사진 칸 × · + · 설정 줄 「›」 · 사진 보기 ×). 웹이 정한 값을 따랐다 — 작은 자리의 굵기를
  되돌리는 일(`stroke-*`)은 웹부터 정한다.
- 경로 사본 시험은 같은 글자만 본다 — 같은 그림을 다른 숫자 꼴(`M6 6 L18 18` · `M6 6l12 12`)로 적으면 못 본다. 그 꼴은 `react-native-svg` 표가 앱에서 막는다.
- 예외 표의 자리가 그림을 걷어도 시험은 붉히지 않는다 — 나란히 도는 PR(만세력 꺾쇠, G-165)이 main 을 붉히지 않게. 걷은 PR 이 줄도 지운다.
- 사진 위 단추는 웹의 흰 30% 테 · 그림자 · 흐림이 앱에 아직 없다. 인연 화면이라 G-172 가 든다 — 스낵바 · 인연 화면의 손 실패 글자와 함께.

## 남은 것 (G-184)

앱 단추 이름(`SecondaryButton` · `TextButton` → 웹 이름, 결제 레인 뒤 — 부르는 파일 28) · 홈 · 관문의 읽기 실패 블록(웹은 `FailureLine` 의
「다시 시도하기」 · 「다시 로그인」, 앱은 보조 단추이고 「다시 로그인」이 세션을 지운다) · 첫 화면 입구의 태극(웹 `TaijiMark` 은 획 1.5 · 밝은 반 흰 면,
앱은 `Icon` 의 획 1.8 · 비침).
