# 에이전트 문서는 매번 싣는 한 장과 닿을 때 여는 원본으로 나누고, 규약 문서의 총량에 천장을 둔다

> **운영자 지시 2026-11-21**(조율자가 옮김) — 하네스가 지나치다는 분석(아래 「까닭」)을 본 운영자가 단계별 안(전역 정리 · 필독 풀기 · 재기 ·
> 규약 줄이기 · 일하는 방식)에 「그래」라고 답하고, 「원칙을 세우고 워크트리로 effort 를 낮춰 문서를 나눠 축소시키고, 통합해서 다시 리뷰하라」고 했다.
>
> 이 결정이 대체하는 것 — ADR 0140 (일부: 손대기 전에 역할 문서를 끝까지 읽는다), ADR 0146 (일부: 라운드 끝마다 `/retro`),
> ADR 0147 (일부: 「먼저 읽는 것」의 기준)

## 정한 것

1. **매번 싣는 것은 한 장이다.** `AGENTS.md` 에는 멈출 선 다섯(운영 배포 · 실호출 · 운영 개인정보 · main 은 PR · force push)과 일을 여는 곳,
   새 기억의 자리만 든다. 멈출 선은 「규칙은 한 곳에만」의 예외로 짧게 싣고 원본을 가리킨다.
2. **손대기 전에는 역할 문서의 멈출 자리(「하지 않는 것 · 묻는 것」)와 「먼저 읽는 것」만 본다.** 「먼저 읽는 것」은 그 역할의 거의 모든 일에
   필요하고 기계가 잡지 못하는 것만(0 ~ 2줄과 선택 묶음) 들고, 나머지는 「닿을 때 여는 것」이다.
3. **규약의 줄은 「빼면 실수하나」로 남긴다.** 잣대의 원본은 `docs/agents/delegation/done.md` 「읽기량 예상치는 보고다」다. 모델이 원래 하는 일 ·
   기계가 이미 하는 일 · 저장소를 읽으면 보이는 것 · 되풀이 · 사연(날짜 · 번호 · 경위)은 지운다. 센 말은 멈출 선에만 쓴다.
4. **맡기기 · 브리프 · 회고 · 인계의 문턱을 낮춘다** — 원본은 `docs/agents/delegation/coordinator.md` 「조율자 세션」 · 「인계」와
   `docs/agents/delegation/notes.md` 「세션 기록」이다.
   - 1 ~ 3 파일짜리 일은 조율자가 그 역할로 직접 한다. 맡기는 것은 병렬 · 격리가 필요한 일이다.
   - 브리프는 역할 이름에 성공 기준 · 해도 되는 것과 안 되는 것 · 볼 곳 두세 개를 더한다. 「역할 문서를 다 읽어라」는 적지 않는다.
   - `/retro` 는 같은 자리에서 두 번 넘어졌을 때만 돈다. 놓는 차례는 기계 검사 → 효과 없는 지시 지우기 → 길잡이 한 줄(더하면 하나를 지운다)이다.
   - 인계는 `node scripts/session-status.mjs` 출력에 사람 칸을 더한 #770 댓글 하나다. 라운드 노트는 다른 데 없는 것이 있을 때만,
     ADR 은 되돌리기 비싼 결정에만 쓴다.
5. **규약 문서의 총량에 천장을 둔다.** `AGENTS.md` · `CLAUDE.md` · `CODING_STANDARDS.md` · `docs/start.md` · `docs/roles/` · `docs/agents/` ·
   `.claude/agents/` 의 합이 220,000 바이트 안이다(`scripts/code-rules.test.ts` 「규약 문서의 총량」). 제품 문서(PRD · 대장 · 런북 · ADR · 노트)는
   세지 않는다. 넘으면 더하기 전에 효과 없는 줄을 지운다. 천장을 올리려면 ADR 로 까닭을 적는다. 역할별 읽기량 예상치는 그대로 보고다(ADR 0177).
6. **주력 모델이 바뀌면 다시 잰다.** 최근 머지한 일 몇 개를 지금 문서와 줄인 문서로 돌려 첫 수정까지의 토큰 · CI 첫 통과 · 멈출 선 위반을
   견주고, 차이가 없는 줄을 지운다.

## 까닭

- **이 저장소에서 잰 값(2026-11-21).** 세션 기록에서 첫 수정까지 간 서브에이전트 88개는 시작할 때 약 3.7만 토큰, 첫 수정 때 약 11.8만 토큰이었다
  (중앙값). 그 사이에 읽은 것의 53%가 문서였다(문서 77KB, 코드 59KB). 역할별 손대기 전 읽기 예상치는 61 ~ 291KB 였다. 규약 문서는 9월 중순 약
  4KB 에서 325KB 로 늘었다. 일화를 덜어낸 다이어트 뒤에도 2주 만에 약 257KB 에서 다시 불었다 — 줄이기만 하고 막는 장치가 없었다.
- **Claude 5 세대의 지침과 실무.** Anthropic 은 Claude 5 세대에서 Claude Code 시스템 프롬프트를 80% 넘게 걷어도 코딩 평가 손실이 없었다고 했다.
  Claude Code 문서는 CLAUDE.md 를 200줄 아래로 두고, 강조해도 놓치는 줄은 훅으로 옮기라고 한다. pstack 은 Opus 5.5 에게 필요 없는 지시를
  문장을 넣은 판과 뺀 판의 A/B 로 확인해 지웠다. 실무자들(Hashimoto · Steinberger · Karpathy)의 매번 싣는 파일은 수십 ~ 백여 줄이고, 나머지는
  폴더별 파일 · 스킬로 닿을 때 연다.
- **이번 정리의 값.** 규약 문서 332,816 → 203,349 바이트. 역할별 손대기 전 읽기 예상치: coordinator 142,755 → 29,606 · ui 176,712 → 52,970 ·
  db 128,138 → 55,383 · feature 160,996 → 76,576 · ops 93,176 → 40,245 · reading 110,853 → 73,586 · docs 146,124 → 18,392 ·
  reviewer 290,811 → 194,112(관점 묶음이 제품 문서다). 다섯 갈래(입구 · 역할 / 조율 규약 / 환경 · 권한 / 코드 규칙 / 시험 지도)가 워크트리에서 나눠
  줄이고 조율자가 합쳐 검토했다.

## 받아들인 것

- 손대기 전에 안 읽게 된 문서에 기대던 실수가 다시 날 수 있다. 멈출 선은 settings · 브랜치 보호 · 시험이 기계로 막는다. 같은 자리에서 두 번
  넘어지면 그 줄을 「먼저 읽는 것」이나 검사로 되살린다.
- 천장은 쓸모 있는 줄을 더할 때도 다른 줄을 지우게 한다 — 그것이 목적이다. 천장을 피하려고 규약을 제품 문서 폴더로 옮기지 않는다.
- 이번 정리는 A/B 로 재지 않았다. 다음 확인은 실제 라운드에서 첫 수정까지의 토큰과 운영자 교정 수다.
