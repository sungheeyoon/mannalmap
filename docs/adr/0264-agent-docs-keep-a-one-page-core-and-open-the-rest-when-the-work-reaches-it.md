# 에이전트 문서는 매번 싣는 한 장과 닿을 때 여는 원본으로 나누고, 역할 문서는 지킬 것을 한 줄씩 직접 적는다

> 후속 결정(일부): ADR 0270 — 매 턴 싣는 크기는 `CLAUDE.md` 와 `AGENTS.md` 를 합쳐 4,000 바이트로 잰다(「정한 것」 5)

> **운영자 지시 2026-11-21**(조율자가 옮김) — 하네스가 지나치다는 분석(아래 「까닭」)을 본 운영자가 단계별 안(전역 정리 · 필독 풀기 · 재기 ·
> 규약 줄이기 · 일하는 방식)에 「그래」라고 답하고, 「원칙을 세우고 워크트리로 effort 를 낮춰 문서를 나눠 축소시키고, 통합해서 다시 리뷰하라」고 했다.
> 통합본을 보고는 「읽기량 상한이 필요한가부터 — 다른 저장소 · 전문가를 분석했잖아」, 「그런 기준으로 다시 봐라. 근본부터 『뭐는 바꾸지 마』 같은
> 규칙부터가 잘못돼 있을 수 있다」고 했다.
>
> 이 결정이 대체하는 것 — ADR 0140 (일부: 손대기 전에 역할 문서를 끝까지 읽는다), ADR 0145 (일부: 역할 문서는 규칙을 다시 말하지 않는다 ·
> 칸 넷 · 읽기량이 세는 칸), ADR 0146 (일부: 라운드 끝마다 `/retro`), ADR 0147 (일부: 「먼저 읽는 것」의 기준)

## 정한 것

1. **매번 싣는 것은 한 장이다.** `AGENTS.md` 에는 멈출 선 다섯(운영 배포 · 실호출 · 운영 개인정보 · main 은 PR · force push)과 일을 여는 곳,
   새 기억의 자리만 든다. 멈출 선은 짧게 싣고 원본을 가리킨다.
2. **역할 문서는 칸 셋이다 — 「지킬 것」 · 「먼저 읽는 것」 · 「끝날 때 고치는 것」, 그리고 맨 뒤 「닿을 때 여는 것」.**
   - 손대기 전에는 「지킬 것」과 「먼저 읽는 것」만 본다. 나머지는 일이 그 자리에 닿을 때 연다.
   - 「지킬 것」은 그 역할의 규칙을 한 줄씩 직접 적고 줄마다 출처 링크를 단다 — 원본까지 가지 않아도 규칙이 보여야 한다. 원본의 규칙을 바꾸는
     PR 이 그 줄도 같이 고친다. 옛 「이 저장소의 방식」(원본 링크만)과 「하지 않는 것 · 묻는 것」을 이 칸 하나로 합쳤다.
   - 「먼저 읽는 것」은 그 역할의 거의 모든 일에 필요하고 기계가 잡지 못하는 것만(0 ~ 2줄과 선택 묶음) 든다.
   - 읽기량 예상치(`npm run read-budget`)는 「먼저 읽는 것」만 센다. 그대로 보고이고 CI 를 붉히지 않는다(ADR 0177).
3. **규약의 줄은 「빼면 실수하나」로 남긴다.** 잣대의 원본은 `docs/agents/delegation/done.md` 「읽기량 예상치는 보고다」다. 모델이 원래 하는 일 ·
   기계가 이미 하는 일 · 저장소를 읽으면 보이는 것 · 되풀이 · 사연(날짜 · 번호 · 경위 — 제목에서도)은 지운다. 센 말은 멈출 선에만 쓴다.
   **시험도 같은 잣대로 본다** — 링크 · 경계 · 비밀처럼 실수를 막는 검사는 두고, 문서의 꼴만 잠그는 검사는 고치거나 지운다. 시험이 지금 틀을
   지킨다는 것은 그 틀이 맞다는 근거가 아니다.
4. **맡기기 · 브리프 · 회고 · 인계의 문턱을 낮춘다** — 원본은 `docs/agents/delegation/coordinator.md` 「조율자 세션」 · 「인계」와
   `docs/agents/delegation/notes.md` 「세션 기록」이다.
   - 1 ~ 3 파일짜리 일은 조율자가 그 역할로 직접 한다. 맡기는 것은 병렬 · 격리가 필요한 일이다.
   - 브리프는 역할 이름에 성공 기준 · 해도 되는 것과 안 되는 것 · 볼 곳 두세 개를 더한다. 「역할 문서를 다 읽어라」는 적지 않는다.
   - `/retro` 는 같은 자리에서 두 번 넘어졌을 때만 돈다. 놓는 차례는 기계 검사 → 효과 없는 지시 지우기 → 길잡이 한 줄(더하면 하나를 지운다)이다.
   - 인계는 `node scripts/session-status.mjs` 출력에 사람 칸을 더한 #770 댓글 하나다. 라운드 노트는 다른 데 없는 것이 있을 때만,
     ADR 은 되돌리기 비싼 결정에만 쓴다.
5. **문서의 크기에 천장을 두지 않는다.** 다시 불어나는 것은 원인 — 회고가 줄을 더하던 문턱(4) — 과 아래 6 으로 막는다. 매번 싣는 자리의 크기만
   전처럼 잰다 — 역할 문서의 한 화면(8,000 바이트)과 `CLAUDE.md`(600 바이트).
6. **주력 모델이 바뀌면 다시 잰다.** 최근 머지한 일 몇 개를 지금 문서와 줄인 문서로 돌려 첫 수정까지의 토큰 · CI 첫 통과 · 멈출 선 위반을
   견주고, 차이가 없는 줄을 지운다.

## 까닭

- **이 저장소에서 잰 값(2026-11-21).** 세션 기록에서 첫 수정까지 간 서브에이전트 88개는 시작할 때 약 3.7만 토큰, 첫 수정 때 약 11.8만 토큰이었다
  (중앙값). 그 사이에 읽은 것의 53% 가 문서였다(문서 77KB, 코드 59KB). 역할별 손대기 전 읽기 예상치는 61 ~ 291KB 였다. 규약 문서는 9월 중순 약
  4KB 에서 325KB 로 늘었고, 일화를 덜어낸 다이어트 뒤에도 2주 만에 약 257KB 에서 다시 불었다.
- **Claude 5 세대의 지침과 실무.** Anthropic 은 Claude 5 세대에서 Claude Code 시스템 프롬프트를 80% 넘게 걷어도 코딩 평가 손실이 없었다고 했다.
  Claude Code 문서는 CLAUDE.md 를 200줄 아래로 두고, 강조해도 놓치는 줄은 훅으로 옮기라고 한다. pstack 은 Opus 5.5 에게 필요 없는 지시를
  문장을 넣은 판과 뺀 판의 A/B 로 확인해 지웠다. 실무자들의 매번 싣는 파일은 수십 ~ 백여 줄이고 규칙을 그 자리에 직접 적는다
  (Ghostty 「Never create a PR」, Steinberger 「This file: hard rules only」).
- **원본만 가리키는 역할 문서는 규칙을 숨겼다.** 「이 저장소의 방식」은 링크만 들어서 규칙을 알려면 원본을 열어야 했고, 읽기량은 그 원본까지
  손대기 전 읽기로 셌다. 닿을 때 여는 문서는 열리지 않을 수 있다 — 바깥 평가에서 에이전트는 부를 수 있는 스킬의 56% 를 부르지 않았다(Vercel).
  그래서 규칙 한 줄은 「지킬 것」에 직접 두고, 원본은 자세한 것을 볼 때 연다.
- **천장은 이미 해 보고 걷었다.** ADR 0147 이 읽기량 천장을 걸었고 ADR 0177 이 6일 뒤 걷었다 — 근거 없이 그날 값에 여유를 더한 수였고, 숫자에
  맞추려 문서를 깎고 옮겼으며, 남의 파일이 자라면 상관없는 PR 이 붉었다. 바깥에서도 도구가 건 크기 상한(Codex 의 지시 파일 한도 등)에 걸린
  저장소는 글을 지우지 않고 참고 파일로 옮겼다. 조사한 실무자 가운데 스스로 크기 천장을 거는 곳은 없었다 — 주기적으로 지우고, 넣은 판과 뺀 판을
  견주고, 같은 데서 되풀이해 넘어질 때만 다시 넣는다.
- **이번 정리의 값.** 규약 문서 332,816 → 202,919 바이트. 역할별 손대기 전 읽기 예상치: coordinator 142,755 → 11,365 · ui 176,712 → 29,110 ·
  db 128,138 → 17,784 · feature 160,996 → 48,136 · ops 93,176 → 31,510 · reading 110,853 → 45,305 · docs 146,124 → 5,956 ·
  reviewer 290,811 → 179,683(관점 묶음이 제품 문서다). 다섯 갈래(입구 · 역할 / 조율 규약 / 환경 · 권한 / 코드 규칙 / 시험 지도)가 워크트리에서
  나눠 줄이고 조율자가 합쳐 검토했다.

## 받아들인 것

- 손대기 전에 안 읽게 된 문서에 기대던 실수가 다시 날 수 있다. 멈출 선은 settings · 브랜치 보호 · 시험이 기계로 막는다. 같은 자리에서 두 번
  넘어지면 그 줄을 「지킬 것」 · 「먼저 읽는 것」이나 검사로 되살린다.
- 「지킬 것」의 줄은 원본과 둘이 된다 — 원본을 바꾸는 PR 이 함께 고치지 않으면 어긋난다. 줄마다 단 출처 링크가 그 PR 이 찾을 자리다.
- 역할 문서의 틀을 잠그던 시험(칸 넷 · 「이 저장소의 방식」의 줄 꼴)을 바꿨다. 남은 시험은 칸의 차례 · 한 화면 · 「지킬 것」의 출처 링크 ·
  가리킨 파일 · 절 · 앵커가 있는지다.
- 이번 정리는 A/B 로 재지 않았다. 다음 확인은 실제 라운드에서 첫 수정까지의 토큰과 운영자 교정 수다.
