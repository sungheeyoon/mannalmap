# 문구 대장의 절 번호는 빈틈을 재지 않고, 「확인 전」 줄의 가까운 사례와 머지된 ADR 의 추기는 시험이 좁게 잰다

> **운영자 위임 2026-11-19**(「권고대로 해주라」 — 조율자가 권고를 브리프로 전함) — 문구 대장 무리 파일 안의 절 번호 빈틈 시험을 걷는다.
> 함께 #1177 독립 검토가 짚은 대장 「확인 전」 시험의 느슨한 판정 둘과 머리 줄 거르기를 조이고, ADR 0240 「머지된 ADR 에 추기를 달지
> 않는다」를 시험으로 잠근다. 결정 점검표의 「검증 · 배포의 문턱」(무엇을 시험이 확인하나)에 걸린다.
>
> 이 결정이 대체하는 것 — ADR 0169 「정한 것」의 「한 파일 안에서 01 부터 끊기지 않는다」(이름 꼴과 무리 이름은 그대로 선다).

## 잰 것 (2026-11-19, main `eed3ec7c`)

- **대장 절 번호의 빈틈 시험은 ADR 번호의 빈틈 시험(ADR 0254 가 걷음)과 같은 꼴이었다.** `scripts/code-rules.test.ts` 「새 절의 번호는 …
  한 파일 안에서 01 부터 끊기지 않는다」는 나란히 도는 PR 이 같은 무리의 번호를 나눠 받으면(`home-17` · `home-18`) 뒤 번호 PR 이 앞 PR 이
  들기 전까지 붉었다. `docs/agents/delegation/parallel.md` 「그 밖의 공유 번호」 줄은 그 붉음을 「받아들인다」고 적고 있었다 — 결함을
  가리키지 않는 붉음이라 매번 로그를 열어 그것 하나뿐인지 봐야 했다.
- **그 시험만 잡던 잘못은 같은 번호 둘뿐이었다** — 「1 2 2」는 「1 2 3」이 아니라 붉었다. 빈틈 단언을 걷으면 그 길이 열리므로 겹침 단언을
  따로 세웠다. 열린 PR 끼리의 겹침은 gate 의 공유 번호 검사(`scripts/shared-numbers.mjs`, ADR 0238)가 그대로 잰다.
- **「확인 전」 시험의 가까운 사례 판정이 반증할 수 없는 자리를 받았다**(#1177 독립 검토). 「실사례 없음」 줄의 출처 칸이 ① 제 절 번호
  (`public-03` 줄의 `public-03`)를 들어도 「있는 절」이라 지났고 ② 백틱 속 대문자 낱말이면 제품 코드 어디에든 그 글자가 있기만 하면
  지났다 — `URL` 처럼 상수가 아닌 낱말도 「상수」였다. 둘 다 사례를 안 들어도 초록이 되는 길이다(ADR 0079). 조인 판정을 지금 대장에 대 보니
  새로 걸리는 줄은 **0** 이었다 — `NEAREST_MISSING_STILL_THERE` 에 더한 줄이 없다.
- **같은 시험의 머리 줄 거르기 `^\| (---|자리) ` 는 자리 칸이 「자리」로 시작하는 진짜 줄도 건너뛰었다.** 지금은 그런 줄이 없다(대장 파일
  전부에서 구분선 바로 위가 아닌 `| 자리…` 줄 0, 같은 날 `awk`). 건너뛴 줄은 출처도 안 재고 셈에도 안 든다.
- **라운드 노트의 「→ 놓은 자리」 판정은 아무 「…」 나 절로 받았다**(같은 검토). 「다음에 보기」처럼 따옴표만 친 말도 자리였다.
- **머지된 ADR 에 추기가 계속 붙었다.** ADR 0240(2026-11-08)이 추기를 막은 뒤에도 16 개가 더 붙었다(2026-11-19 감사 — `docs/agents/domain.md`
  「Writing an ADR」). 그 규칙을 재는 시험이 없었다. 2026-11-19 의 추기 머리(`## 추기`)는 ADR 마흔넷에 92 개다(ADR 0109 하나에 26).

## 정한 것

1. **문구 대장의 절 번호는 빈틈을 재지 않는다.** 「새 절의 번호는 그 파일 이름을 달고(머리는 `all`) 한 파일 안에서 같은 번호가 둘이
   아니다」 — 남의 이름 · `00` · 같은 번호 둘만 붉다. 뒤 번호가 먼저 들어도 붉지 않고, 빈 번호는 앞 PR 이 들면 찬다. 대장 전체 번호
   01–47 의 시험(얼어 있다)과 색인 「절」 칸이 파일의 절을 차례대로 다 드는 시험은 그대로다.
2. **「확인 전」 줄의 가까운 사례는 좁게 받는다.** 대장 절은 **제 절이 아닌** 있는 절이고, 상수는 제품 코드가 `const NAME` · `export const NAME`
   으로 **정의한** 이름이다. 링크 + 날짜, 옛 「대장 NN」 꼴은 그대로다. 이 조임으로 새로 걸리는 줄이 있으면 조임 전에 있던 줄만
   `NEAREST_MISSING_STILL_THERE` 에 더한다 — 이번에는 0 줄.
3. **표의 머리 줄은 구분선과 그 바로 위 줄만 거른다** — 첫 칸의 글자로 거르지 않는다.
4. **노트의 「→ 「절」」 은 저장소 문서에 실제로 있는 절 머리의 글자일 때만 자리다.** 파일 경로 · `G-nn` · `#NNN` 은 그대로다.
5. **머지된 ADR 의 추기 머리 수를 지문으로 잠근다.** ADR 마다 `## 추기` · `### 추기` 머리 수를 시험의 `ADDENDA_STILL_THERE` 가 든다 —
   늘면 붉고, 줄면(사실 정정으로 옮기는 등) 목록도 줄인다. 0240 뒤에 붙은 것도 지금 수 그대로 든다(이미 있는 추기는 걷지 않는다 —
   ADR 0240 「정한 것」 2). 사실 정정 `## 정정 …` 은 세지 않는다.

## 치르는 값

- 대장 무리 파일에 번호를 잘못 쳐서(`home-17` 을 `home-71` 로) 생긴 빈틈은 아무도 붉히지 않는다. 절 번호는 이름표라 가리키는 것이 틀리지
  않고, gate 가 내주는 다음 번호는 끝 번호 위다(ADR 0238).
- 절 머리 판정은 「그 글자를 담은 머리가 어딘가 있다」이지 「그 파일의 그 절」이 아니다 — 짧은 낱말(「확인 전」)은 거의 늘 지난다. 경로를
  함께 적는 꼴은 `docs/agents/delegation/notes.md` 「세션 기록」이 이미 권한다.
- 새 ADR 을 처음부터 `## 추기` 머리로 쓰면 붉다 — 새 ADR 에는 추기가 없으니 받아들인다.

## 버린 것

- **빈틈 시험을 main 에서만 돌린다** — ADR 0254 「버린 것」과 같다. 엇갈린 머지마다 main 이 붉다.
- **추기 수를 ADR 0240 뒤에 붙은 것만 센다** — 머지 날을 git 으로 재야 해 시험이 git 이력에 묶인다. 지금 수 그대로가 같은 것을 잰다.
- **가까운 사례의 상수를 쓰임까지 잰다**(그 상수가 그 화면 글자를 드는가) — 대장 줄과 코드 줄을 잇는 일이라 화면 문구 대조의 몫이다.

`→ 놓은 자리`」와 그 판정 시험, 「머지된 ADR 에 추기 머리가 늘지 않는다」와 그 판정 시험. 일부러 어긴 꼴은 이 결정의 PR 본문에 적었다.
