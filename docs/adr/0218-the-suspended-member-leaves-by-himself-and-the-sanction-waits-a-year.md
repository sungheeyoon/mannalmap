> 계정을 같은 사람으로, 제재 기록 1년.

## 잰 것 (2026-11-03, main `4b5db9c1`)

- `request_account_deletion` 은 `status <> 'active'` 를 「이용이 정지된 계정입니다.」(`42501`)로 거절한다 — 정지된 사람은 화면에서 못 지운다(ADR 0190 의 8). 웹 · 앱 설정의 「탈퇴하기」도 이용 중일 때만 섰다.
- **가입을 안 마친 계정**(로그인해서 `app_user` 행은 있고 `signed_up_at` 이 빈 이용 중 계정)은 DB 문은 지나지만 **화면에 길이 없었다** — 관문이 가입 화면 하나로 보내고, 그 화면에는 「다른 계정으로 로그인하기」뿐이다.
- 정지된 사람의 탈퇴를 막아 두던 까닭은 「정지를 피하는 길이 되지 않는지 사람이 본다」였다(ADR 0190 「버린 것」). 지금 탈퇴하고 같은 구글 계정으로 다시 들어오면 새 계정이고 정지가 없다.
- 본인확인의 CI 는 저장하지 않는다(ADR 0214 「정한 것」 2 · 「잠그지 않은 것」). 같은 사람을 알아볼 값은 로그인 계정뿐이다 — `auth.users.email` 과 `auth.identities` 의 제공자 · 계정 번호.

정지 중 탈퇴를 **막는다고 적은 곳은 없다.** 재가입 제한의 식별값은 사례마다 그 서비스의 가입 수단이다(CI · 전화번호 · 「신상정보」). 정지가
새 계정에 **이어진다**는 모양은 당근의 안내로 알려져 있으나 1차 원문을 못 찾았다(블로그 요약, [예](https://jab-guyver.co.kr/3195), 확인 2026-11-03) —
그래서 근거로 세지 않고, 이어지는 모양은 「새 문구 없이 이미 정한 정지 화면을 쓴다」는 까닭으로 골랐다(아래 4).

## 정한 것

1. **정지된 계정도 스스로 탈퇴를 신청한다.** `request_account_deletion` 이 `active` 와 `suspended` 를 받는다. 하는 일은 이용 중과 같다 — 탈퇴 대기 시각 · 노출 끄기 · 답을 기다리던 요청 정리, 처분은 크론(`account-disposal`). 이력은 이용자 스스로의 갈래(`deletion_request`)이고 알리지 않는다. 정지에서 왔으므로 운영자가 거두면 정지로 돌아간다(ADR 0190 의 6 그대로). 문의로 받아 운영자가 옮기는 길(ADR 0190 의 5)도 남는다 — 앱에 못 들어오는 사람의 길이다(맞나만나의 메일 길).
2. **화면 — 같은 말 · 같은 창을 더 많은 자리에.** 설정 맨 아래 「탈퇴하기」가 정지된 사람에게도 선다(웹 · 앱, `mayRequestDeletion`). 가입 화면에는 「다른 계정으로 로그인하기」 아래에 「탈퇴하기」가 선다 — 가입을 안 마친 사람에게 설정이 닫혀 있어서다. 확인 창의 글은 설정의 것 그대로다. 가입을 안 마친 채 탈퇴 대기 · 정지가 된 계정에는 가입 폼 대신 그 상태의 안내(`AccountNotice`)가 선다 — 폼을 세우면 DB 가 거절할 누름을 권하게 된다.
3. **제재 기록** `retention.sanction` — **정지된 채로 지워지는 계정**(지금 정지, 또는 정지에서 온 탈퇴 대기)만. 든다: 로그인 이메일(소문자) · 로그인 식별값(`provider:provider_id`) · 정지 갈래 · 신고로 정지했으면 그 신고 id · 정지한 운영자 · 정지 시각 · 처분일. 안 든다: 계정 id · 닉네임 · 운영자 메모 · 출생 정보 · 대화. `auth.users` 의 `before delete` 가 옮긴다(ADR 0098 의 자리 — 크론 처분이든 `forget_user` 든 같다). `retention` 스키마라 앱 역할은 못 읽는다.
4. **정지가 이어진다.** 새 계정이 **가입을 마치는 순간**(`signed_up_at` 이 처음 채워질 때) 살아 있는 기록과 이메일 또는 로그인 식별값이 겹치면 같은 갈래 · 같은 신고 id · 같은 운영자로 정지된다. 정지 화면 · 소명 경로(대장 `all-03`) · 스스로 탈퇴는 보통 정지와 같다 — **새 화면 문구가 없다.** 운영자에게 한 줄 알린다(`sanction-carried:`). 가입을 마치기 전에는 정지하지 않는다 — 그동안 그 사람은 아무것도 못 하고 가입 화면의 「탈퇴하기」로 떠날 수 있다.
5. **1년** — 처분일부터. 미러의 1년을 따랐다(조율자 권고). 그 사이 다시 정지된 채 떠나면 새 기록이 그날부터 1년이다. 크론 `sanction-retention-purge`(매일 05:17 UTC)가 지난 줄을 지운다.
6. **한 사람은 지금 로그인 계정이다.** 다른 구글 · 애플 계정으로 들어오면 못 막는다. 본인확인의 CI 를 저장하게 되면(G-20 · ADR 0214) 그 PR 이 이 기록에 CI HMAC 을 더하고 같은 1년을 쓴다 — 지금 빈 칸을 지어 두지 않는다(#946 「그 답 전에는 표만 지어 두지 않는다」).

## 실패했을 때

| 자리 | 답 |
| --- | --- |
| 지울 때 기록 쓰기가 실패한다 | `auth.users` 의 지우기가 함께 되감긴다 — 처분 크론이 실패로 적고 다시 집는다(ADR 0094 덧의 모양) |
| 이메일도 로그인 식별값도 없다 | 기록을 안 남긴다 — 맞춰 볼 값이 없다 |
| 가입을 마칠 때 정지를 잇는 쓰기가 실패한다 | 가입째 되감긴다 — 가입이 안 끝나고 다시 누를 수 있다 |
| 이용자가 설정 값을 실어 탈퇴를 운영자의 일로 적으려 한다 | `request_account_deletion` 이 값을 먼저 비운다 — pgTAP 이 잰다 |

## 고르지 않은 것

- **정지된 사람은 계속 문의로만** — 스토어 요건에 어긋난다. Apple 5.1.1(v) 는 앱 안에서 삭제를 시작할 수 있어야 한다고 적는다.
- **가입을 아예 거절한다**(맞나만나 모양) — 거절 문장이 새 화면 문구다. 이미 확정된 정지 화면을 쓰면 소명 경로까지 따라온다.
- **로그인하는 순간 정지한다** — 가입 미완 상태와 정지가 겹친 계정은 관문 · 화면이 다루지 않던 자리다. 가입을 마칠 때 이으면 정지된 사람은 늘 가입을 마친 사람이다.
- **정지가 풀렸거나 경고만 받은 계정도 남긴다** — 이어 받을 정지가 없다. 경고의 셈은 지금 계정의 것이다(G-110).
- **6개월(글램) · 7일(정오)** — 조율자 권고는 1년이고 #932 조사가 6개월을 짧은 대안으로 들었다. 운영자가 바꾸면 `retention.sanction_period()` 하나다.
- **기록을 HMAC 으로** — 비밀키 · 교체 절차가 드는 일이고(ADR 0101), 같은 규율의 신고 기록(ADR 0098)도 이메일을 그대로 6개월 둔다. 키가 서는 날(CI) 함께 본다.

## 남은 것

- **처리방침의 보존 줄** — 항목(로그인 이메일 · 로그인 식별값 · 정지 사유 · 일시) · 목적(이용 정지 회피 재가입 방지) · 기간(처분일부터 1년)을 #938 에 넘겼다. ADR 0098 의 「알리기 전에 남기지 않는다」대로 이 마이그레이션의 `db push` 는 #938 의 처리방침 줄이 게시되는 판과 같은 판이거나 그 뒤다(조율자 2026-11-03). 배포 순서는 `db push` → 웹 · 앱이다 — 앞서면 정지된 사람의 「탈퇴하기」가 옛 DB 에 거절된다.
- **약관 제8조④** 의 재가입 제한 기간 빈칸(「변호사 검토 필요」)도 #938 이 이 1년으로 맞춘다. 약관의 문장은 「위반으로 해지」이고 여기는 「정지 중 탈퇴」다 — 문장을 고를 때 함께 본다.
- 동의 철회 두 문의 정지 거절(#384)은 이 결정 밖이다.
