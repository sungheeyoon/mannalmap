# 앱의 누름은 손가락에 답하고, 적는 칸은 초점 고리가 서며, 고를 수 있는 문장도 어절을 지키되 값은 깨끗이 복사된다

> **2026-11-27 앱 전수 점검(에뮬레이터, 조율자 라운드)의 「뜻을 안 바꾸는 다듬기」 열 건을 고치며 정했다**(레인 J). 글자 · 흐름은 그대로다 —
> 바뀐 모양은 PR 의 전후 그림이다(운영자 확인 전).
>
> 이 결정이 대체하는 것 — ADR 0250 (일부: 「정한 것」 4 의 「긁어 복사하는 글자(`selectable`)는 `WordText` 가 그대로 둔다」 — 값을 품은 문장은
> `sentence` 로 어절을 묶는다. 통째로 값인 글자는 그대로다)

## 정한 것

1. **앱 화면의 누름은 `mobile/src/ui/press.tsx` 의 `Press` 로 선다** — 누르는 동안 웹의 `active:` 와 같은 반응이 선다. 갈래는 넷이고 웹의 같은 자리를
   따른다 — `shrink`(단추 · 칩, 웹 `PRESS` 의 0.97 · 앱 `Button` 과 같은 값) · `icon`(아이콘 · 하단 탭, 웹 `active:scale-95`) · `fade`(글자만 있는
   누름, 웹 `BUTTON_TERTIARY` 의 `active:opacity-55`) · `row`(목록의 줄, 웹 `active:bg-surface-sunken`). 안드로이드 물결(`android_ripple`)은 쓰지
   않는다 — 공용 단추 · 면과 같이 iOS · 웹과 한 반응이다. 누르면 바탕이 서는 자리라 모서리를 지킨다(`KEEP_VIEW`, ADR 0241 의 둥근 자리).
   카드 전체가 누를 자리면 면 부품의 `onPress`(누르면 0.85)를 쓴다.
   - 옮긴 자리 — 머리의 로고 · 풀이권 · 종 · 톱니, 하단 탭, 도움말의 묶음 칩 · 물음 줄 · 링크, 궁합 고르기의 사람 칸 · 목록 줄 · 사이 칩, 저장한 사람
     카드의 두 단추, 사람 화면의 「만세력 자세히」 · 사주풀이 카드 · 궁합 줄, 홈 묶음 머리의 「모두 보기 · 관리」 · 「더보기」, 관계 지도의 카드 단추 ·
     「사람 추가」, 소식의 줄, 그리고 공용 폼 부품(`ui/parts.tsx`)의 고르는 칸 · 펼치는 칸과 그 목록 · 확인 상자 줄 · iOS 키보드의 「완료」.
   - `scripts/mobile-press.test.ts` 가 잰다 — 화면 파일이 `react-native` 의 누름(`Pressable` · `Touchable*`)을 바로 들여오면 붉다. 아직 옮기지 않은
     파일은 그 시험의 표가 까닭과 함께 든다(인연 · 채팅 — 닫혀 있다 · 제 눌림 꼴을 이미 든 곳 · 누름이 움직임인 곳 · 열린 화면의 남은 자리). 표는
     줄기만 한다.
2. **적는 칸(`Field` · `DigitField`)에 초점이 오면 테가 크림 먹색이 되고 둘레에 3 의 옅은 고리(`accentSoft`)가 선다** — 웹 출생 정보 폼의 칸
   (`app/birth-form.module.css` 「초점 · 오류 — 모든 칸이 같은 고리」)과 같다. 누른 뒤 걸린 칸은 붉은 테 2 가 이기고 초점 고리는 옅은 붉은색이다.
   웹 `FIELD`(가입 · 프로필의 칸 — 먹색 테 · 2 고리)와는 테 색 · 고리 두께가 조금 다르다 — 앱의 칸은 두 부품 한 벌이라 출생 정보 폼 쪽을 따랐다.
3. **고를 수 있는 글자(`selectable`)도 값을 품은 문장이면 어절을 지킨다** — `WordText` 에 `sentence` 를 함께 준다(고객센터의 문의 줄 · 결제 내역의
   주문 번호 줄). 금지 글자는 한글 곁에만 서므로 한글 없는 값(메일 주소 · 주문 번호 · 금액의 숫자)은 그대로다 — 값만 골라 복사하면 깨끗하다
   (`src/lib/brand/keep-words.test.ts`). 통째로 값인 줄(약관 및 정책의 사업자 정보 — 상호 · 주소 · 번호)은 ADR 0250 그대로 끼우지 않는다 — 한글
   값을 통째로 복사해 붙여도 보이지 않는 글자가 섞이지 않게. 긴 주소는 글자 단위로 꺾일 수 있다.
4. **줄에 선 제목 글은 글자에 꼭 맞는 폭을 받지 않는다** — 안드로이드는 꼭 맞는 폭을 받은 글의 끝 어절을 다음 줄로 밀어 잘랐다(홈 묶음 머리
   「저장한 사람」→「저장한」, 사주표의 월지 「정관」→「정」). 홈 묶음 머리는 개수를 제목 글자 안에 두고(웹 `h2` 안 `span` 과 같다) 제목이 줄의 남은
   폭을 다 쓴다. 관계 지도 · 프로필 사진의 머리는 제목과 수가 줄을 반씩 나눈다.
5. **화면 통째 실패는 웹의 같은 자리처럼 실패 줄(`FailureLine`) 하나다** — 앱 껍데기의 관문 실패 · 보관함 · 풀이 화면(`ReadFailure`)이 붉은 줄과
   「다시 시도하기」로 선다(가운데 작은 글씨와 보조 단추 · 분홍 판이던 것). 소식의 못 읽은 줄 · 읽음 표시 실패도 그 줄이다. 설정 · 사람 화면 · 저장한
   사람은 이미 그 꼴이었다. 홈 탭 본문의 실패 블록(「다시 로그인」이 세션을 지운다)은 G-184 그대로다.
6. **관계 지도의 오행 번짐은 지도 틀 밖까지 번지고 판의 가장자리에서만 잘린다**(웹 `Zones`) — 안드로이드의 Svg 는 `overflow: 'visible'` 이어도 제
   틀 밖을 자르므로 번짐만 사방 16(지도 폭의 %) 넓은 Svg 에 그린다.

## 까닭

점검이 열린 화면에서 웹과 갈린 다듬기 열 건을 짚었다 — 눌러도 아무것도 안 바뀌는 누름(맨 `Pressable` 119 곳 가운데 눌림 꼴은 열한 파일), 초점이
안 보이는 칸, 「주세 / 요.」처럼 끊기는 고를 수 있는 문장, 잘리는 구역 제목 · 네모로 잘리는 번짐, 네 갈래의 화면 실패 꼴. 하나하나는 작지만 같은
꼴이 화면마다 다시 서므로 부품 · 시험으로 잠근다(ADR 0241 · 0274 과 같은 길).

## 받아들인 것

- 누름 시험은 들여오기만 본다 — 부품 안(`mobile/src/ui/`)의 누름과 면 부품의 `onPress` 는 제 반응을 든다고 보고 재지 않는다.
- 표의 「열린 화면의 남은 자리」(열여덟 파일)는 아직 눌러도 안 바뀐다. 옮기는 PR 이 줄을 지운다.
- 값을 품은 문장을 통째로 복사하면 한글 어절 안의 금지 글자가 함께 간다 — 붙여 넣는 자리가 문의 메일이라 받아들인다.
- 홈 묶음 머리의 읽는 이름이 「저장한 사람 2/10명」 하나가 됐다(전에는 제목과 개수가 따로 읽혔다) — 웹 `h2` 와 같다.
- 실패 줄의 「다시 로그인」 — 소식의 못 읽은 줄에 다시 로그인이 답인 문장이 들면 「다시 시도하기」 대신 「다시 로그인」이 선다(공용 실패 줄의 규칙,
  ADR 0164 · 0280).
- iOS · 실기기 · TalkBack 으로는 재지 않았다 — 안드로이드 에뮬레이터(Expo Go · 가짜 서버)와 웹 번들로 쟀다.
