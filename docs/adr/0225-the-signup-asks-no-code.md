# 가입은 테스트 코드를 묻지 않는다 — 로그인한 누구나 닉네임 · 안내 확인으로 가입을 마친다

> 후속 결정(일부): ADR 0234 — 추기 2026-11-06 의 글 · 코드를 `notice-v17` 이 옮기고, 일정 줄의 종료일이 서비스를 끝내지 않는다

이 결정이 대체하는 것 — ADR 0042(「문을 여는 것은 코드다」 대목과 코드 칸) · ADR 0066(코드의 창과 정원) · ADR 0124(틀린 코드의 셈) · ADR 0101(일부 — 추기: 본인확인이 가입의 문이라는 대목과 「한 사람에게 평생 한 번」)

> 조율자의 맡김(2026-11-05): 가입의 테스트 코드(「SAJU1001」 꼴)를 걷어, 코드 없이 누구나 가입하고 쓰게 한다. 그 밖의 가입 조건은
> 그대로 둔다. 결정 점검표의 **「누가 무엇을 할 수 있는가」**(가입의 문)와 **「비용」**(무료 풀이권이 계정마다 나간다)에 걸린다 —
> 마이그레이션이 든 PR 이라 운영자의 `db push` 승인 전에 머지하지 않는다.

## 정한 것

1. **가입은 코드를 묻지 않는다.** 웹 `/signup` · 앱 가입 화면에서 코드 칸 · 코드 설명 · 코드의 거절 줄을 걷었다. 처음 가입하는 사람의
   폼은 닉네임(중복 확인) · 가입 안내 확인 · 선택 항목 둘이다. 단추의 글자는 그대로다(처음 가입은 「가입하고 시작하기」, 다시 확인은
   「확인하고 계속하기」).
2. **남는 문은 그대로다** — 로그인, 안내 판본과 본 일정 줄(바뀌면 거절), 선택 항목의 답, 베타 종료(`beta_is_over`), 일정 · 연락처가
   없으면 가입 없음(ADR 0024), 정지 · 탈퇴 대기 계정의 거절(ADR 0218), 닉네임 규칙(2~8자 · 유일), 가입 닫기(`signup_pause`, ADR 0105).
3. **DB 문은 서명을 그대로 두고 `p_code` 를 읽지 않는다**(`20270111090000`). 옛 앱 빌드는 아직 코드를 보낸다 — 서명을 바꾸면 그
   빌드의 가입이 함수를 못 찾아 선다. 새 웹 · 앱은 `null` 을 보낸다. 인자를 걷는 좁히기는 옛 빌드가 다 사라진 뒤의 일이다(ADR 0071).
   틀린 코드가 없으므로 이 문은 가입을 마치면 `true` 이고 나머지는 던진다 — `false` 갈래가 없어졌다.
4. **가입이 닫힌 때의 문장이 코드를 말하지 않는다** — 「지금은 신규 가입을 잠시 멈췄어요. 나중에 다시 시도해 주세요.」(대장 public-08,
   확인 전). 전에는 「사용할 수 없는 코드예요」를 빌려 썼다. 닫힘은 이름 검사보다 먼저 본다 — 닫힌 동안 닉네임을 고쳐 다시 누르게
   하지 않는다. 이미 가입한 사람의 안내 재확인은 닫힌 동안에도 된다(그대로).
5. **틀린 시도를 세던 표와 한도 함수를 걷는다** — `signup_code_miss` · `signup_code_miss_limit()` · `signup_code_miss_window()`. 계정마다
   한 시간 창의 줄이라 이력이 아니고, 부르던 곳이 가입 문 하나였다.
6. **`signup_code` 표와 `app_user.signup_code` 칸은 기록으로 남긴다.** 운영 베타의 테스터가 어느 코드로 들어왔는지가 그 기록이다.
   개인정보가 아니고(계정의 칸은 계정과 함께 지워진다), 표는 지금처럼 아무 역할에도 안 열려 있다. 새 가입자의 칸은 비어 있다.
   코드를 내는 운영 SQL(`docs/ops/runbook/signup.md` 「초대」)은 걷었다 — 화면(`/ops`)에는 코드를 내거나 세는 자리가 없었다.
7. **무료 풀이권은 그대로다.** 무료 몫은 계정마다 `reading_credit_limit()`(5)로 세고 코드와 이어진 적이 없다. 장부(`reading_credit_use`)가
   계정마다 세므로 한 계정에 두 번 나가지 않는다 — **한 계정에 한 번**은 그대로 참이다.
8. **가입 밖의 화면이 코드를 말하지 않는다** — 로그인 화면(웹 · 앱)의 「처음 오셨다면 로그인 뒤에 테스트 코드가 필요해요」, 받은
   공유본 · 서비스 소개의 `BETA_SIGNUP_CODE_NOTE`(운영자 2026-10-09 「코드를 빼면 이 상수와 부르는 자리를 함께 지운다」), 자주 묻는 질문
   「테스트 코드는 어디서 받나요?」, 서비스 소개의 단계 글, 앱 인연 입구의 단계 「테스트 코드로 가입」, 가입 화면 머리의 「초대받은 분만」 줄.

## 바꾸지 않은 것 — 알고 둔 것

- **베타 종료일** — 운영의 일정 줄은 2026-11-30 에 끝난다(2026-11-05 에 잰 값, 열린 가입 닫힘 0). 그날이 지나면(서울 날짜 12월 1일)
  관문이 모두를 `/closed` 로 보내고 가입 문 · 쓰는 문이 거절한다 — 코드와 무관하게 **가입도 이용도 막힌다.** 이어 받으려면 운영자가
  새 일정 줄을 넣는다(`docs/ops/runbook/signup.md` 「테스트 시작하기」) — 그러면 이미 가입한 사람도 안내를 한 번 다시 확인한다.
- **처리방침 · 약관의 글** — 처리방침(`notice-v13` 꼴의 `PRIVACY_INTRO`)은 「초대받은 분만 쓰는 비공개 베타」 · 「초대해 드린 주소로
  회신」을 말하고, 게시된 약관 초안(아직 시행일 없음)은 PASS 본인확인 · 만 19세 · CI 한 사람 한 계정 · 무료 1장을 가입 조건으로 적는다.
  코드를 걷으면 앞의 둘은 사실과 어긋나고, 뒤의 것은 아직 서지 않은 조건이다. 법률 문장은 운영자 없이 고치지 않는다 — G-136.
- **ADR 0101(본인확인이 가입의 문)** — 「공개 출시에서 테스트 코드 자리를 인증이 대신한다」였다. 이 결정은 코드를 **인증보다 먼저**
  걷는다. 본인확인은 G-20 · G-25 대로 꺼진 채이고, 그동안 가입 문에 나이 · 사람 확인이 없다 — 한 사람이 계정을 여럿 만들면 무료 몫도
  여럿이다. 하루 전체 풀이 상한(`reading_daily_budget()`)은 그대로 비용의 벽이다.
- **출시 단계** — `docs/product/prd/roadmap.md` §7.0 의 「운영 베타 (지금)」는 「테스트 코드로 들어온 사람」을 말했고, 운영 절차는
  「테스트가 아닌 사람을 처음 들이기 전에 출시 단계를 옮긴다」(ADR 0093 · 0097)였다. 단계를 옮길지는 운영자가 정한다 — G-136.

## 고르지 않은 것

- **함수 서명에서 `p_code` 를 지금 걷기** — 위 3. 옛 앱 빌드의 가입이 선다.
- **`signup_code` 표 · 칸을 지우기** — 운영 베타의 기록이 사라지고, 얻는 것이 없다.
- **가입 닫기의 기존 문장을 그대로 두기** — 코드 칸이 없는 폼에서 「코드를 다시 확인해 주세요」는 할 일을 잘못 가리킨다.

## 옛 빌드와 차례

차례는 `db push` → 머지 → 웹 배포 → 앱 빌드다.

| 조합 | 결과 |
| --- | --- |
| 옛 앱 · 옛 웹 + 새 DB | 코드를 보내도 읽지 않으므로 가입이 된다. 옛 화면은 코드 칸을 그대로 세우고 빈 칸이면 앞에서 막으므로, 옛 앱 사용자는 아무 글자나 넣어야 지난다 — 앱을 올리면 풀린다. 틀린 코드의 `false` 는 더 오지 않는다 |
| 새 웹 · 새 앱 + 옛 DB | 코드 없이 보내면 옛 DB 가 「테스트 코드를 넣어 주세요.」로 거절하고, 폼에 코드 칸이 없어 풀 길이 없다 — **그래서 DB 가 먼저다** |

## 추기 2026-11-05 — 공개 서비스의 고지 · 약관 (운영자 결정, 조율자가 옮김)

운영자 답: ① 종료일(2026-11-30)은 운영자가 그 전에 옮긴다 — 바꾸지 않는다 ② 처리방침을 **공개 서비스**로 바꾸고 카카오 로그인의 고지를
같은 판에 묶어 판을 **한 번** 올린다 ③ 무료 풀이권은 5 가 아니라 **1** — 코드는 다른 PR 이 고치고, 글은 「새 계정은 1, 이미 받은 계정은 그대로」로
④ 「비공개 베타」를 걷는다 ⑤ 약관의 본인확인 · 만 19세 · 한 사람 한 계정을 인연의 조건으로 옮기고, 무료 풀이권은 계정마다로 사실대로.

1. **처리방침 `notice-v15` — 판과 기준을 함께 올린다**(ADR 0095). 받는 항목(카카오 회원번호)이 늘고 선택 동의의 목적이 바뀐 내용 개정이라
   확인한 사람 전원이 한 번 다시 읽는다. 바꾼 줄:
   - 머리 「이 서비스는 초대받은 분만 쓰는 비공개 베타입니다.」 → 「이 서비스가 개인정보를 어떻게 다루는지 적었습니다.」
   - 「문의는 이 서비스를 초대해 드린 주소로 회신해 주시면 됩니다. …」 → 「문의는 위 「권리와 행사 방법」의 연락처로 보내 주시면 됩니다. 운영자가 직접 답합니다.」
     — 고지가 이미 싣는 운영자 연락처를 가리킨다(고객 문의 이메일 상수는 `src/lib/brand` 에 있어 `src/lib/consent` 가 부르면 층의 새 방향이다)
   - 「이 비공개 베타는 …에 끝납니다.」 → 「지금 정한 운영 기간은 …까지입니다.」 · 파기 절 「이 베타에서는」 → 「지금 정한 운영 기간에서는」 ·
     맨 끝 줄 「비공개 베타 기간의 … 공개 전환 시에는 이 방침을 다시 씁니다.」 → 「정보 파기 시점은 위 운영 기간의 끝을 기준으로 합니다(끝난 후 N일 이내).
     운영 기간이 바뀌면 이 방침을 다시 알려 드립니다.」
   - 카카오 — 「무엇을 받고」 첫 줄에 회원번호(이메일 · 닉네임 · 사진은 안 받음), 신고 기록의 「로그인 이메일(카카오로 로그인한 계정은 이메일이
     없습니다)」, 파기 절에 「카카오로 로그인하신 계정은 탈퇴를 처리할 때 카카오에 이 서비스와의 연결을 끊어 달라고 요청하며, 이때 카카오 회원번호를
     카카오에 보냅니다.」(#1010 의 웹 연결 끊기 · 앱 SDK)
   - 선택 동의 「다음 테스트 소식 받기」(다음 테스트 초대와 인터뷰 요청) → 「인터뷰 요청 받기」 — 「서비스 개선 인터뷰 요청을 이메일로 보내드립니다.
     이메일이 없는 카카오 계정에는 보내지 않습니다. 광고성 메시지는 보내지 않습니다.」 걷지 않고 목적을 좁혔다 — 칸 · 저장 칸(`contact_consent`) ·
     끄면 쓰지 않는다 · 1년은 그대로라 가장 덜 건드리고 사실과 맞는다. 테스트 모집은 더 없다.
   - 근거는 `docs/legal/privacy-grounds.md` 「공개 서비스 · 카카오 로그인 — `notice-v15`」.
2. **가입 화면의 고지** — 「로그인 정보(이메일 또는 카카오 회원번호)와 닉네임, …」 · 「지금 정한 운영 기간은 …까지이며, 저장된 정보는 늦어도 …까지
   삭제합니다.」 일정 줄이 있는 동안 선다.
3. **약관 초안(시행 전 고침, 뜻이 바뀜)** — 제8조는 약관 · 처리방침 확인과 닉네임뿐이다. 본인확인 · 만 19세 · 한 사람 한 계정 · 명의 도용 해지는
   **제19조의2(인연 찾기 · 대화방의 이용 조건)** 로 옮겼다 — 인연의 스위치(ADR 0222)와 성인 확인 스위치(ADR 0214)를 따라 여는 날의 조건이 된다.
   제13조①은 「회사는 가입을 마친 계정마다 무료 풀이권 1장을 줍니다. 무료 풀이권은 계정마다 한 번입니다.」 — CI 식별값 보관(옛 ②)은 걷었다(사람마다
   세는 길이 없다). 제18조는 「법정대리인의 동의 없이 한 결제는 취소할 수 있다」는 고지만 남겼다(가입에 나이 확인이 없다, 전자상거래법 제13조③).
   부칙은 「시행 전에 가입한 계정이 그때까지 받은 무료 풀이권은 그대로 둡니다」. 카카오를 제2조 · 제9조 · 환불정책 「서비스가 끝날 때」에 더했다.
   근거는 `docs/legal/terms-grounds.md` 「가입 조건과 무료 풀이권 — 공개 서비스」.
4. **화면의 「비공개 베타」** — 바닥글의 「· 비공개 베타」를 걷고, 판매가 닫힌 말을 「지금은 풀이권을 구매할 수 없어요.」로, 일정이 없을 때의 말을
   「아직 서비스를 시작할 수 없어요. 운영 기간과 운영자 연락처가 정해지면 이 화면이 열려요.」로(대장 public-09). **`/closed` 와 DB 의 「비공개 테스트가
   끝났어요」는 두었다** — 기간이 끝났을 때만 서는 말이고 운영자가 그 전에 일정을 옮긴다. 궁합 점수의 「베타」는 지표의 이름이라 두었다.
5. **안 한 것** — 출시 단계(§7.0) · 무료 풀이권의 코드(지금 5)는 다른 PR 이다(G-136).

> 글 · 코드는 다음 라운드다 — G-146(#938 의 다음 notice 판과 함께).

1. **처리방침 · 가입 화면의 고지가 운영 기간과 일괄 파기일을 말하지 않는다.** 「지금 정한 운영 기간은 …까지입니다」 · 「…늦어도 …까지 파기합니다」를 걷고, 파기는
   일반 규칙(탈퇴 때 · 법정 보존 기간)으로 적는다. 까닭: 산 풀이권은 기한이 없는데(ADR 0212 · 0230) 고지가 모든 계정의 파기일을 약속한다. 한국 사주 앱(점신 · 포스텔러 ·
   헬로우봇)은 종료일을 걸지 않는다(출처는 #938 댓글, 같은 문서).
2. **`/closed`(웹 `app/closed/page.tsx` · 앱 `mobile/src/app/closed.tsx`)는 실제 서비스 종료 때만 쓴다** — 「비공개 테스트」 말을 걷는다.
3. **관문의 종료 판정**(`src/lib/consent/gate.ts` 의 `betaIsOver` 갈래 → `/closed`, DB 의 `beta_is_over()` · `beta_schedule.ends_on`)을 고정 기간 없이 어떻게 둘지는 그 PR 이 정한다 — 일정 줄이 끝나는 날이
   곧 서비스 종료가 되지 않게.
4. **그 판이 운영에 오르기 전에는** `beta_schedule` 종료일(2026-11-30)을 운영자가 미룬다(`docs/ops/runbook/signup.md`, G-62).
5. 다음 notice 판에 만 14세 줄(ADR 0231) · Play 결제 · 환불 줄(ADR 0230)과 함께 싣는다 — 판은 한 번 올린다.
