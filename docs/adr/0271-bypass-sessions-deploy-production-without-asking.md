# 운영자가 바이패스 모드로 돌리는 세션은 운영 배포도 묻지 않고, 프로젝트 설정의 `ask` 는 비운다

> **운영자 지시 2026-11-26**(조율자가 옮김) — 전체 점검 라운드 끝에 조율자가 「「배포」라고 답해 주시면 올리겠습니다」라고 하고 배포 명령이
> 확인 창을 띄우자, 운영자가 「바이퍼미션에서 권한요청하지마」라고 했다. 결정 점검표의 「검증 · 배포의 문턱」(배포가 무엇을 기다리나)에 걸린다.
> 운영자가 이미 답한 결정이라 그 말을 옮겨 적는다.
>
> 이 결정이 대체하는 것 — ADR 0093 (일부: 2026-11-07 추기 「배포만 묻는다」의 `ask` 넷과, 공개 출시 뒤 `ask` 를 켤 목록과 같게 두는 시험),
> ADR 0258 (일부: 「정한 것」 3 의 「운영 배포(권한 등급 3)는 「배포」 답 뒤다」 가운데 바이패스 모드 세션)

## 정한 것

1. **바이패스 모드 세션은 운영자에게 권한을 묻지 않는다 — 운영 배포까지.** 라운드 끝의 묶음 배포(`docs/ops/runbook/deploy.md` 「묶음 배포」)를
   조율자가 묻지 않고 밟고, 배포 SHA · Ready · smoke 를 #770 에 적는다. 바이패스 모드는 Claude Code 의 `bypassPermissions` 다(ADR 0258 과 같다).
   그 밖의 세션은 전처럼 「배포」 답 뒤다.
2. **`.claude/settings.json` 의 `ask` 는 비운다.** `ask` 는 바이패스 모드에서도 창을 띄운다(ADR 0093 「재어 본 것」). 바이패스가 아닌 세션의
   배포는 도구가 아니라 권한 표의 문장이 막는다 — 그 세션의 기본 모드는 어차피 허용 목록 밖의 셸 명령마다 묻는다.
3. **이 말로 바뀌지 않는 것.** 등급 4(`deny` — force push · `supabase config push` · main 삭제 · Vercel 변수 삭제)는 묻는 것이 아니라 막는 것이다.
   토큰이 나가는 실호출은 운영자가 돌리고, 운영 개인정보는 직접 조회하지 않는다(ADR 0105). 결정 점검표의 물음(정책 · 비용 · 문구 같은 내용)은 권한이
   아니라 결정이라 그대로 묻는다. 마이그레이션이 든 묶음은 DB 가 먼저다(규약 넷).

## 까닭

운영자의 말 그대로 — 바이패스로 돌리는 것은 묻지 말라는 뜻이다. 머지 승인은 ADR 0258 이 이미 걷었고 남은 물음이 배포였다. 배포의 위험은 main 의 CI 초록 ·
`deploy-range` · smoke 다섯 화면 · 앞 배포로의 Instant Rollback 이 받친다.

## 받아들인 것

- 바이패스 세션에서 운영자가 모르는 사이 운영이 바뀐다 — #770 의 배포 댓글이 그 기록이다.
- `ask` 를 비우면 사용자 설정의 넓은 `allow` 와 겨루던 칸이 사라진다 — 바이패스가 아닌 세션의 배포는 문장만 막는다.
