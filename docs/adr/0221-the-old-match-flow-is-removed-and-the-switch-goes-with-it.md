# 옛 인연 흐름을 지우고 대화와 상세 궁합만 남긴다 — 스위치를 걷는다

> 이 결정이 대체하는 것 — ADR 0216 통째(스위치와 견줄 것이 없다), ADR 0215 의 스위치 · 옛 길 호환 대목, ADR 0038 의 「궁합 요청 때 예약 · 수락이 생성 · 7일 만료」, ADR 0012 의 「수락하면 서로의 여덟 글자 공개」, ADR 0009 의 거절, ADR 0166 의 「거절은 한 번 더 묻는다」, ADR 0130 의 받은 요청 띠 · 수락 카드.
>
> **운영자 지시(2026-11-04): 「문서와 코드 모두 새 흐름으로 통일하고 옛 흐름은 삭제해.」** 결정 점검표의 「누가 무엇을 할 수 있는가」 · 「비용」 · 「되돌릴 수 있는가」에 걸린다. 정책의 원본은 PRD `docs/product/prd/matching.md` §6.6 이고 결정 1 ~ 21 은 그대로다 — 이 ADR 은 정책을 새로 정하지 않고, 두 흐름이 나란히 서던 모양을 하나로 줄인다.

## 잰 것 (2026-11-04)

- **운영 집계** — 요청 · 예약 · 인연 · 방 모두 0, 계정 2(운영자 확인, 2026-11-04). 옛 흐름으로 선 줄이 없어 옮길 자료가 없다.
- **앱은 출시 전이다** — 스토어에 나간 판이 없고 테스트 앱은 OTA 로만 바뀐다. ADR 0215 · 0216 이 지키던 「깔린 옛 앱」이 실제로는 없다.
- **두 흐름이 나란히 서서 생긴 비용** — 요청 줄마다 이름(`bundled` · `talk` · `detail`)을 들고, 규칙이 그 이름을 갈랐다(`match_is_on_the_old_way`). 스위치 경합을 막으려고 요청 문이 기대 종류를 받았다(ADR 0216). 화면 · 시험 · 문서가 켜진 갈래와 꺼진 갈래를 두 벌로 들었다.
- **문서가 옛 흐름을 지금 구조로 말했다** — PRD 입구(§0.1 · §0.2)와 §6.2 가 옛 흐름을 「지금 동작」으로 적고 새 흐름은 §6.6 에만 있었다. 조율자가 입구만 읽고 옛 흐름을 지금 구조로 잘못 읽었다(2026-11-04).

## 정한 것

1. **흐름은 하나다** — 카드 → 바로 첫 말 1건(무료, 수락 없음) → 받은 사람이 답하면 자유 채팅 → 원하면 상세 궁합 구매(구매자 1장, 받은 사람이 72시간 안에 동의한 뒤 생성, 둘이 같이 봄). 수 · 기한 · 끝남의 규칙은 §6.6 이 든다.
2. **옛 흐름을 지운다** — 궁합 요청 때 풀이권 1장 예약, 수락이 인연 궁합을 저절로 만들고 방을 연다, 거절 단추와 그 확인 창, 요청의 7일 만료, 수락하면 서로의 여덟 글자 공개. 어느 화면 · 문에서도 이 길이 서지 않는다.
3. **스위치를 걷는다** — `match_talk_switch` 표 · `match_talk_is_open` · `match_is_on_the_old_way` · `match_request_ttl` · `reading_run_request_kind` · `match_run_awaiting_send.request_kind` · `MK001` · 상세의 「꺼짐」 `55000` 이 없어진다(`20270109090000`). 켜고 끄는 절차 · 재측정 · 되돌리기도 없다. 옛 궁합 요청(`bundled`)이 남아 있으면 그 마이그레이션이 예외로 멈춘다 — 그 줄을 어떻게 할지는 운영자가 정한다.
4. **요청 문은 늘 대화다** — `request_match` 는 언제나 대화(`talk`)를 연다. 대화에 거절은 없어 `respond_to_match_request` 의 대화 `p_accept=false` 는 `22023` 이다. **임시 호환 셋**이 OTA 전에 깔린 앱을 위해 남는다 — `p_expected_kind`(선택, `null` · `talk` 만, 그 밖은 `22023` 이고 아무것도 안 남는다), `my_match_detail_state.detail_open`(늘 참), `match_talk_open()`(늘 참). 제거 조건은 셋이 같다 — 운영 웹이 이 판 뒤로 나가고 모든 계정의 앱 채널에 새 OTA 가 닿은 것을 확인한 뒤 후속 마이그레이션으로 걷는다.
5. **상세 궁합의 예약은 그대로다** — ADR 0038 「예약은 값이 아니라 세는 법」을 상세 요청이 그대로 탄다. 요청 때 1장을 잡고 받은 사람의 누름이 그것을 쓴다. 바뀐 것은 무엇이 예약하는가(궁합 요청 → 상세 요청)와 기한(7일 → 72시간)이다.
6. **여덟 글자는 어느 흐름에서도 사용자에게 돌아가지 않는다** — ADR 0215 「ADR 0012 의 변경」이 새 흐름에만 걸던 것이 유일한 흐름의 규칙이 된다. 동의의 내용은 분석용 AI 전송이고, 관계 해석에서 상대 글자를 유추할 위험은 남으며 복원 불가를 보장하지 않는다(ADR 0012 측정).
7. **배포 순서는 DB 먼저 → 웹 → 앱 OTA 다**(`docs/ops/runbook/deploy.md` 규약 넷의 2). 새 코드가 옛 DB 를 만나면 없는 문을 부른다. 차례는 `docs/ops/runbook/match-talk.md` 「배포 순서」가 든다.

## 앞선 결정과의 관계

- **ADR 0215** — 일부 대체. 스위치(「세운 모양」 1), 요청의 `bundled` 이름과 「규칙은 줄의 이름을 따른다」, 옛 앱의 거절 호환 길(4 · 5 · 6 의 「옛 앱의 거절」), 「꺼진 동안 달라지는 것」 · 「켜면 옛 앱이 보는 것 — 켜기 조건」 · 「잠그지 않은 것」의 끄기 · 옛 인연 줄이 걷힌다. 대화 · 상세 · 동의 · 유일성 · 한도 · 돌려주기 · 상태 문 · 글자를 안 돌려주는 것은 그대로다.
- **ADR 0216** — 통째 대체. 견줄 스위치가 없다. DB 먼저라는 배포 순서는 저장소의 규약이라 이 ADR 이 없어도 선다.
- **ADR 0038** — 일부 대체. 궁합 요청 때의 예약 · 수락 때의 생성 · 7일 만료가 걷히고, 예약 · 세는 법은 상세 요청이 잇는다.
- **ADR 0012** — 일부 대체. 「수락하면 서로의 여덟 글자가 공개된다」가 걷힌다. 출생 원문과 원국 전체 판정을 안 연다는 것과 유추 위험의 측정은 그대로다.
- **ADR 0009** — 일부 대체. 거절이 없다. 요청은 후보를 본 데서 난다는 것과 차단을 되돌리지 않는 것은 그대로다.
- **ADR 0166** — 일부 대체. 거절 단추가 없어 「거절은 한 번 더 묻는다」가 걷힌다. 확인 창 한 벌 · 첫 초점 「취소」는 그대로다.
- **ADR 0130** — 일부 대체. 답할 받은 요청이 없어 인연 탭 맨 위의 받은 요청 띠와 수락 카드가 걷힌다 — 받은 대화는 채팅 목록의 「답하지 않은 대화」에, 상세 요청은 대화방 머리의 카드에 선다. 종은 소식만 든다는 것은 그대로다.

## 고르지 않은 것

- **스위치를 남겨 두고 켜기만 하기** — 두 갈래의 코드 · 시험 · 문서가 그대로 남고, 끄면 옛 흐름이 되살아난다. 옛 흐름으로 선 줄이 없고 깔린 옛 앱도 없어 되돌릴 자리가 지킬 것이 없다.
- **옛 줄을 옮기는 마이그레이션** — 운영에 옮길 줄이 0 이다.
