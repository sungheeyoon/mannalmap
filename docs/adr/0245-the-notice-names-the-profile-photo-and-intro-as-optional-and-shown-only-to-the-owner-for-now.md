# 처리방침이 프로필 사진 · 소개를 선택 항목으로 들고, 지금은 본인에게만 보인다고 적는다 — `notice-v19`

> **운영자 결정 2026-11-08**(조율자가 옮김) — G-153 에서 (a) 「고지 보완」을 골랐다. 문장은 운영자가 정했다 — 정오의데이트처럼 실제 기능을
> 적고 「향후 서비스 확장」 같은 포괄 표현은 쓰지 않는다. 결정 점검표의 「누가 무엇을 볼 수 있는가」(지금 · 열린 뒤의 공개 범위를 고지가 약속한다)와
> 「데이터의 보존 · 삭제」(정지 계정의 삭제)에 걸린다.
>
> **운영자 답 2026-11-08**(PR #1089 의 결정 표에) — 아래 「정한 것」의 1 ~ 5. 게시는 아래 「차례」를 따른다.
>
> **운영자 승인 2026-11-08**(「다 승인해 머지해」 · 「인터뷰 요청받기 그냥 지워, 내 계정이라고」, 조율자가 옮김) — 코드 · 문구 · 결정 표 7 · 8 을 포함해 전부. 8 의 켜진 값과 옛 앱은 아래 8 에 적었다.

## 잰 것

- 프로필 화면은 인연이 닫힌 지금도 사진(최대 6장, `profile_photo`)과 소개(500자, `app_user.intro`)를 받는다. `notice-v18` 의 「무엇을 받고 무엇에
  쓰나요」는 그 둘을 안 들었다 — 인연 절(`DISCOVERY_DISCLOSURE`)과 위탁(AWS) · 파기 줄에만 있었다(`docs/ops/play-listing.md` 「어긋남 · 약점」 1).
- 둘 다 선택이다 — 가입 · 참여 · 풀이 · 궁합이 묻지 않는다. 남의 사진 · 소개가 서는 갈래는 모두 닫힘 판정(`match_open_to`, ADR 0222)을 지난다.
- **기본 참여(opt-out)는 이미 지금 동작이다** — 홈 · 매칭 · 입력 수정 때 `ensure_discovery_participation` 이 사주와 닉네임이 있는 사람의 참여를 열고,
  설정에서 끈 사람(`opted_out_at`)은 다시 열지 않는다(`app/me/discovery/participation.ts` · `app/me/(home)/page.tsx`). 남에게 보이는 조건은 인연 열림과
  양쪽의 성인 확인이다(`discovery_pair_eligible`) — 성인 확인 스위치가 꺼져 있으면 성인 확인 조건이 빠진다(`adult_check_passed`, ADR 0214).
- 정지된 계정은 사진 · 소개를 고치지도 지우지도 못한다(`lock_my_photos` · `save_my_profile`). 그 삭제를 여는 것은 db 의 ADR 0244 다.

## 정한 것

1. **재확인 기준(`notice_ack_floor()`)은 올리지 않는다 — `notice-v18` 그대로.** 까닭: 이미 받던 선택 항목을 고지에서 빠뜨린 것의 보완이고 공개
   범위를 넓히지 않는다. 기준을 두는 뜻은 「진입할 때 전원에게 재확인을 강제하지 않는다」이지 「새 가입자만 본다」가 아니다 — 게시된 처리방침은
   누구나 `/privacy` 에서 본다. 다음 앱 빌드 때도 기준을 저절로 올리지 않고 그때의 변경을 보고 정한다. **기존 회원 안내는 하지 않는다** — 기존 회원
   셋이 모두 운영자 본인 계정이다(운영자 답).
2. **가입 요약(`src/lib/consent/signup.ts`)은 바꾸지 않는다** — 사진 · 소개는 가입에서 받지 않고, 닉네임 안내가 이미 「가입한 뒤에 추가할 수 있어요」라고 말한다.
3. **등록 · 삭제 줄은 (가)** — 「…프로필 화면에서 수정하거나 삭제할 수 있습니다. 이용이 정지된 동안에는 삭제만 할 수 있습니다.」 정지 계정의
   삭제(ADR 0244)가 운영에 반영되고 확인된 뒤에 게시한다.
4. **인연 공개 — 기본 참여(opt-out)를 유지한다.** 이미 지금 동작이고 운영자가 그대로 두기로 했다. 별도의 공개 확인 화면은 두지 않는다. 「지금은
   본인에게만 표시됩니다」 줄은 그대로 둔다. 「성인 확인을 마친」은 인연을 성인 확인 스위치를 켠 채로 열 때만 참이라 그 조건을 G-158 로 ADR 0222 를
   여는 일에 건다. 기본 참여가 근거로 충분한지는 `docs/legal/privacy-grounds.md` 에 `［변호사 검토 필요］` 로 남긴다 — 결론은 내지 않는다.
5. **같은 설명을 두 번 적지 않는다**(운영자 2026-11-08) — 수집 항목 절은 목적까지만 적고, 기본 참여 · 성인 확인 · 누구에게 소개되나 · 끄기는 인연 절
   한 곳에 모은다. 앞 초안의 「인연이 열리면 …」 줄을 수집 항목 절에서 걷었다.
6. **문장 — 운영자가 고른 최종안, 글자 그대로**(2026-11-08).

   | 자리 | 문장 |
   | --- | --- |
   | 수집 · 목적(수집 항목 절) | 「프로필 사진과 소개는 선택 항목입니다. 직접 등록하신 정보를 저장하고, 내 프로필 표시와 인연 찾기의 프로필 소개에 사용합니다.」 |
   | 지금 공개 범위(수집 항목 절) | 「현재 인연 기능은 준비 중이며, 등록한 사진과 소개는 본인에게만 표시됩니다.」 |
   | 등록 · 삭제(수집 항목 절) | 「사진과 소개를 등록하지 않아도 다른 서비스를 이용할 수 있습니다. 등록한 내용은 프로필 화면에서 수정하거나 삭제할 수 있습니다. 이용이 정지된 동안에는 삭제만 할 수 있습니다.」 |
   | 인연 참여 · 공개(인연 절 첫 줄) | 「인연 기능이 열리면, 내 사주와 닉네임을 등록하고 성인 확인을 마친 이용자는 인연 찾기에 기본으로 참여합니다. 참여 중인 이용자의 프로필은 성인 확인을 마친 다른 참여자에게 소개될 수 있습니다.」 |
   | 참여 끄기(인연 절) | 「인연 찾기 참여는 설정에서 언제든 끌 수 있습니다. 인연 찾기 참여를 끄면 새로운 상대에게 소개되지 않으며, 새로운 대화 요청을 보내거나 받을 수 없습니다. 이미 주고받은 대화 요청과 열린 대화방은 유지되며, 해당 상대에게는 내 닉네임·소개·사진이 계속 표시됩니다. 직접 다시 켜기 전까지 꺼진 상태로 유지됩니다.」(운영자가 고른 (ㄴ), 2026-11-08) — 뒤에 「참여를 꺼도 내 사주와 저장한 사람은 그대로 남습니다.」(운영자 승인)를 둔다 |

   세 줄은 「이 정보가 없으면 … 제공하지 못합니다」(출생 정보의 줄) 뒤에 선다. 웹 처리방침만 바꾼다. 사진의 자리 · 보일 자리 · 올린 시각은 문장이
   아니라 근거 문서의 항목 표에 둔다. 「…에만 쓴다」는 쓰지 않는다. 코드와 견준 결과(성인 확인 전의 노출 · 끄기의 즉시성 · 소개받기)는 `docs/product/gaps/records/g-153.md` 「코드와 견줌」.
7. **참여 끄기는 「새 만남 중단」이다**(운영자 (ㄴ), 2026-11-08). 끄면 새 상대에게 소개되지 않고 새 대화 요청을 보내지도 받지도 못한다. 이미 주고받은
   대화 요청과 열린 대화방은 남고 그 상대에게는 닉네임 · 소개 · 사진이 계속 보인다. **기존 관계는 요청 취소 · 대화 종료 · 차단으로 정리한다.** 끌 때
   기존 요청까지 취소하는 안((ㄷ))은 따로의 정책 변경이라 이번에 하지 않았다. 기존 상대에게도 숨기고 싶은 사람이 쓸 길이 있는지는 인연을 열기 전에
   확인한다(G-158).
8. **선택 동의 「인터뷰 요청 받기」를 걷는다**(운영자 지시 2026-11-08 — 「승인한 적이 없다」). **수집 항목이 줄어드는 개정이다** — 선택 동의로 받던
   이메일의 인터뷰 연락 쓰임 하나가 빠진다. 걷는 것: 처리방침의 선택 동의 줄(`OPTIONAL_CONSENTS` — `/privacy` · 가입 · 설정이 같은 목록을 그린다), 웹 · 앱의 가입
   칸과 설정 스위치. 앱 코드가 바뀌므로 **다음 EAS 빌드에 실린다** — 깔린 옛 빌드는 업데이트 전까지 그 칸 · 스위치를 그대로 보이고 `set_contact_consent` 를 부른다.
   **DB 칸 `contact_consent` · 문 `set_contact_consent` · `complete_signup` 의 인자 `p_contact` 는 이번에 지우지 않는다** — 옛 앱이 아직 부를 수 있어
   넓히기 → 좁히기(ADR 0071)를 따르고, 좁히는 일은 G-159 다. 새 가입은 그 인자를 늘 `false` 로 보낸다(DB 가 `null` 을 거절한다). 이 항목을 보내는 코드는
   저장소에 없다(메일 발송 · 크론 · 운영 화면 0 — `contact_consent` 를 읽는 곳은 운영 절차의 가입 집계 SQL 하나, `docs/ops/runbook/signup.md`).
   **경위** — 처음 이름은 「다음 테스트 소식 받기」(다음 테스트 초대와 인터뷰 연락, ADR 0024 의 `contact_consent`)이고, ADR 0225 추기(2026-11-05, #1007)가 공개
   서비스로 바꾸며 「인터뷰 요청 받기」로 좁혔다. 그 추기의 운영자 답 ① ~ ⑤ 에는 이 항목이 없다 — 좁히기는 「걷지 않고 목적을 좁혔다 — 가장 덜 건드리고 사실과
   맞는다」는 맡은 쪽의 판단이었다. 걷은 뒤에도 가입 요약(`SIGNUP_NOTICE_*`)의 문장은 그대로다 — 그 셋에 이 항목이 없다.
   **운영에 켜진 값 3 은 칸째 지운다 — 별도 PR**(결정 표 7 — 운영자 2026-11-08 「끄는 게 아니라 아예 없애」: 셋 다 운영자 본인 계정). 값만 비우는 운영 SQL 은 하지 않고,
   칸 · 문(`contact_consent` · `set_contact_consent` · `complete_signup` 의 `p_contact`)을 지우는 마이그레이션 PR 이 값도 함께 없앤다 — G-159 를 이번 라운드에서 닫는다.
   **옛 앱은 다음 EAS 빌드 때 `android_min_version_code` 를 올린다**(결정 표 8 — 운영자 2026-11-08, ADR 0237). 그 전까지 옛 빌드가 `set_contact_consent` 로 값을 다시 켤 수 있고, G-159 는 그 뒤에 닫힌다.
9. **소급하지 않는다.** 이 판은 게시 뒤의 처리를 알린다. 게시 전에 저장된 것의 처리 근거는 정하지 않고 G-153 에 남긴다. 근거의 선택지(계약 이행 ·
   동의 · 약관)는 판정 없이 근거 문서에 두고 결론은 변호사 검토로 남긴다(ADR 0180).

## 차례

1. 정지 계정의 삭제(ADR 0244)가 운영에 반영되고 확인된다.
2. 인연이 닫힌 동안에도 설정에 참여 끄기 줄이 보이게 하는 PR(#1092)이 머지되고 배포된다 — 지금은 닫힌 동안 설정의 「인연」 무리가 안 서서(ADR 0222 의 6)
   「참여는 설정에서 언제든 끌 수 있습니다」가 화면으로는 참이 아니다. 그 일은 다른 PR 이 맡는다.
3. `notice-v19` 를 웹 배포로 게시한다. 기준은 올리지 않는다.

## 고르지 않은 것

- **기준을 올려 전원에게 재확인** — 공개 범위를 넓히지 않는 보완이고 기존 회원이 운영자 계정뿐이다.
- **인연을 열 때 기존 참여자에게 공개를 다시 확인(별도 화면)** — 기본 참여를 유지했다. 그 대신 성인 확인을 켠 채로 연다(G-158).
- **인연이 닫힌 동안 사진 칸 · 소개 칸을 가리기** — 운영자가 고지 보완을 골랐다.
- **「향후 서비스 확장」 같은 포괄 목적** — 운영자가 걷었다.
