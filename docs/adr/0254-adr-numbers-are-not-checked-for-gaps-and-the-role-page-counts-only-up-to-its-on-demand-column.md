# ADR 번호의 빈틈은 재지 않고, 역할 문서의 한 화면은 「닿을 때 여는 것」 앞까지만 잰다

> **운영자 결정 2026-11-19**(조율자가 읽기만 하는 감사 일곱의 결론을 물었고, 고른 답 그대로 — 조율자 브리프로 전함) —
> 「ADR 번호 빈틈 검사 걷기 — PR 빨간불 69번 중 34번이 이 검사 하나. 번호 겹침 · 없는 번호 검사는 남김」 ·
> 「역할 문서 한도 조정 — 8,000바이트에서 「닿을 때 여는 것」 칸은 안 셈. 깎지 않고 줄을 넣기 위해」.
> 결정 점검표의 「검증 · 배포의 문턱」(무엇을 시험이 확인하나)에 걸린다.
>
> 이 결정이 대체하는 것 — ADR 0177 「정한 것」 1 의 재는 범위(역할 문서 한 장 전부 → 「닿을 때 여는 것」 앞까지) ·
> ADR 0238 「견준 것」의 번호 이음 시험 대목(앞 PR 이 머지되기 전에는 뒤 PR 이 붉다 · 머지는 번호 순).

## 잰 것 (2026-11-19, main `1da9819e`)

- **PR 이 붉은 까닭의 절반이 번호 이음 하나였다.** 조율자 감사가 PR 의 실패한 검사 69 를 셌더니 실패가 `scripts/code-rules.test.ts`
  「ADR 파일은 … 번호가 빈틈없이 이어진다」 하나뿐인 것이 34 였다. 예: run 43415724845(2026-11-13, ADR 0251 의 PR) — `1 failed | 5412 passed`,
  `expected 251 to be 250`. 나란히 연 PR 들이 조율자에게 번호를 나눠 받고, 뒤 번호가 앞 번호보다 먼저 준비되면 앞 PR 이 머지될
  때까지 붉었다. 그 붉음은 결함을 가리키지 않는다 — 빈 번호는 앞 PR 이 머지되면 찬다. 그런데 매번 로그를 열어 「실패가 이것
  하나뿐인지」 봐야 했고(`docs/agents/delegation/parallel.md` 「ADR 번호」 줄), 머지 차례가 번호에 묶였다.
- **그 시험만 잡던 잘못은 따로 없다.** 같은 번호 둘은 「ADR 번호는 한 파일에만 있다」(한 트리)와 gate 의 공유 번호 검사(열린 PR
  끼리, ADR 0238)가, 없는 번호를 가리키는 참조는 「코드·SQL·문서의 `ADR NNNN` 은 전부 있는 파일을 가리킨다」가 잡는다. ADR 은
  지우지 않으므로(ADR 0240) 빈틈이 생기는 길은 머지 차례와 번호를 잘못 친 것뿐이다.
- **역할 문서 둘이 한도에 닿았다.** `docs/roles/ui.md` 7,996 · `docs/roles/reviewer.md` 7,966 바이트(한도 8,000). 줄 하나를 더할 자리가
  없어 새 규칙이 역할 문서 대신 조율자 문서와 세션의 사설 기억으로 샜다(감사). 「닿을 때 여는 것」 앞까지 재면 ui 4,346 ·
  reviewer 5,979 이고, 나머지 여섯은 2,880(feature) ~ 4,246(coordinator)이다(같은 날 `awk` 로 머리 앞까지 잘라 `wc -c`).
- 운영자는 2026-10-11 에도 「설명을 계속 줄여서 맞추지는 마세요」라고 했다(조율자가 옮긴 말 — G-107, ADR 0177 「잰 것」의 문서
  깎기를 막은 일). 한도에 닿은 역할 문서는 줄일 수도 늘릴 수도 없었다.

## 정한 것

1. **ADR 번호의 빈틈은 재지 않는다.** `scripts/code-rules.test.ts` 「ADR 파일은 `NNNN-영어-문장.md` 이다」는 이름 꼴만 잰다 —
   첫 번호가 1 이고 끝 번호가 파일 수와 같다는 두 단언을 걷었다. 그대로 서는 것:
   - 같은 번호의 파일 둘 — 「ADR 번호는 한 파일에만 있다」
   - 열린 PR 끼리 같은 번호 — `gate` 의 공유 번호 검사(ADR 0238)
   - 없는 번호를 가리키는 참조 — 「코드·SQL·문서의 `ADR NNNN` 은 전부 있는 파일을 가리킨다」
   - 다음 번호를 고르는 법 — 조율자가 브리프에서 나눠 주고, PR 을 열기 직전 `origin/main` 과 열린 PR 을 다시 본다
     (`docs/agents/delegation/done.md` 「끝났다는 것」)

   **머지는 번호 순이 아니어도 된다.** 뒤 번호 PR 이 먼저 들어도 붉지 않고, 빈 번호는 앞 PR 이 들면 찬다.
2. **역할 문서의 한 화면(8,000 바이트)은 「닿을 때 여는 것」 머리 앞까지 잰다** — 제목 · 머리말 · 칸 넷(「먼저 읽는 것」 ·
   「이 저장소의 방식」 · 「하지 않는 것 · 묻는 것」 · 「끝날 때 고치는 것」). 「닿을 때 여는 것」은 손대기 전에 읽지 않는 칸이라
   (ADR 0147) 한 화면에 들지 않는다. 그 칸이 맨 뒤에 있는지, 줄마다 `- 조건 → [원본](경로)` 한 줄인지, 가리킨 파일 · 절 · 앵커가
   있는지는 그대로 잰다. **더한 것 둘** — 그 칸에는 여는 말 한 줄(「손대기 전에 다 읽지 않는다 — …」)과 목록 줄만 선다(목록 밖 문단은
   붉다 — 셈 밖에 원본을 옮겨 적는 길을 막는다). 머리가 있는데 그 자리에서 못 자르면(머리 끝 공백 · CRLF) 붉다 — 못 자른 칸은 꼴
   시험까지 조용히 건너뛰었다.
   - **경계는 그대로 일의 쓰임으로 정한다**(ADR 0147 「무엇을 옮기는가의 기준」 · ADR 0177). 셈에서 빠진다는 까닭으로 「먼저 읽는
     것」의 줄을 「닿을 때 여는 것」으로 옮기지 않는다 — 바이트는 까닭이 아니다.
   - 바이트를 맞추려고 문서를 깎거나 쪼개지 않는다(ADR 0177) — 그대로다.

## 치르는 값

- 번호를 잘못 쳐서(0254 를 0264 로) 생긴 빈틈은 아무도 붉히지 않는다. 번호는 이름표라 빈 번호가 남아도 가리키는 것이 틀리지
  않고, gate 가 내주는 다음 번호는 끝 번호 위다(ADR 0238 의 4).
- 「닿을 때 여는 것」이 길어져도 CI 는 모른다. 그 칸은 일이 그 자리에 닿을 때만 여는 칸이라 손대기 전의 한 화면과 무관하고,
  줄의 꼴 · 가리킨 자리는 시험이 든다. 목록 줄 하나의 길이는 재지 않는다 — 꼴(`- 조건 → [원본](경로)` 한 줄)만 잰다. 그 칸이 커져
  「닿을 때」의 줄을 찾기 어렵다는 보고가 쌓이면 다시 연다.

## 버린 것

- **번호 이음 시험을 main 에서만 돌린다** — PR 은 초록이어도 차례가 엇갈린 머지마다 main 이 붉어, 같은 34 번이 붉은 main 이슈가 된다.
- **번호 이음을 경고로만 찍는다** — 아무도 안 읽는 줄이 하나 는다. 막는 것이 없는 검사는 두지 않는다.
- **역할 문서 한도를 올린다**(8,000 → 10,000 같은) — 천장을 올리면 다시 닿는다(ADR 0177 「버린 것」의 천장과 같은 결). 운영자가 「닿을 때
  여는 것」을 세지 않는 쪽을 골랐다.
- **역할 문서를 깎아 맞춘다** — 운영자가 막았다(2026-10-11, ADR 0177).

## 시험

`scripts/code-rules.test.ts` — 「ADR 참조」의 첫 시험(이름 꼴과 ADR 이 200 넘게 있는지)과 「역할 문서」의 칸 시험(칸 넷 · 칸 넷까지가
한 화면 · 머리에서 실제로 자른다 · 그 칸에는 여는 말과 목록 줄만). 일부러 어긴 것은 이 결정의 PR 본문에 적었다 — 빈틈(가짜 `0299-…`)은
초록, 잘못된 이름 · 같은 번호 둘은 붉음, 「닿을 때 여는 것」의 목록 줄만 늘려 문서 전부가 8,000 을 넘으면 초록, 칸 넷을 늘려 넘으면 붉음,
「닿을 때 여는 것」에 목록 밖 문단 · 머리 끝 공백이면 붉음.
