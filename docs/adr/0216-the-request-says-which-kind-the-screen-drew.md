# 요청 문은 화면이 그린 종류를 받아 스위치와 같은 읽기로 견준다

> 운영자 결정(2026-11-02, #961): 스위치 경합을 위험 기록으로 끝내지 말고 DB 에서 호출자가 기대한 요청 종류를 확인한다. 결정 점검표의 「비용」 · 「실패했을 때 열리는가 닫히는가」에 걸린다. 흐름의 원본은 PRD §6.6, 흐름을 세운 까닭은 ADR 0215 다.

## 잰 결함

`request_match` 하나가 스위치 값으로 대화(`talk`, 무료)와 옛 요청(`bundled`, 풀이권 1장 예약)을 고른다. 화면은 스위치를 먼저 읽고 단추를 그린다.

- 켜진 화면의 무료 「대화 시작」이 끈 뒤 눌리면 풀이권 1장이 잡힌다. 앱의 사전 읽기는 틈을 줄일 뿐이고 웹은 다시 읽지도 않았다.
- 꺼진 화면의 유료 「궁합 요청」이 켠 뒤 눌리면 말없이 무료 대화가 선다.

## 정한 것

1. **서명은 하나다** — `request_match(p_candidate_user_id uuid, p_expected_kind text default null)`. 옛 `request_match(uuid)` 는 같은 마이그레이션에서 지웠다. 값은 `talk` · `bundled` 뿐이고 그 밖은 `22023` 이다.
2. **견줌과 갈래는 한 번의 읽기다** — 계정을 잠그고 정지를 다시 본 뒤 스위치 줄을 `for share` 로 한 번 읽어, 그 값으로 기대를 견주고 그 값으로 갈래를 고른다. 줄이 없으면 꺼짐이다.
3. **다르면 `MK001`** — 이 문만 쓰는 전용 코드다. 던지므로 요청 · 인연 · 예약 · 횟수 · 소식이 안 남는다. `55000` 은 이 문의 「내 요약이 낡음」이 쓰고 있어 못 쓴다. 코드는 `src/lib/matching/requests.ts` 의 `SWITCH_MOVED_CODE` 한 곳이고, 화면은 문장이 아니라 코드로 가른다.
4. **스위치를 바꾸는 `update` 는 진행 중인 요청을 기다린다** — 사진 스위치와 같은 규율이다(ADR 0203). `update … returning` 이 돌아온 순간에는 옛 값으로 지난 요청이 남아 있지 않다. 옛 호출도 이 읽기를 지난다.
5. **화면** — 웹 · 앱의 「대화 시작」은 `talk`, 「궁합 요청」은 `bundled` 를 싣는다. 거절을 받으면 돈이 안 움직였으므로 잔액을 다시 묻거나 풀이권 창을 열지 않고, 최신 상태로 다시 그린 뒤 DB 의 문장을 보인다. 앱의 사전 읽기는 걷었다. 인자가 선택이라 타입이 빠뜨림을 못 잡아 `scripts/match-talk-stays-off.test.ts` 가 호출 자리마다 잰다.

## 옛 호출 — 이 보호가 없다

운영 웹 `7405da7` · 깔린 앱 · `scripts/check-*.mjs` 는 인자 하나로 부른다. 기대값이 `null` 이라 **지금 동작 그대로이고 이 보호가 없다** — 켜진 화면의 옛 앱은 끈 뒤 누르면 풀이권을 잡고, 꺼진 화면의 옛 앱은 켠 뒤 누르면 무료 대화가 된다. 이 틈은 옛 앱이 나가야 닫힌다. 그래서 인자를 필수로 좁히는 일은 옛 판이 나간 뒤의 일이고 지금 하지 않는다.

## 배포 순서 — DB 먼저, 그다음 웹 · 앱

새 코드가 없는 인자를 부르므로 마이그레이션이 먼저다(`docs/ops/runbook/deploy.md` 규약 넷의 2). **새 코드가 옛 DB 를 만나면 요청이 전부 닫힌다** — `PGRST202`, 줄 0, 돈 0. 화면에는 「일시적인 문제로 처리하지 못했어요. 잠시 뒤 다시 시도해 주세요.」가 선다. 돈이 안 나가는 쪽이지만 그 창 동안 인연 요청이 안 된다.

**이 PR 은 나누지 않는다 — `docs/agents/delegation/permissions.md` 「예외 — 마이그레이션이 든 PR」의 분리 규칙(「넓히는 마이그레이션 PR 과 앱 PR 로 나눈다」)과 다르다**(조율자 결정). 까닭: 머지는 아무것도 내보내지 않고(`vercel.json` `deploymentEnabled: false`), DB 적용은 운영자의 별도 승인이며, 테스트 앱이 main 을 재야 한다. 그래서 **머지와 DB 적용의 차례가 그 규칙처럼 잠기지 않는다 — 운영 `db push` 와 확인 전 묶음 배포 금지, 어기면 인연 요청이 전부 `PGRST202` 로 닫힌다(돈은 안 나간다).** `docs/ops/runbook/deploy.md` 「묶음 배포」의 0 과 G-130 이 든다. 적용 순서는 `20270107090000` → `20270107100000`.

**옛 서명의 `drop` 과 새 서명의 `create` 사이에 틈이 없다** — 저장소 관례대로 파일에 `begin` 을 안 적어도 CLI 가 파일 하나를 한 트랜잭션으로 돈다. 로컬 `supabase migration up --local`(CLI 2.115.0)로 쟀다: `drop` 뒤 6초 잠들고 `1/0` 으로 끝나는 파일을 돌리면, 잠든 사이 다른 세션에 함수가 1개 보이고 `AccessExclusiveLock` 이 쥐어져 있으며, 실패 뒤 함수가 그대로이고 이력 줄이 0 이다. 운영에 쓰는 `db push` 자체로는 안 쟀다.

## 고르지 않은 것

- **기본값 없는 둘째 서명으로 두 벌** — 모호하지는 않지만 문이 둘이라 갈래 읽기 · 시험 · 권한 목록이 두 벌이 된다. 본문을 안쪽 함수로 빼야 하고 생성 타입이 합집합이 된다.
- **옛 서명을 남기고 `default` 를 단 새 서명** — 인자 하나의 호출이 모호해져 운영 웹과 깔린 앱이 깨진다.
- **새 이름의 문** — 한 일에 문 이름이 둘이 되고 옛 문의 본문을 함께 고쳐야 한다.
- **스위치를 잠그지 않는 읽기** — 어긋남은 막지만 끈 뒤에도 옛 값으로 지난 요청이 커밋될 수 있다.
- **화면의 사전 읽기만 더하기** — 읽기와 부름 사이의 틈이 남는다.

## 앞선 결정과의 관계

- **ADR 0215** — 잇는다. 「규칙은 줄의 이름을 따른다」는 그대로이고, 이 일은 새 줄의 이름이 화면이 말한 것과 같은지만 잰다.
- **ADR 0203** — 스위치 줄을 `for share` 로 쥐는 규율을 빌렸다. **차례는 사진과 같다** — 계정 잠금 뒤 스위치다. 스위치를 바꾸는 쪽은 그 줄 하나만 잠가 교착이 안 선다.
- **규약 넷의 3**(넓히고 재고 좁힌다) — 옛 서명을 남기는 대신 기본값으로 넓혔다. 옛 호출이 그 한 서명에 닿는 것을 위 표가 잰다.
