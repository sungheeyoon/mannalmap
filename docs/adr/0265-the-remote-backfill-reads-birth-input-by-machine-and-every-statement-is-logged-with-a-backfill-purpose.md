# 원격 백필은 출생정보를 기계로만 읽는 넷째 갈래이고, 문장마다 `backfill:` 목적으로 접속기록에 남는다

> **운영자 결정 2026-11-23**(조율자가 옮김) — G-180 의 두 안 가운데 (가): 「넷째 갈래를 새로 둔다. 사람에게 값을 보이지 않는 기계 읽기로 보고
> `docs/ops/runbook/access.md` 표에 한 줄 더하고 목적 앞머리를 정해 두 백필 시험의 목적에 싣고, 그 앞머리를 시험이 확인하게 한다.」
>
> 이 결정이 대체하는 것 — ADR 0105 (일부: 결정 1 의 「개인정보를 읽는 직접 SQL 은 break-glass 에서만, 사람만, 대장에 적고」 가운데
> 원격 백필 두 시험의 출생정보 읽기)

## 까닭

엔진 판이 바뀌면 이미 저장된 사람의 여덟 글자를 다시 세야 한다(ADR 0071). 그 계산은 TypeScript 엔진만 할 수 있어 원격 백필 두 시험
(`src/lib/input/backfill-chart.live.test.ts` · `backfill-reading-chart.live.test.ts`)이 운영 DB 의 출생정보(`person_chart_revision`)를
SQL 로 읽는다. ADR 0105 결정 1 은 출생정보를 SQL 로 읽는 것을 break-glass(장애 · 수사기관 요청, 사람만, 밖의 대장 먼저)로만 두었다 —
백필은 그 어느 까닭에도 안 들고, 표대로면 할 수 없는 일이 된다. 그런데 백필은 읽은 값을 사람에게 보이지 않는다 — 찍는 것은 개수와
불투명 id 뿐이고, 값은 엔진에 들어가 여덟 글자로 바뀌어 다시 쓰인다. 2026-11-23 까지 이 SQL 은 접속기록도 안 거쳤다(G-179, #1259 가 닫음).

## 정한 것

1. **원격 SQL 의 갈래는 넷이다** — 보통 · 운영자만(검토 기록) · **운영자만 — 기계 읽기(백필)** · break-glass. 넷째는 출생정보를 SQL 로
   읽되 값을 사람에게 보이지 않고 계산에만 쓰는 원격 백필 두 시험이다. 원본은 `docs/ops/runbook/access.md` 「개인정보는 화면으로만」 표다.
2. **운영자가 돌린다** — 잠금으로 감싸서(`node scripts/remote-lock.mjs npx vitest run <백필 파일>`). 에이전트는 돌리지 않는다
   (`docs/agents/delegation/permissions.md` 등급 3 그대로). 같은 SQL 로 값을 사람이 보면 이 갈래가 아니라 break-glass 다.
3. **문장마다 접속기록에 한 줄** — `npm run db:remote` 와 같은 길(`scripts/db-remote.mjs` 의 `sendLogged`)로, 보내기 전에 목적 · sha256,
   적지 못하면 안 보냄, 끝난 뒤 결과. 한 번 돌림에 한 줄이 아니다 — 백필의 문장은 읽은 자료로 그때 지어져 돌리기 전에는 해시할 원문이
   없고, 결과 줄은 앞 줄 하나를 가리킨다(부분 유일 인덱스, `20261015090000`).
4. **목적은 `backfill:` 로 연다** — `break-glass:` 와 같은 꼴이다. 그 앞머리는 백필의 손(`loggedSender`)만 쓴다: `npm run db:remote` 는
   `backfill:` 로 여는 목적을 거절하고, `loggedSender` 는 그 앞머리가 없는 목적이면 던진다. 두 시험의 목적이 그 앞머리로 열리는지는
   `scripts/db-remote.test.ts` 가 잰다.
5. **월 점검이 두 앞머리를 함께 본다** — `break-glass:` 줄은 대장과, `backfill:` 줄은 운영자가 백필을 돌린 날 · 실행자와 맞춘다. 백필을
   돌리면 저장소 밖 점검 기록에 날짜 · 실행자 · 엔진 판을 한 줄 적는다(`docs/ops/runbook/security.md` 「월 점검」).

## 버린 것

- **break-glass 로 둔다**(G-180 의 (나)) — 대장 번호를 목적에 싣는다. break-glass 의 까닭(장애 · 수사기관)에 백필이 안 들어 까닭 칸이
  거짓이 되고, 엔진 판이 바뀔 때마다 도는 정해진 일을 비상 통로로 다루게 된다.
- **기록 밖에 둔다**(G-179 의 다른 닫는 조건) — 운영자가 그 갈래를 접속기록 밖으로 정한다. 출생정보를 읽는 SQL 이 0일 남는다 — ADR 0105 가
  막으려던 틈이다.
- **한 번 돌림에 한 줄** — 위 3.

## 잠그지 않은 것

- 백필이 값을 사람에게 보이지 않는다는 것은 코드의 약속이다(보고가 개수와 id 만 찍는다). 누가 그 SQL 을 따로 떼어 값을 보면 접속기록은
  `backfill:` 로 남을 수 있다 — 월 점검이 운영자가 돌린 날과 맞춰 드러낸다.
- `backfill-chart` 의 쓰기(`set_person_chart`)는 열쇠로 부르는 RPC 라 이 기록 밖이다 — 앱의 열쇠 호출과 같다.
