# 앱은 풀이를 시스템 공유창으로 보내고, 넘기는 것은 주소 한 줄뿐이다

> **운영자 승인 2026-11-13**(조율자가 옮김) — 앱의 풀이 공유를 안드로이드 시스템 공유창으로 바꾼다. 넘기는 값은 주소 한 줄뿐이고,
> 「복사했어요」 말풍선은 걷는다(안드로이드는 복사하면 시스템이 알린다). 웹은 그대로 둔다.
> 이 결정이 대체하는 것 — ADR 0063(일부 — 「시스템 공유창도 안 쓴다」를 앱에서. 웹은 그대로 복사다).

## 정한 것

1. **앱(`mobile/src/reading/share-button.tsx`)은 누르면 공유본 주소를 만들어 시스템 공유창(React Native `Share.share`)에 넘긴다.**
   단추 글자는 「공유하기」, 표지의 둥근 아이콘은 위 화살표 + 상자 꼴(`mobile/src/ui/icons.tsx` 의 `share`)이다.
   웹(`app/me/reading/share-button.tsx`)은 ADR 0063 그대로 「공유 링크 복사」다.
2. **넘기는 값은 주소 한 줄이다** — 안드로이드는 `message` 에 주소만, iOS 는 `url` 하나만. 제목 · 설명 글은 넘기지 않는다.
3. **앱의 「복사했어요」를 걷는다.** 복사는 공유창의 「복사」가 하고, 안드로이드가 스스로 알린다.
4. **공유창을 그냥 닫은 것은 실패가 아니다** — 아무 줄도 안 선다.
5. **링크를 못 만들었거나 공유창이 안 열리면 주소를 세워 손으로 긁게 한다**(ADR 0063 의 마지막 길과 같다). 표지 아이콘의 그 줄은
   표지 아래에 선다 — 아이콘 곁에 띄우면 표지의 비유 글을 덮었다(에뮬레이터, 2026-11-13).

## 까닭

ADR 0063 이 공유창을 뺀 까닭은 받는 앱이 `url` 과 `text` 를 구분자 없이 이어 붙여 주소가 깨진 것이었다. 붙일 글을 넘기지 않으면 그
자리가 없다. 앱 안에서는 클립보드보다 공유창이 사람이 기대하는 동작이고(단추에 적힌 대로 일어난다), 공유창에도 「복사」가 있어 복사의
길은 남는다. 웹은 브라우저마다 `navigator.share` 의 값 처리와 누름 만료가 달라 이 결정에 넣지 않았다.

## 잰 것 · 안 잰 것

- 에뮬레이터(API 37, Expo Go, 가짜 서버)에서 공유창이 주소 한 줄만 받는 것(「Sharing link」 판에 주소만), 닫아도 줄이 안 서는 것,
  링크 실패 줄이 표지 아래에 서는 것을 쟀다.
- 실기기에서 카카오톡에 붙여 넣은 모양 · iOS 는 재지 않았다.
