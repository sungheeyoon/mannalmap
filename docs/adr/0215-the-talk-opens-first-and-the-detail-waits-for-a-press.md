# 대화는 수락 없이 먼저 열리고, 상세 궁합은 받은 사람의 누름을 기다린다 — 꺼진 스위치 뒤에서

> **정책의 원본은 PRD `docs/product/prd/matching.md` §6.6 이다.** 여기는 그 정책을 DB 에 어떻게 세웠고 왜 그 모양인지만 적는다. 문의 이름 · 칸 · 코드는 `docs/ops/runbook/match-talk.md` 「API 계약」.
>
> 운영자 결정(2026-11-02, #961) 위에 운영자가 위임한 세부(2026-11-01 · 11-02)를 조율자가 정했다. 결정 점검표의 「누가 무엇을 할 수 있는가」 · 「실패했을 때 열리는가 닫히는가」 · 「비용」 · 「보존」에 걸린다. 켜는 것은 이 ADR 이 아니다.

## 잰 것 (2026-11-02, main `4224b6e9`, 로컬 스택)

- 수락 트랜잭션이 방 · 여덟 글자 · 시도 · 차감을 한 번에 연다. 옛 재시도의 계산 입력은 지금 입력이다(#961 결함 1).
- 「한 인연에 글 하나」는 화면 판정뿐이었고 `save_reading` 은 덮어쓴다(결함 2). `my_last_reading_run` 은 실패를 상대에게도 보인다(결함 3).
- 셈은 행을 센다. #966 의 B4 · B7 은 장부로 셈할 때만 밟는다.
- 끝난 방의 말은 `purge_closed_chat_messages` 가 `closed_at` 만 보고 지운다 — `declined` 방도 든다(시험이 89일 · 91일로 잰다). 숨은 방의 신고 문은 닫혀 있어 열었다.

## 세운 모양

1. **스위치** `match_talk_switch` 는 한 줄이고 기본값은 꺼짐이다. **줄이 없으면 꺼짐이다** — ADR 0214 와 반대인데, 여기서 위험한 쪽(수락 없이 방이 열린다)이 켜짐이기 때문이다.
2. **요청에 이름이 붙는다** — `bundled` 옛 요청 · `talk` 대화 · `detail` 상세. **규칙은 스위치가 아니라 줄의 이름을 따른다.** 스위치는 새 줄의 이름과 문이 열렸는가만 정한다. 켜기 전 요청은 옛 길로 끝나고, 다시 꺼도 선 대화의 규칙은 그대로다. 그 인연이 옛 길인지는 `match_is_on_the_old_way` 하나가 답한다.
3. **상세도 `match_request` 줄이다. 새 표 · 새 장부 칸이 없다**(ADR 0038 「예약은 값이 아니라 세는 법」). 예약 · 풀림 · 만료 · 장부 트리거 · 탈퇴 cascade 를 그대로 탄다. 셈이 행을 세는 채이므로 cascade 뒤 남은 `reserved` 장부 줄이 잔액을 안 먹는다(#966).
4. **대화** — 기한이 `infinity` 라 그냥 둔 대화는 그대로 남고, 입력을 고쳐도 무효가 안 된다. 받은 사람의 말이 곧 답이다. 옛 앱의 거절 단추가 부르는 `p_accept=false` 는 호환 길로 남긴다. 새 화면은 안 부른다.
5. **끝난 답 전 대화** — 거둠 · 답 전 차단 · 옛 앱의 거절 · 정지 · 탈퇴 신청이 모두 방 이름 `declined` 로 닫는다. 이 칸은 상대가 표에서 읽으므로 **저장값부터 같아야** 차단이 안 드러난다. 인연은 `visible_matches` 에서 내려가고 사진 · 소개가 닫히며 방은 양쪽 목록에서 사라진다. 말은 안 지우고 90일 보존을 따른다.
6. **다시 시작** — 인연에 `ended_at` 을 두고 「한 쌍에 인연 하나」를 살아 있는 인연으로 좁혔다. 거둠 · 정지 · 탈퇴 신청 철회 뒤 새 대화는 새 인연 · 새 방이고 옛 말이 안 섞인다. 옛 앱의 거절은 유일 색인에 그대로 묶여(ADR 0009) 다시 못 연다.
7. **동의** — 누름이 입력 판을 재고(D2) 글자를 베끼고 한 트랜잭션에서 시도를 열어 얼린다. 시도를 못 열면 누름 전체가 되돌아가고 까닭은 말하지 않는다 — 구매자의 지갑이다. 동의는 같은 두 사람 · 같은 입력 판에 유효하고(`match_consent_holds`), 정지 · 탈퇴 신청 · 차단 · 받은 사람의 참여 끔이 끝낸다. **모델로 보내기 직전(`prepare_reading_job`)에 범위 · 방 · 동의를 다시 재고** 끝났으면 실패로 닫아 복원한다. 옛 길은 그대로다. 저장 때는 안 잰다(ADR 0071). 기술 실패 뒤 재시도는 새 누름 없이 양쪽 누구나 열고 연 사람이 1장을 쓴다. 재시도는 새 줄이 아니라 계수 · 소식을 안 탄다.
8. **유일성** — 답을 기다리는 상세 하나 · 도는 생성 하나 · 완성 하나 · 살아 있는 인연 하나를 색인이 든다. 시도를 여는 안쪽 문도 동의의 열쇠(`match_run_is_agreed`) 없이는 거절한다.
9. **한도 · 묶음** — 시간당 수는 대화 · 상세 공용이고, 요청 소식 묶음은 둘을 따로 센다. 값은 설정 함수 한 곳씩이다: `match_detail_ttl` 72시간(운영자 결정) · `match_request_hourly_limit` 3 · `match_talk_daily_limit` 10 · `request_news_window` 24시간. 시간당은 줄이 새로 설 때만 세므로 재전송 · 돌려받은 호출 · 거절된 호출 · 재시도는 안 센다.
10. **돌려주기** — 두 사람 사이 살아 있는 대화 · 상세 요청은 각각 하나고, 상대가 이미 시작했으면 내 호출은 그것을 돌려준다.
11. **상세는 시스템이 거절로 끝내지 않는다** — 정지 · 탈퇴 신청 · 차단 · 참여 끔 · 문의 직접 `p_accept=false` 가 모두 `cancelled` 다. 상세의 `rejected` 는 없고 다시 청할 수 있다(차단이면 범위가 막는다). 옛 앱에도 상세 거절은 없어 호환 길이 아니라 직접 호출일 뿐이다.
12. **상태 문** `my_match_detail_state`, 켜짐을 읽는 `match_talk_open`(로그인 전에도, 개인 값 없음).

**분석 범위 변경**(§6.6 의 16)은 AI 로 보내는 자료의 종류가 늘어나는 것이다. 프롬프트 문장 변경은 아니다. 코드 조건은 없고 그런 변경을 할 때 판을 올리는 규칙이다.

## ADR 0012 의 변경 — 새 흐름에서

동의 시점은 받은 사람의 누름이고, 새 흐름에서는 **동의해도 여덟 글자를 사용자에게 돌려주지 않는다.** 문장을 쓰는 데만 쓰인다(`my_match_scope` · `my_readings` 의 글자 칸 null, 내부 동결값은 그대로). 옛 `bundled` 는 그대로 보인다.

**위험과 검증 한계:** 관계 해석에서 상대 글자를 유추할 위험이 있다(ADR 0012 측정). 이 일은 **응답 칸의 직접 노출 차단만 검증했고, 복원 불가를 보장하지 않는다.** 글 안의 글자 금지 검사는 #963 으로 넘긴다.

## 초기값의 조정 기준

첫 말 1건 · 시간당 3회 · 하루 10건 · 소식 24시간은 **근거 없는 초기값**이다. 켠 뒤 신고 · 차단율, 한도에 걸린 수, 답장율을 재서 고친다.

## 꺼진 동안 달라지는 것

`supabase/tests/99_match_off_keeps_old_answers.test.sql` 은 새 이름을 안 쓰고 마이그레이션 앞 · 뒤의 스택에서 같은 43 값으로 초록이다 — 요청 · 재전송 · 수락 · 채팅 · 생성 · 실패 · 복원 · 다시 만들기 · 거절 · 취소 · 차단과 새 한도가 안 걸림을 든다. 달라지는 것은 둘이다.

1. 글이 있는 인연의 **둘째 완성**이 `save_reading` 에서 덮어쓰지 않고 `23505` 로 선다.
2. 그래서 그 길의 시도는 모델을 부르고 글을 버린다 — 그 자리는 시도가 실패로 닫혀야 돌아온다.

글이 선 뒤 다시 만드는 단추는 흐름 검사가 없다고 잰다(ADR 0038). 다른 판 · 다른 호출이 그 길에 닿는지는 다 재지 않았다. 색인을 스위치 뒤 줄로만 좁히면 「완성 하나」가 함수의 약속으로 내려가 일부러 전체에 걸었다. 프로덕션 인연은 2026-11-02 에 0 이고, 올리기 전 집계는 runbook 이 든다.

## 켜면 옛 앱이 보는 것 — 켜기 조건

| 호출 | 답 |
| --- | --- |
| 요청 | 성공 — 방이 바로 열린다. 살아 있으면 같은 번호 |
| 받은 요청 수락 · 거절 · 취소 | `accepted` · `rejected` · `cancelled` — 아는 값이다. 시도 · 차감 없음 |
| 말 보내기 | 답 전 둘째 말은 우리 문장으로 거절 |
| 궁합 만들기 | `23514` 문장. 궁합 화면은 글자가 없어 닫힘 — 새 흐름의 완성 글도 옛 화면에는 안 선다 |
| 소식 | 첫 소식 문장이 「상세 궁합을 함께 보자고 요청」이다 — **대화에 안 맞는다.** 상세 소식 · `declined` 방은 옛 앱에 안 보인다 |

**옛 앱의 받은 사람은 상세 소식을 못 봐서 누를 길이 없다 — 그 상대에게 청한 구매자의 1장이 72시간 잡혔다가 돌아온다.** 켜기의 대가로 표에 올린다.

## 앞선 결정과의 관계

- **ADR 0009** — 잇는다. 차단 · 옛 앱의 거절은 되돌리지 않는다. 답 전 거절은 사용자 행동이 아니다.
- **ADR 0012** — 새 흐름에서 위 「변경」대로 좁아진다. 옛 흐름은 그대로다.
- **ADR 0038** — 켜진 뒤 좁아진다. 예약 · 세는 법은 그대로다. 「요청 때 예약」은 상세 요청의 일이고, 재시도는 누른 사람이 쓴다.
- **ADR 0071** — **다시 열지 않는다.** 앱이 글자를 안 대고, 시도를 여는 트랜잭션이 얼리고, 문에서 재고 출구에서 안 잰다. 옛 재시도의 틈은 켠 동안 입력 판을 견주어 닫힌다.
- **ADR 0106** — 그대로. 쓰임은 요청의 줄을 잇거나 시도의 새 줄이다.
- **#966** — 상대 탈퇴로 글을 잃은 구매자의 일은 남아 있다.

## 고르지 않은 것

- **상세 전용 표** — 예약 · 풀림 · 만료 · cascade · 장부 출처를 새로 다 잇는다. 잊힌 복원 하나가 ADR 0038 이 없앤 일이다.
- **잔액을 장부 예약으로 세기** — #966 B4 · B7 을 밟는다.
- **스위치로 규칙 가르기** — 켜고 끌 때 살아 있는 줄의 뜻이 바뀐다.
- **말 보내기의 새 답 값** — 옛 앱은 모르는 값을 망 실패로 읽어 재전송한다. 그래서 던진다.
- **실패 때 글자 거두기 · 끝난 인연 지우기** — 앞의 판에 있었고 걷었다. 글자는 애초에 안 돌려주고, 말은 보존을 따른다.

## 잠그지 않은 것

- 답한 대화의 방은 정지가 풀려도 닫힌 채다 — 그 뒤 상태 문은 `room_closed` 이고 동의도 끝난다.
- **잠금 순서 교착** — 계정 · 요청 · 사람 자물쇠의 차례는 옛 함수들의 것을 잇는다. 어긋난 차례가 만나면 Postgres 가 한쪽을 되돌려 실패로 답한다. 트랜잭션째 되돌아가 돈은 어긋나지 않는다.
- 소식 묶음은 대화와 상세를 따로 세고, 거둔 요청의 소식도 센다 — 거두고 다시 열면 받은 사람은 그 창에서 소식 없이 방 안 상태로만 본다.
- **끄기는 전송을 멈추는 비상 수단이 아니다** — 기다리던 상세의 누름은 끈 뒤에도 전송까지 간다.
- **90일 파기는 크론이 없다**(G-132) — 함수는 있고 사람이 돈다. 켜기 전 조건이다.
- 무료 몫 · 측정 · D8 은 여기서 안 건드린다.
